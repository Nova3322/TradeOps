# 审核队列数量与重复提案验收

## P0 / P1 / P2

- P1，已修复：`PENDING_REVIEW` API 曾返回 92 条记录，其中 61 条已经超过 `expires_at`，导致 API、首页与审核页可能出现不一致。现在读取时统一投影有效状态；待审核查询只返回尚未到期记录，到期记录在全部提案和详情中显示为 `EXPIRED`。
- P1，已验证：历史数据库存在同标的重复提案，但当前有效 SYSTEM 提案按环境、账户、交易所、精确合约、方向和策略分组的重复数为 0。自动提案仍使用事务锁、活动作用域去重和来源候选幂等；本批未删除历史审计记录。
- P2，已修复：审核队列按最早到期排序；统计改为“待我审核 / 需两人审核 / 30 分钟内到期 / 最早到期”，避免把“全部高风险”当成无法解释的告警。
- P2，已修复：全部提案增加状态筛选；历史到期记录可明确筛选，不再伪装为仍待审核。
- P2，已验证：当前管理员默认配置 v4 明确将风险档位设为 `HIGH`、有效期 8 小时、自动提案阈值 4 周期，因此有效自动提案大多需要两名审核人，这是当前生效配置，不是前端误算。本批没有擅自改变风险策略。
- P2，待后续：本轮在 Codex 内置浏览器完成桌面实页验收；该浏览器当前不提供可控手机 viewport，手机端仍由现有响应式样式和静态页面测试覆盖，后续需要在可控手机视口补一张当前运行截图。

## 五维证据

- 代码：统一提案有效状态投影；审核页优先级、说明、统计和状态筛选完成。
