## 一、目标

本文建立一套能够回答以下问题的统一口径：

- 当前交易所、Vault、在途资金和全组合到底有多少资本。
- 一笔 Campaign 从初仓、全部 Add、动态减仓到退出，真实赚亏多少。
- 收益来自价格方向、加仓、退出、费用、资金费、滑点还是资金操作成本。
- Freqtrade、本地账本和交易所出现差异时，以谁为准、如何修复。
- 未实现盈亏如何进入 Current Portfolio MTM Equity、风险预算、回撤和报表。
- 资金从 Vault 到交易所或从交易所归集到 Vault 时，如何避免双计或被误记成利润。
- 历史结果如何保持可重放，且后续更正不会静默改写审计事实。

本文的首要原则是：

> 资金位置变化不是利润；保证金变化不是利润；下单请求不是成交；成交确认不等于 Campaign 已结算；交易所私有事实是订单、成交、仓位、费用和账户余额的最终事实源。

---

## 二、范围与非范围

本文覆盖：

- Binance 与 Hyperliquid 受管账户的订单、成交、仓位、费用、资金费和权益。
- Trading 内部的 Campaign、风险 R 和策略归因；Campaign 是唯一经济仓位生命周期。
- RiskControl / NoTilt Vault、场所运营资金和 CTO 在途资本。
- 实时、日终、Campaign 结束和恢复后的对账。
- 资本高水位、A-DD、C-DD 与外部资本流调整。

本文不覆盖：

- 税务申报、法定财务报表或第三方基金 NAV。
- FundPool、FundShare、管理费和公开募资。
- 未经治理批准的跨组织、多租户或客户资产会计。
- 具体会计软件或数据库实现。

第三方资金不属于本系统。若另行立项，必须重新建立托管、法律、税务、客户资产隔离和正式 NAV 合同，不能直接复用本文作为法定会计政策。

## 三、会计对象与身份

### 3.1 最小事实对象

| 对象 | 定义 | 主身份 |
| --- | --- | --- |
| Instrument | 某 venue / execution domain 上的具体永续合约 | `instrument_id` |
| Fill | 交易所确认的一次成交事实 | `venue + execution_domain + account + venue_trade_id` |
| Order | 交易所订单生命周期 | `venue_order_id`，关联 `order_intent_id` |
| Venue Position | 某账户、Instrument、margin mode 下的真实净仓 | 场所原生身份与本地规范身份 |
| Campaign | 同一策略、标准底层资产、方向和授权生命周期的唯一经济仓位 | `campaign_id` |
| AddUnit | Campaign 内一次预授权加仓单元 | `add_unit_id` |
| Protection Requirement / Coverage | Campaign 的版本化保护义务与由场所订单派生的覆盖事实 | `protection_requirement_id` |
| Account Equity Snapshot | 场所私有账户的逐时权益事实 | `account_snapshot_id` |
| Capital Transfer | Vault、链、中转钱包和场所之间的一次资金迁移 | `capital_transfer_id` |
| Ledger Entry | 不可变会计或风险分录 | `ledger_entry_id` |
| Reconciliation Run | 一次范围明确的对账运行 | `reconciliation_run_id` |

### 3.2 Campaign 边界

Campaign 在初仓出现第一笔非零真实成交时进入活动状态；只有同时满足以下条件才能结束：

- 对应真实净仓为零。
- 无可能恢复成交的普通、条件、保护或 Unknown 订单。
- 全部成交、费用、资金费和已实现盈亏已取得场所事实。
- 相关风险预留、Funding Envelope 和保证金占用已对账并释放。
- 所有差异已经解决或以明确调整分录关闭。

同一 Instrument 由多策略竞争、同账户方向反转或外部人工仓位介入时，不能把全部成交强行归入原 Campaign。方向反转必须先关闭原 Campaign，再建立新方向 Campaign；外部人工仓位按 `DEC-EXEC-003` 处理所有权与冻结。

同一底层资产在 Binance、Hyperliquid Core 或 HIP-3 DEX 上分别保留 Venue Position 与执行 PnL，但在底层资产、风险簇、板块和组合报告中聚合暴露。跨所反向仓位不能因为展示净额而丢失各自费用、清算和执行风险。

## 四、计量币种、数量与价格

### 4.1 三层币种

系统必须同时保存：

1. **原生计价币种**：交易所成交、费用、资金费和余额实际记账的资产。
2. **抵押/结算币种**：例如某执行域真实使用的 USDT、USDC 或其他抵押资产。
3. **组合报告币种**：用于 Current Portfolio MTM Equity、风险预算和跨场所报表的统一单位。

不能因资产名称含“USD”或“U”就固定按 1:1 换算。组合报告币种与运营日界由 `DEC-OPS-010` 冻结；FX/稳定币价格源、链上资产价格和脱锚处理由 `DEC-FUND-002` 与 `DEC-RISK-006` 冻结。

所有原生金额和换算金额必须同时保存，且记录价格源、价格时间、转换方向和政策版本。缺失可靠 FX 时，对应资产不能凭静态前端估值进入风险资本；报表应标记 `VALUATION_UNKNOWN` 或按已批准保守折扣处理。

### 4.2 数量符号

- 多头数量为正，空头数量为负。
- 买入成交为正数量变化，卖出成交为负数量变化。
- `reduce_only` 订单只能使绝对仓位变小或保持不变。
- 数量、价格、合约乘数和名义价值都以 Instrument Catalog 的版本化规则解释。

任何 UI 反向符号或交易所专用字段必须在 VenueAdapter 归一化，账本内部不得同时存在两套含义。

### 4.3 价格职责

| 用途 | 价格事实 |
| --- | --- |
| 成交 PnL | 交易所确认的实际成交价格和数量 |
| 未实现 PnL / 账户权益 | 对应场所认证的 Mark / 账户原生权益事实 |
| 下单前风险 | 真实可成交盘口及批准的最坏滑点，不用单纯中间价 |
| 保护风险 | 已确认保护价或冻结的压力退出价 |
| 日终/报告 | 冻结时点和来源的认证估值价格 |
| Vault 风险贡献 | 决策批准的链、资产、价格源与折扣 |

指数价、中间价、Mark、最后成交价和可成交价不得混为一个字段。所有快照必须保存 `price_type`、event time、received time、source 和 quality。

## 五、成交、持仓与成本基础

### 5.1 成交是仓位变化的唯一内部起点

订单创建、接受或 Freqtrade 报告“已提交”不改变真实持仓。只有交易所确认的 Fill 才改变 Venue Position 和 Campaign 数量。

每笔 Fill 至少保存：

- venue、execution domain、account、Instrument。
- venue order/trade ID、order intent、Campaign、AddUnit 或退出意图关联。
- side、position side、`reduce_only`、数量、价格、合约乘数。
- maker/taker、手续费、手续费币种、成交时间和接收时间。
- 原始场所载荷的不可变引用及归一化版本。

### 5.2 成本基础

内部成本基础必须通过按时间排序的真实 Fill 重建，不能使用“最近一笔订单价格 × 当前数量”。

净持仓增加时，成本基础按批准的持仓会计方法更新；净持仓减少时，减少部分形成已实现价格 PnL；减仓超过零点时必须把原方向关闭与新方向建立拆成两个 Campaign。正式的加权平均/FIFO 等归因方法属于财务详细设计，并按 `DEC-GOV-001` 的职责分离流程批准；无论选择何种方法都必须满足：

- 同一版本、同一成交序列得到确定结果。
- 能解释并对账场所已实现 PnL。
- 不通过改变方法重写历史绩效。
- 方法版本永久绑定 Ledger Entry 和 Campaign。

VenueAdapter 或场所展示的平均价可以作为对账事实，不能替代内部不可变成交序列。

## 六、PnL 分类

### 6.1 价格 PnL

**未实现价格 PnL** 是当前真实净仓按认证 Mark 相对剩余成本基础的逐时结果。

**已实现价格 PnL** 只在真实减仓或退出 Fill 被确认后形成，按减少数量、原成本基础、实际成交价和合约乘数计算。

多头与空头使用同一有符号数量语义，避免两套公式产生方向错误。

### 6.2 交易成本

交易成本至少分开：

- 成交手续费及返佣。
- 资金费支付与收入。
- 下单滑点。
- 止损穿透或退出冲击。
- 借贷、利息或场所特有成本；其他场所若独立立项则单独认证。

手续费、返佣和资金费使用交易所实际结算事实；尚未结算但可可靠预计的金额单独标记为 accrual，不能冒充最终值。

滑点、价差、市场冲击和止损穿透是把实际成交结果相对冻结基准价格进行拆解的归因维度，不是实际成交价格 PnL 之外再扣一次的现金费用。只有场所另行收取的真实费用才作为额外成本，避免双计。

### 6.3 Campaign Net Trading PnL

Campaign 的净交易结果由以下部分组成：

> 已实现价格 PnL + Campaign 期间归属的资金费收入 − 资金费支出 − 交易手续费 + 返佣 − 其他经认证交易成本

活动 Campaign 同时展示未实现净结果；关闭 Campaign 只使用已经对账的已实现结果。转账本金、保证金增加/移除、Vault 释放或交易所充值不进入 Campaign Trading PnL。

### 6.4 Treasury 与基础设施成本

以下不属于策略价格 PnL，应单列 Treasury / Capital Movement Cost：

- 交易所提款费。
- 链上 Gas。
- Bridge、Swap、中转钱包或充值费用。
- Vault 协议费用和释放净额差异。

组合净资产会受到这些成本影响，但策略是否具有正期望时应分别展示“交易净结果”和“包括资金运营成本后的总结果”。归属周期和成本摊分方式由资金与治理决策冻结，不能为了美化策略回测而隐藏。

### 6.5 保证金动作

保证金增加、移除或 `POST_REDUCTION_MARGIN_NORMALIZATION` 只改变抵押品位置与清算缓冲，本身不是收益或损失。

- 减仓产生的真实 Fill 可以形成已实现 PnL 和费用。
- 随减仓释放的保证金不是利润。
- 把已释放保证金回加到剩余仓不是新投入收益。
- 保证金腿失败导致的额外减仓按真实 Fill 记账，不能用“normalization 失败”冲销。

## 七、浮盈、Protected Profit 与风险结果

未实现盈亏必须进入最新账户价值和 Current Portfolio MTM Equity，但它仍是逐时变化值，不等于已结算可提款利润。

Protected Profit 是风险分析指标，不是独立现金账户：

- 只有保护已由交易所确认并按压力折扣后，才可以影响 Open Heat。
- 从当前 Mark 回到有效保护/压力退出价的回吐必须进入最坏损失。
- 已通过保护价降低 Open Heat 的利润不能再次作为新额度。
- 它不能跨 Campaign 转移，也不能触发 Vault 到交易所再融资。

Protected Profit、Open Heat 和 Giveback 的正式公式由 `DEC-RISK-005` 冻结。财务账本继续记录完整未实现 PnL，不因风险折扣改变真实净值展示。

## 八、1R 与策略归因

每个提案冻结：

> `1R_0 = Total Capital Snapshot_0 × 0.5%`

Campaign 完成并对账后的核心结果为：

> `Campaign Net R = Campaign Net Trading PnL ÷ 1R_0`

1R_0 在整个 Campaign 不因加仓、浮盈、外部入金或风险政策变化而重算。低/中/高风险的 1R/2R/3R 是计划最大损失上限，不是对最终收益作截断。

报告必须至少拆分：

- 初仓贡献。
- Add-1、Add-2、Add-3 增量贡献。
- 动态去杠杆、趋势退出、硬止损和其他退出贡献。
- 毛价格 PnL。
- 费用、返佣、资金费和滑点。
- 保护价偏差与止损穿透。
- 资金运营成本；与交易净结果分列。

自动加仓的价值必须与同一入场、同一退出逻辑、但关闭自动加仓的配对基线比较，不能只展示含 Add 策略的绝对收益。

## 九、E_campaign 与目标杠杆

`E_campaign` 是该经济仓位按真实初仓、全部成交、费用、资金费、已实现和未实现盈亏重建的当前仓位权益。它不能使用最近订单价格或交易所 UI 的即时 ROE 反推。

它用于：

> `L_effective = abs(Q_current) × P_mark ÷ E_campaign`

> `Q_target = E_campaign × L_target ÷ P_executable`

PnL 账本必须为每次目标杠杆决策提供可重放的：

- 当前真实数量和成本基础。
- 累计已实现 PnL。
- 当前未实现 PnL。
- 累计费用与资金费。
- 初仓冻结的保证金参考额。
- 使用的 Mark 与可成交价格时间。

30% / 50% / 100% 的候选解锁比例已经固定。“仓位冻结收益率”分母是初仓成交后冻结的初始保证金参考额；加仓、转账或场所 UI 变化不得改变分母。`DEC-RISK-004` 只通过研究冻结持续时间、K 线确认时点、保护上移、候选失效等附加规则，不重新决定三个解锁比例。

## 十、账户权益与回撤

### 10.1 交易账户权益 A

交易账户逐时权益基于全部受管交易所账户的 Exchange Margin Equity，只额外扣除尚未被该权益或源端账本反映的已知未结算负债。源端转出预留和在途金额在资本互斥账本中只扣一次；若已经反映在 Exchange Margin Equity 或源端可用额中，不得在 A 口径尾部再扣。

交易账户回撤 `A-DD` 使用经外部资本流等额调整的权益高水位。入金不产生收益，出金不产生亏损；资金迁移也不能伪装成回撤，但费用和真实到账差额仍是真实损失。

### 10.2 扩展资本权益 C

在 `EXCHANGE_PLUS_VAULT` 模式下，扩展资本逐时权益由 Exchange Margin Equity 加“纳入监控范围的 Vault 保守完整 Mark-to-Market 价值”形成，用于 Extended Capital MTM 视图和 `C-DD`。它必须扣除 pending、源端预留、在途、费用和已知负担，并使用保守可验证价格；但不使用 Eligible Vault Equity 的“风险贡献上限”截断超出上限的真实资本变动。

Vault 纳入、移出和资本转账必须作为资本范围变化调整高水位，不能被误记为交易收益或回撤恢复；价格或资产实际下跌则必须保留为资本损失，不能用贡献上限隐藏。无法可靠计算监控范围 Vault 完整 MTM 时，C 视图进入 `UNKNOWN`，系统使用更严格的风险状态。

### 10.3 外部资本流调整

每笔入金、出金、Vault 纳入/移出和系统外注资必须：

- 关联唯一资本流或调整事件。
- 保存生效前后权益、原生币种、换算价和时间。
- 等额调整对应高水位的资本基数。
- 不重置日/周损失、连续亏损或 KILL_SWITCH 历史。

正式日周回撤门由 `DEC-RISK-008` 冻结。

## 十一、Vault 与 CTO 互斥资本账本

同一金额在任一时刻只能属于：

1. 源端已确认资本。
2. 源端已预留转出。
3. 在途资本。
4. 目的端确认中。
5. 目的端已确认资本。

不能同时记入 Vault 和交易所，也不能在目标尚未确认时恢复为源端可用。

### 11.1 Vault → 交易所

- 进入 `SOURCE_RESERVED_OUT` 时从 Vault 可用资本和 Managed Settled Capital 扣除 gross 预留。
- 若该 Vault 原本计入风险资本，只在唯一 Eligible Vault Equity 账本扣减一次；Current Portfolio MTM Equity 与 Extended Risk Equity 从同源重算。
- 释放、链上中转和充值在途期间风险贡献为零。
- 只有交易所私有接口确认目的账户可用余额后，才进入交易所已确认资本。
- `grossAmount`、`netAmount`、协议费、Gas、Bridge/中转费和实际到账差异分别记账。

### 11.2 交易所 → Vault

- 提款授权时先从交易所可用资本扣除源端预留。
- 提款提交后保存 withdrawal ID、tx hash、Token、链、金额和费用。
- 达到冻结确认深度并观察到 Vault 实际余额增量后才确认目的端。
- 只有通过资产、价格、控制权和流动性资格后才能进入 Eligible Vault Equity。

### 11.3 状态未知与链重组

失败或未知不能直接把金额放回可用余额。必须证明源端未扣、已退回或目的端已到账。转账超时、确认深度、链重组、重复 tx、替换交易和人工修复规则由 `DEC-FUND-008` 冻结。

利润归集只是利润资本的位置变化：交易 PnL 在交易所成交和结算时已经形成，转入 Vault 时不能再次记为收益。运营补充是资本投入，也不能记为策略收益。

## 十二、事实来源与对账层级

### 12.1 事实优先级

| 事实 | 最终来源 | 本地职责 |
| --- | --- | --- |
| 订单、成交、仓位、费用、资金费、账户余额 | 交易所私有接口 | 保存预期状态、不可变镜像和差异 |
| 执行请求与 worker 进度 | Trading OMS / Freqtrade worker | 关联订单意图和执行过程 |
| 批准、授权、Risk Reservation、Campaign、AddUnit | Trading 事实库与不可变账本 | 唯一内部事实 |
| Vault 余额、权限、请求、链上转账 | 链上状态与交易回执 | 保存观察与资格判断 |
| 资金在途和资本归属 | CTO 不可变资本账本 | 维持源/在途/目的互斥 |
| 市场估值价格 | 认证市场数据源 | 保存时间、类型、质量和版本 |

Freqtrade 数据库是执行镜像，不能覆盖交易所事实；Redis 或缓存不能覆盖任何资金、风险或成交账本。

### 12.2 三方订单对账

订单和仓位必须比较：

1. Trading 的订单意图、风险预留和预期状态。
2. Freqtrade worker 的请求与执行镜像。
3. 交易所私有订单、成交和真实仓位。

发现差异时，以交易所私有事实重建当前风险，但不能删除内部意图或审批历史。差异以独立 reconciliation adjustment/event 解释。

## 十三、对账触发与完成条件

### 13.1 必须触发对账的时点

- 订单发送前和收到任何执行结果后。
- 部分成交、撤单、拒单、超时或结果未知。
- 保护订单创建、修改、触发或缺失。
- Freqtrade、VenueAdapter、Trading 或数据库重启。
- 私有 WebSocket 断线重连、REST 修复或交易所规则变化。
- 外部人工动作、未知入出金或账户抽象变化。
- 每次 Add、动态去杠杆、Campaign 完全退出。
- CTO 每个源端、在途、目的端状态迁移。
- 冻结的周期性账户快照、日终和风险恢复前。

### 13.2 对账完成

只有以下事实共同成立，对账范围才可标记完成：

- 已取得认证时间窗口内的订单、成交、仓位、余额和费用事实。
- 分页、游标和查询窗口无缺口，迟到事件已纳入。
- 本地数量、费用、资金费、已实现和未实现 PnL 可解释场所事实。
- 每个差异都有解决、调整、在途或 Unknown 分类。
- Risk/Capital Ledger 守恒，所有调整产生不可变分录。
- 无重复 Venue trade/order ID 和重复资本到账。
- 对账水位、事实截止时间和证据引用已保存。

对账频率、时间边界、容差和历史查询要求由 `DEC-OPS-008` 冻结，升级时限按 `DEC-OPS-002` 与 `DEC-OPS-011` 执行。任何金额差异不得因“小于 UI 显示精度”被静默忽略。

## 十四、差异分类与安全动作

| 差异 | 示例 | 最低安全动作 |
| --- | --- | --- |
| `MISSING_LOCAL_FILL` | 场所有成交，本地未记 | 冻结相关 Campaign，补入不可变成交，重算仓位/PnL/Heat |
| `PHANTOM_LOCAL_FILL` | 本地认为成交，场所无事实 | 转 Unknown，禁止释放风险，扩大查询窗口 |
| `POSITION_MISMATCH` | 数量、方向或模式不一致 | 账户停止增险，按场所事实重建并确认保护 |
| `ORDER_MISMATCH` | 未知挂单、状态冲突 | 冻结 Instrument，查询/撤销但不盲重试 |
| `FEE_OR_FUNDING_MISMATCH` | 费用币种或金额不同 | 保留财务差异，使用场所最终结算并创建调整分录 |
| `EQUITY_MISMATCH` | 自算权益无法解释场所权益 | 停止新增风险，检查负债、抵押品、费用与价格 |
| `TRANSFER_MISMATCH` | 源端已扣而目的端未确认 | 保持在途/未知，不计入任一可用资本 |
| `DUPLICATE_FACT` | 重复成交、重复到账 | 以场所唯一 ID 去重并告警，不产生第二次账本影响 |
| `CLASSIFICATION_DRIFT` | Instrument sector/risk cluster 改变 | 旧快照保留，新风险按新版本重算；必要时收紧 |

自动修复只能补充可验证事实或收紧风险，不能删除审计记录、扩大仓位、放宽止损或把未知金额恢复为可用。

## 十五、迟到、撤销、冲正与历史修正

- 任何已发布账本事实不可原地改写。
- 迟到 Fill、费用、资金费或链上结果通过新分录追加，并引用原对象。
- 交易所更正、交易回滚、链重组或人工修复使用 reversal/correction 关系，保留原值、修正值、原因、证据和批准者。
- 历史策略、风险和授权版本保持原样；财务修正不能用当前配置重算历史。
- 日报或 Campaign 报告若已发布，修正后生成新 revision，旧 revision 继续可查。
- 真实 PnL 可以因迟到费用改变，但 1R_0、初始授权和历史决策输入不能被重新定义。

## 十六、快照状态与报表成熟度

每个财务结果必须标记成熟度：

| 状态 | 含义 |
| --- | --- |
| `PROVISIONAL` | 基于实时事实，仍可能有迟到成交/费用/资金费 |
| `VENUE_CONFIRMED` | 场所关键事实已确认，但周期尚未关闭 |
| `RECONCILED` | 指定范围和水位已完成三方对账 |
| `PERIOD_FINAL` | 冻结周期关闭、全部规定证据齐全 |
| `CORRECTED` | 终值后发现新事实，以新 revision 修正 |
| `UNKNOWN` | 事实或估值无法可靠计算 |

界面、Telegram 和报告必须展示状态与事实截止时间。`PROVISIONAL` 不能被称为“已结算利润”，`UNKNOWN` 不能显示为零。

## 十七、标准报表

### 17.1 实时账户视图

- 原生余额、Exchange Margin Equity、Exchange Risk Equity。
- 已实现/未实现 PnL、费用、资金费、可用保证金和负债。

- 毛价格 PnL、费用、资金费、滑点、净交易 PnL 和净 R。
- 最大有利/不利变动、保护变化、计划与实际最大损失。
- 策略、风险、审批、Catalog、Adapter 和执行版本。

### 17.3 组合与板块

## 十八、不可变审计字段

每个会计、PnL 或对账事件至少保存：

- event/ledger ID、aggregate ID、sequence、correlation/causation ID。
- venue/execution domain/account/instrument/campaign/order/fill/transfer 身份。
- 原生金额、原生币种、报告金额、FX/价格源、价格类型和时间。
- event time、observed time、booked time、reconciled time。
- 原事实引用、归一化 Schema 和 VenueAdapter 版本。
- 策略、风险、Catalog、权限和资金政策版本。
- 状态前后值、调整原因、证据、actor 和审批引用。
- 对账 run、水位、成熟度和 report revision。

审计记录与业务事实使用不可变追加语义；查询投影可以重建，不能成为覆盖账本的第二真源。

## 十九、数据存储与一致性候选

推荐候选为关系型事实库、不可变 Ledger、transactional outbox/inbox 和可重建查询投影，由 `DEC-ARCH-002` 最终确认。

无论技术选择如何，都必须满足：

- Fill、费用、资金费、账本分录和资本迁移具有唯一约束。
- 业务事实与待发布事件原子提交。
- 至少一次事件投递不会重复计算 PnL、重复移动资本或重复关闭 Campaign。
- 风险预留、订单事实与财务分录通过稳定身份关联，而不是依赖日志文本。
- Redis、搜索索引、缓存和报表库均可丢弃重建。
- 主库损坏时可以从持久备份恢复不可从交易所重建的审批、授权、意图、风险和资本历史。

## 二十一、验收门

影子盘前必须证明：

- 任意成交序列可确定性重建数量、成本基础、已实现和未实现 PnL。
- 部分成交、重复事件、乱序、迟到费用和重启不会双计。
- 订单发送但无响应、场所有成交而本地缺失、本地幻影成交均能进入安全状态并最终对账。
- 保证金增加/移除不产生虚假利润。
- Vault、在途和交易所资金在任一时刻互斥，转账本金不进入 PnL。
- 正浮盈只影响逐时净值一次，Protected Profit 不重复释放风险。
- 外部入出金调整高水位，不制造收益或清除回撤。
- Campaign 净 R 始终使用冻结 1R_0，历史策略版本不会被当前参数覆盖。

小额实盘前还必须完成：

- Binance 与 Hyperliquid 各执行域真实费用、资金费、平均价和权益对账。
- 原生币种与报告币种的价格、脱锚和 UNKNOWN 演练。
- CTO 双向小额转账、链重组/超时、费用差异和目的端重复通知演练。
- 数据库与缓存丢失后的恢复、重新对账和报告 revision 验证。
- 从上位需求到分录、报表、对账告警和自动化测试的追踪矩阵。

未满足任一对应门时，报表必须明确标记为研究、影子、模拟或未认证，不能显示为生产已结算结果。
