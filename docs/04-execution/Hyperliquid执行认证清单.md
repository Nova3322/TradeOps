## 1. 使用说明

本清单用于逐个认证 Hyperliquid 执行域。不得把“Hyperliquid 已支持”当成单一结论：Core 与每个启用的 HIP-3 DEX，以及不同账户抽象、抵押池、margin mode 和 worker，都是不同认证单位。

状态值；它们是检查项状态，不是 `capability_status`：

| 状态 | 含义 |
| --- | --- |
| `已定` | 上位业务规则已经固定；技术能力仍需证据 |
| `待验证` | 需要目标账户、执行域和版本的真实证据 |
| `不支持` | 场所、执行栈或本产品明确不提供；必须安全降级 |
| `不适用` | 对该证书不适用，需写明原因 |

对应规范值依次为 `FIXED_DESIGN`、`UNVERIFIED`、`NOT_SUPPORTED`、`NOT_APPLICABLE`。没有实现证据时，汇总能力保持 `NOT_IMPLEMENTED`，不能因清单写“待验证”而升级。清单不能用官方说明、接口名称或一次成功请求替代完整的状态、风险、恢复和小额实盘证据；汇总认证状态在 [主策略参数与能力认证登记表](../07-registers/主策略参数与能力认证登记表.md) 管理。

| 单个 HIP-3 小额、无 Add | 从头认证该域 | 在证书内 |
| Add-1 | 独立认证目标杠杆与保护 | 在证书内 |
| Add-2 / Add-3 | 逐层独立认证 | 在证书内 |
| normalization | 按 capability 单独认证 | 在证书内 |

这些环境只验证对应已实现流程。Core 的通过不授予任何 HIP-3 DEX；一个 HIP-3 DEX 的通过也不授予另一个，isolated 的通过不授予 cross。其他作用域按后续端到端里程碑分别开发和验证。
