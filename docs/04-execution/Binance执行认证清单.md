## 1. 使用说明

本清单是 Binance 执行证书的验收模板。每个条目必须留下可复查证据，不能只填写“支持”。

状态值只有四种；它们是检查项状态，不是 `capability_status`：

| 状态 | 含义 |
| --- | --- |
| `已定` | 上位业务规则已固定；仍不表示技术能力通过 |
| `待验证` | 需要目标账户、版本、影子、模拟或小额实盘证据 |
| `不支持` | 交易所、执行栈或本产品明确不提供；必须有安全降级 |
| `不适用` | 对该认证单位不适用，必须写明原因 |

对应规范值依次为 `FIXED_DESIGN`、`UNVERIFIED`、`NOT_SUPPORTED`、`NOT_APPLICABLE`。执行能力不得标记为“已通过”，直到证据包、审批与有效期同时登记；没有实现证据时，汇总能力保持 `NOT_IMPLEMENTED`，不能因清单写“待验证”而升级。认证状态统一在 [主策略参数与能力认证登记表](../07-registers/主策略参数与能力认证登记表.md) 管理。

## 15. 证据包模板

每次认证提交：

- 证书身份、版本、范围、有效期与失效条件。
- 配置摘要与哈希，不包含秘密。
- 场所规则与账户事实快照。
- 测试运行 ID、时间、环境、输入和预期。
- 请求 / 回执 / 场所订单 / 成交 / 仓位 / 保护关联。
- 风险快照、Heat 迁移与 Add 消费。
- 失败注入、重启、双主与人工接管结果。
- 预测与实际手续费、滑点、资金费。
- 未解决差异、限制和明确不支持能力。
- 执行、风险与安全审批结论。

证据路径不得填写临时聊天或截图作为唯一依据；必须指向可长期复查的持久制品。
