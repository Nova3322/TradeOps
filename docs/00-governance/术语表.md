## 1. 使用规则

- 本表规定跨产品、风险、策略、执行和资金域的规范名称。代码、API、数据库、页面和审计优先使用“规范英文名 / 字段名”，中文用于解释。
- 专项文档可以细化公式、枚举和 Schema，但不能用相同名称表达另一件事。需要改变语义时先登记决策或 ADR，并创建新名称。
- “示例”“建议起点”“研究默认值”不是生产默认值；没有冻结值时必须显示 `TBD / NOT_CERTIFIED`，不能由实现团队猜测。
- `Vault` 未加限定时容易歧义。界面和审计必须区分 `RiskControl / NoTilt Vault`、`Hyperliquid Vault` 与 `Hyperliquid Subaccount`。

## 2. 系统与职责

| 规范术语 | 定义 | 不能被解释为 |
| --- | --- | --- |
| **Perptape** | 市场与机会发现层，提供公开行情、指标、突破候选和数据健康信息 | 私有账户事实源、风险引擎、审批或下单服务 |
| **Trading** | 决策、风险、授权、仓位生命周期、OMS、执行协调、对账和审计核心 | 单一策略脚本或 Freqtrade 的别名 |
| **RiskControl / NoTilt Vault** | 长期资金储备与受控释放闸门 | 交易所保证金账户、单仓救援工具或 Hyperliquid Vault |
| **Web / PWA 主控制台** | 完整查看、提案、审核、风险、仓位、资金和异常处置入口；只向 Trading 提交意图 | 事实源、直接 Freqtrade/交易所入口或离线授权端 |
| **Trading Telegram Bot** | 通知与白名单轻操作入口，包括批准/拒绝冻结初仓提案、关闭加仓、暂停和紧急减仓请求 | 完整人工提案编辑器、风险放宽入口或 Freqtrade 内置 Bot |
| **Freqtrade worker** | 与一个场所、账户、margin mode 和配置绑定的底层订单执行进程 | 策略、风险、审批、资金划转或事实最终来源 |
| **OMS** | Trading 内把唯一目标仓位转为一次性 `OrderIntent`、管理订单生命周期与对账的执行协调域 | 交易所适配器本身、策略信号或资金划转服务 |
| **VenueAdapter** | Trading 内将规范订单、账户和市场语义映射到特定场所，并把批准交易订单交给绑定的 Freqtrade worker | 新策略、Risk Engine、提款接口或可跨所自动接管的抽象 |
| **Margin Controller** | 逐场所认证、只处理场内保证金增加/移除/normalization 的执行组件 | 订单发送者、Vault 提款服务或风险放宽者 |
| **Capital Transfer Orchestrator / CTO** | 消费独立资金授权，管理 Vault、钱包和交易所之间双向划转、在途与对账的服务 | OMS、Freqtrade、Margin Controller 或交易授权的附属动作 |
| **Market Catalog / Instrument Catalog** | Trading 动态发现、标准化、分类并判断标的交易资格的目录 | 当前实盘白名单本身；“被发现”不等于“获准交易” |
| **Risk Engine** | 对提案、初仓、Add、状态恢复和相关操作作确定性风险校验并拥有最终否决权 | 给出交易方向的策略模型或可被人工覆盖的提示 |
| **Auxiliary Suggestion Source / 辅助建议源** | 只提供候选、解释或辅助判断的非权威输入源 | 不得持有交易/资金密钥、签名、下单、划转或覆盖风控的权限 |

## 3. 产品、提案与授权

| 规范术语 | 定义 | 关键约束 |
| --- | --- | --- |
| **SYSTEM Proposal** | 由 Perptape/策略候选、排名、风险定仓形成，并且只能由已认证策略 `service_principal` 创建的系统提案 | 人类不能伪造 SYSTEM 来源；信号不是订单；初仓仍需人工审核 |
| **MANUAL Proposal** | 用户在 Web/PWA 把图表判断结构化后，经风险定仓形成的人工提案 | 保存草稿不是批准；人工请求数量超限时拒绝而非静默缩量 |
| **Draft / 草稿** | 尚可编辑、没有执行效力的输入 | 不能签发订单或占用 Heat |
| **Frozen Trading Proposal / 冻结交易提案** | 字段、版本、风险、有效期和执行边界已经冻结，等待或完成审核的对象 | 修改任何影响风险的字段必须生成新版本 |
| **Approval / 审核决定** | 具备作用域的 Reviewer 对冻结提案作批准或拒绝 | 不能覆盖 Risk Engine，也不能编辑被审核提案 |
| **Limited Authorization / 有限授权** | 对冻结提案签发的、有作用域、有上限、会过期的许可 | 不是“可以买某币”的无限许可，也不等于订单 |
| **Initial Order Authorization** | 短期、一次性的初仓授权 | 超过时间/价格边界或事实变化即失效 |
| **Add Authorization Package** | 开仓时预授权的 Add-1/2/3 单元集合，初仓成交、对账和保护确认后才激活 | 不逐次人工审核；不保证未来一定可以加仓 |
| **Authorized Capacity** | 人工批准的最高风险、次数、数量和价格等边界 | 不长期占用 Heat，不自动成为可执行容量 |
| **OrderIntent / 订单意图** | Trading OMS 在某一时点基于有效授权、风险预留和最新事实创建的唯一、不可复用订单动作 | 不是长期授权；结果未知时查询原 `OrderIntent`，不能另建意图盲重试 |
| **Proposal Validity / 提案有效期** | `valid_from`、`valid_until/TIF` 与价格偏离共同定义的执行窗口 | 超时或越界不能追价、换所或静默刷新 |
| **Expansion / 扩权** | 提高档位、最大损失、资金信封、次数、期限、价格容忍、Vault 贡献或权限范围 | 必须重新批准并按影响重验 |
| **Tightening / 收紧** | 关闭加仓、降低档位/次数、缩小范围、收紧止损或进入更严风险状态 | 可以按已批准政策立即生效，但在途订单仍须撤销与对账 |

## 4. 身份与权限

| 术语 | 定义 |
| --- | --- |
| **User Label / 用户标签** | 可叠加职责标签；一个用户可有多个标签，但标签不自动产生风控豁免或自审权 |
| **OBSERVER** | 查看授权范围内的候选、提案、仓位、风险、资金与审计；不能创建、审核、交易或划转 |
| **PROPOSER** | 创建、编辑和提交 MANUAL 草稿；不能仅凭此标签批准或执行 |
| **REVIEWER** | 在账户、场所、板块和风险档位作用域内批准/拒绝冻结初仓提案；不能修改提案或覆盖风控 |
| **OPERATOR** | 关闭自动加仓、暂停、发起已授权紧急减仓并处理运行异常；不能扩大风险或划转资金 |
| **RISK_ADMIN** | 管理版本化风险政策、冻结、降级和恢复；不能直接下单或单人完成同一风险放宽的提出与批准 |
| **TREASURY_ADMIN** | 在资金政策内提议、审核或执行资金划转；不能交易、改变交易风险或救仓 |
| **SYSTEM_ADMIN** | 管理身份、标签、作用域、MFA 和系统配置；默认不继承交易、审核、风险或资金权限 |
| **RBAC** | 依据职责标签允许动作集合 |
| **ABAC** | 依据账户、场所、标的、板块、档位、金额、时间、渠道、设备与 MFA 等属性进一步缩小权限 |
| **Deny Overrides / 拒绝优先** | 任一显式拒绝、系统风险状态或 Risk Engine 拒绝都会阻断动作，不能由多标签并集覆盖 |
| **Self-review Policy** | 提案者能否审核自己提案的版本化政策；当前已确认禁止，不能由 `PROPOSER + REVIEWER` 自动推导 |
| **Step-up MFA** | 在审核、资金、恢复、权限或紧急动作前要求动作级重新认证，而不是只依赖已有登录会话 |
| **Separation of Duties / 职责分离** | 创建、批准、执行和审计等高风险职责由不同身份承担的控制 |

## 5. 仓位与经济对象

| 术语 | 定义 |
| --- | --- |
| **Venue Position Projection / 场所仓位投影** | 由场所订单、成交和私有仓位事实重建的某账户、Instrument、margin mode 当前净仓视图；它不是独立业务生命周期或第二个仓位真源，可从场所事实和账本重建 |
| **Asset Exposure / 资产暴露** | 跨策略、跨交易所的同一底层资产及相关方向风险 |
| **Trading Campaign / 仓位战役** | 系统唯一的经济仓位生命周期；从初仓到完全退出，承载冻结 1R、资金信封、授权、Add、场所仓位投影关联和归因 |
| **Strategy Owner / 策略所有者** | 唯一负责解释和管理某 Campaign 的策略身份；同一场所净仓不能被多个策略争夺 |
| **Normalized Underlying** | 不同场所合约映射到的标准化底层资产身份；映射后仍保留 venue/dex/instrument 的独立执行事实 |
| **Sector / 板块** | 加密货币、美股及股指、贵金属、商品及商品期货参考资产之一；未分类标的风险上限为零 |
| **Risk Cluster / 风险簇** | 因相同底层、相关性或共同宏观因子而需要合并约束的一组暴露 |
| **TrendEpisode / 趋势样本波次** | 研究统计中合并同一宏观/突破波次相关交易的样本标签；不是业务 Campaign、领域实体或新的风险分母 |

## 6. 资本、资金与风险权益

| 规范术语 | 定义 | 用途/限制 |
| --- | --- | --- |
| **Exchange Margin Equity** | 交易所按最新 Mark-to-Market 得出的保证金权益，包含已实现和正负未实现盈亏 | 清算、可用保证金、可执行量和 A-DD；以交易所私有事实为准 |
| **Exchange Risk Equity** | 场所/账户新增风险门的保守权益：未实现亏损扣减，未实现浮盈不用于扩大该层容量，并扣除费用、负债和转出预留 | 保守场所上限；不代替实时组合 MTM |
| **Eligible Vault Equity** | 经认证 Vault 的确认余额扣除 pending、预留、在途、费用后，再施加资产、价格、流动性、控制权和时效折扣的唯一净贡献账本 | 默认值为零；不能作为交易所保证金或提款授权 |
| **Extended Risk Equity** | `Σ Exchange Risk Equity + Eligible Vault Equity` | 初始授权、账户和跨场所的第二道保守上限 |
| **Current Portfolio MTM Equity** | `Σ 已确认 Exchange Margin Equity + Eligible Vault Equity - 尚未扣除的其他组合负债`，完整包含交易所正负未实现盈亏 | 每次初仓/Add 的实时组合预算分母；正浮盈不能扩大原冻结授权，浮亏立即收紧 |
| **Total Capital Snapshot_0** | 待审核提案版本冻结时的 Current Portfolio MTM Equity 快照，又称 Frozen Authorization Equity | 冻结本战役 `FundingEnvelope_0`、`1R_0` 和授权上限；之后不得静默重写 |
| **Extended Capital MTM Equity** | Exchange Margin Equity 加纳入监控范围的 Vault 保守 MTM 价值 | C-DD 时间序列；不是最保守风险上限 |
| **Managed Settled Capital** | 已确认交易所资本加资金政策纳入的已确认 Vault 资本 | 计算场所运营资金目标；不含在途、未知或预留转出 |
| **Trade Funding Envelope / FundingEnvelope_0** | `Total Capital Snapshot_0 × trade_funding_pct`；完整战役从初仓到所有 Add 共用的已结算运营资金占用上限 | 不是 1R、最大亏损、保证金实际占用或每次 Add 的新额度 |
| **trade_funding_pct / N%** | 每笔交易资金信封比例 | 1.5% 仅为示例，正式值由预登记研究证据冻结；大写 `N` 与场所运营目标小写 `n` 区分 |
| **venue_operating_target_pct / n%** | 每个场所/抵押池希望保留的运营资金目标比例 | 与单笔 `N%` 不同；结合 `T_low/T_v/T_high` 形成滞回资金政策 |
| **1R_0 / Frozen 1R** | `Total Capital Snapshot_0 × 0.5%`，冻结为货币金额贯穿战役 | 低/中/高整份经济仓位最大计划损失分别为 1R/2R/3R；不是每个 Add 各一份 |
| **Risk Tier / 风险档位** | 低、中、高的授权包；最大有效杠杆分别为 3x/5x/10x，默认 Add 上限分别为 1/2/3 | 杠杆是上限，不要求用满；自动加仓默认关闭 |

## 7. 风险账本与最坏损失

| 术语 | 定义 |
| --- | --- |
| **Open Heat** | 已有真实仓位到有效保护/压力退出价的成本后计划风险，最低为零 |
| **Reserved Heat** | 即将发送或仍在途的增险意图按最坏允许成交暂时占用的风险 |
| **Unknown Heat** | 结果未知订单按最坏可能成交情景保留的风险；未对账前不得释放 |
| **Stress Heat** | 按冻结压力情景计算的压力风险结果；不是第四个可消费余额，不能机械地与计划 Heat 重复相加 |
| **Protected Profit** | 已被有效保护并经保守折扣的同仓浮盈分析指标；其风险效果只能通过降低 Open Heat 使用一次 |
| **Protected-Profit Giveback** | 从当前 Mark 回落到已确认保护/压力退出价可能吐回的利润，计算最坏损失时不能漏掉 |
| **Trade Worst-Case Loss_after** | 本经济仓位在动作后的 Open/Reserved/Unknown Heat、利润回吐及费用/滑点/资金费/止损穿透附加项的互斥合计 |
| **Scope Worst-Case Loss_after(scope)** | 底层资产、风险簇、板块、场所或全组合范围内全部经济仓位和订单的互斥最坏损失及 scope 附加项 |
| **Dynamic Mode Cap** | `Current Portfolio MTM Equity(t) × 0.5% × 档位倍数`；与冻结上限、Authorized Capacity 取更严格者 |
| **Risk Reservation / 风险预留** | 执行前把可能成交的风险从可用预算原子地转为 Reserved Heat 的动作 |
| **A-DD** | 交易账户 Mark-to-Market 权益相对外部资金流调整后高点的回撤 |
| **C-DD** | 启用 Vault 资本范围后的 Extended Capital MTM Equity 回撤；不能放宽 A-DD |
| **S-DD** | 策略认证单位的完整 MTM 证据回撤 |
| **P-DD** | 回放风险状态和 Heat 动作正确性的组合政策回撤；不证明策略盈利 |

## 8. 加仓、减仓与退出

| 术语 | 定义 | 固定语义 |
| --- | --- | --- |
| **Add / Add Unit** | Add-1、Add-2、Add-3 中一个独立、一次性的加仓授权单元 | 任意大于零真实成交永久消费一次；终态确认零成交不消费；动态减仓不返还 |
| **Frozen Return / 仓位冻结收益率** | `扣除预计平仓成本后的整仓未实现净收益 ÷ 初仓成交后冻结的初始保证金参考额` | 分母不随加仓、转账或 UI 改变；30/50/100% 只解锁候选 |
| **E_campaign** | 按初仓、全部成交、费用、资金费、已实现与未实现盈亏重建的当前经济仓位权益 | 不能用最近订单价格或主观保证金分摊虚构 |
| **L_effective** | `abs(已对账净仓位名义价值) ÷ E_campaign` | 是目标杠杆控制量，不代表计划最大损失 |
| **L_target / L_min / L_max** | 冻结目标杠杆及上下无动作边界，必须满足 `L_min < L_target < L_max ≤ 档位上限` | 低于 L_min 仅允许继续评估 Add；高于 L_max 触发 reduce-only 去杠杆 |
| **Q_target** | `E_campaign × L_target ÷ P_executable` 形成的目标净数量 | 是未经风险与执行约束裁剪的数学目标，不等于最终订单量 |
| **Delta Q to Target** | 当前净数量到 `Q_target` 的沿原方向正差额 | 每个 Add 不配置固定手数、初仓比例或风险份额 |
| **Delta Q Approved** | 目标差额与冻结授权、动态预算、资金信封、保证金、规则和流动性允许值的最小安全量 | 约束只可缩量或归零，不能放大到目标以上 |
| **target_reached** | 最终对账杠杆是否进入执行附件冻结的目标容差 | 不等于风险永久通过；false 必须给出原因 |
| **Callback / 回调过滤** | 当前价相对冻结布林参考线的偏差是否进入 `[callback_lower_pct, callback_upper_pct]` | 不是从盈利峰值回撤；失败只令当前候选不合格，不自动减仓或撤 Add |
| **Dynamic Deleveraging** | `L_effective > L_max` 时以 `reduce-only` 降向 `L_target` 或更小安全目标 | 不需人工再次审核，不消费或返还 Add，不可反向开仓 |
| **Hard Protective Stop** | 限制单笔计划损失的交易所原生保护优先路径 | 跳空和限价未成交仍可能造成穿透，必须有压力附加项 |
| **Trend Exit** | 冻结趋势结构失效或反向条件触发的退出 | 与其他退出由唯一目标仓位仲裁器合并 |
| **POST_REDUCTION_MARGIN_NORMALIZATION** | 逐仓减仓成交并对账后，把本次实际释放且已预留的场内保证金中冻结部分回加剩余仓位 | 不增仓、不放宽止损、不调用 Vault；未认证或失败时保持更小仓位或继续退出 |
| **Excess-margin Normalization** | `ISOLATED_REMOVABLE` 增仓和保护完成对账后，可选地按场所原生事实移出超过冻结缓冲的保证金 | 不属于 Add 数量算法，不得降低清算缓冲 |

## 9. 交易所、账户与保证金

| 术语 | 定义 |
| --- | --- |
| **Venue / 交易场所** | Binance、Hyperliquid Core 或某个独立 HIP-3 DEX 等执行域；人工批准后锁定，不能自动换所 |
| **Execution Domain / 执行域** | 具有独立市场运营、预言机、账户、抵押、规则、限速和故障结论的认证边界 |
| **margin_mode** | cross 或 isolated；每个 Freqtrade bot/config 只使用一种模式并独占账户 |
| **collateral_scope** | 可以共同承担保证金与清算风险的账户、DEX、抵押资产和 margin mode 范围 |
| **collateral_pool_id** | 某抵押池及其版本化共享边界的唯一身份；变化使相关执行和风险证书失效 |
| **CROSS_SHARED** | 多仓共享抵押池与清算风险；不虚构单仓可提保证金 |
| **ISOLATED_REMOVABLE** | 仓位抵押隔离且场所允许在安全条件下增减 isolated margin；normalization 必须独立认证 |
| **STRICT_ISOLATED** | 活动仓位保证金不能主动移出，只随减仓按场所规则释放；禁止绕过限制 |
| **P_executable** | 结合方向、盘口、允许滑点、订单类型和容量得到的预期可成交价格，不等于 Last 或屏幕价 |
| **Mark Price** | 用于权益、保证金和清算的场所价格口径；不能自动替代信号或可成交价格 |
| **Reduce-only** | 只允许减少既有净仓，不得反向建立新仓的订单语义；需要逐场所认证 |
| **Native Protection / 原生保护** | 已在交易所确认、能够在 Trading 控制面故障时继续存在的止损/保护订单 |

## 10. 状态、认证与运营

| 术语 | 定义 |
| --- | --- |
| **NORMAL** | 可在全部风控通过后生成提案、开仓、已授权加仓、减仓和退出 |
| **NO_PYRAMID** | 禁止加仓；剩余加仓授权按合同失效 |
| **NO_NEW_POSITION** | 禁止新仓和加仓，只管理现有风险 |
| **REDUCE_ONLY** | 只允许撤销增险、维护保护、减仓、退出和对账 |
| **KILL_SWITCH** | 停止增险、撤销增险、确认事实并受控保护/减仓/退出；不是无条件大额市价清仓 |
| **Frozen / 冻结状态** | 事实或权限不满足，禁止扩大风险，只允许对账、保护、减仓和退出 |
| **Unknown / 未知状态** | 订单、仓位、余额、价格、数据或资金结果无法确认；按最坏情景处理，不能猜测成功或失败 |
| **Reconciliation / 对账** | 用交易所、链上与内部持久事实解决预期状态和真实状态差异的过程 |
| **Certification Unit / 认证单位** | 由 `CapabilityCertificate.scope` 明确绑定的策略、参数、来源、板块、方向、场所、适配器、worker、账户、margin mode、抵押池、档位和 Add 层级组合；没有作用的维度显式为 `NOT_APPLICABLE`，不能省略后猜测 |
| **CapabilityCertificate / 能力证书** | 唯一能力证书对象；以统一 Schema 和 `certificate_type` 表达 `STRATEGY_EVIDENCE`、`EXECUTION`、`RISK_COVERAGE` 或 `MARGIN_NORMALIZATION` 的证据、作用域、版本、有效期、失效条件与状态。人工审核权限由 RBAC/ABAC、职责分离和 MFA 决定，不创建“审核证书”；任何辅助建议源也没有证书可获得交易、签名或风控覆盖权 |
| **Shadow / 影子** | 使用实时事实计算候选、风险或执行结果，但不发送真实订单 |
| **Small Live / 小额实盘** | 仅在独立批准容量和有效 `CapabilityCertificate` 作用域内使用真实资金取得场所证据；它是能力认证环境，不是功能不完整的产品阶段 |

## 11. 明确禁用或应避免的表述

| 避免表述 | 应使用的精确表述 |
| --- | --- |
| “总资金” | `Total Capital Snapshot_0`、Current Portfolio MTM Equity、Managed Settled Capital 等具体口径 |
| “浮盈可以再拿出来加仓” | 按 `E_campaign` 计算目标差额，并在已到账场内资金、冻结授权和动态预算内加仓 |
| “1.5% 风险” | 若指资金占用，用 `trade_funding_pct`；若指高风险最大计划损失，用 `3R = 1.5%` |
| “每次加仓 N%” | 每次 Add 默认补到 `L_target` 的安全差额；只控制次数，不设每级百分比 |
| “回调止损” | 布林偏差回调过滤、MFE 高水位回撤、硬止损、趋势退出必须分别命名 |
| “Vault 余额可用” | 明确是展示余额、Eligible Vault Equity、已批准划转额度还是交易所已到账保证金 |
| “已下单/已平仓” | 区分意图已创建、请求已发送、交易所已接受、部分成交、完全成交、仓位已归零和财务已结算 |
| “Binance/Hyperliquid 已支持” | 明确所需 `CapabilityCertificate` 类型及具体策略、账户、执行域和风险作用域是否有效 |
| “Telegram 批准后直接下单” | Telegram 提交审核操作，Trading 校验身份、授权、幂等和实时风控后才产生 `OrderIntent` |
| “自动恢复” | 明确恢复门、对账、冷却、人工解锁和哪些旧授权永久失效 |
