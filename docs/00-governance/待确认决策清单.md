## 1. 使用说明

本清单只收录会改变产品范围、安全边界、实现形态、运行责任或认证方法的决策。其他文档可以引用决策 ID，但不得复制独立状态。用户已经授权：凡目标明确且不需要外部事实或实验数据的事项，按满足功能和安全目标的最小成熟方案直接确认，不再作为逐项问卷。

奥卡姆约束：只有具备独立生命周期、独立权限边界、独立外部副作用或独立扩缩容/故障域的概念，才建立新的领域对象、服务或专项文档。可计算状态、页面步骤、规则函数、投影和仅供未来想象的能力，不升级为独立实体。

“一步到位”在本系统中指完整目标范围一次性设计和工程交付，不是跳过真实资金验证。回放、影子、仿真和小额实盘属于能力认证证据环境，不是残缺产品阶段。实现完成不等于真实启用；只有认证单位状态为 `CERTIFIED`、证书有效、系统健康且开关显式启用时，能力才可作用于真实资金。

状态定义：

| 状态 | 含义 |
| --- | --- |
| `OPEN` | 只用于必须由用户提供、系统无法自行推断的外部事实；在补充前采用安全默认 |
| `RESEARCH_REQUIRED` | 设计方法已选，但参数或能力必须由预登记研究、账户事实或执行证据冻结 |
| `CONFIRMED` | 已由当前权威方案明确，不再作为普通开放问题 |
| `SUPERSEDED` | 已被另一决策 ID 正式替代，仅保留审计 |

决策优先级使用独立命名空间：`DEC-P0` 会阻塞 PRD、架构或安全基线；`DEC-P1` 会阻塞影子/模拟或真实账户接入；`DEC-P2` 会阻塞扩容、商业化或高级能力。它们不是发布阶段，也不是生产事故严重度。

状态变更规则：

1. `OPEN → CONFIRMED` 必须保存外部事实、确认人、确认时间、理由和影响文档。
2. `RESEARCH_REQUIRED → CONFIRMED` 必须关联预登记研究、结果、批准人与证据版本，不能只填一个结果数字。
3. 已确认项改变时不得覆盖历史；新建版本或替代 ID，并审计受影响合同、测试、配置、证书和存量仓位。
4. `OPEN` 或 `RESEARCH_REQUIRED` 项没有关闭时，实现不得填入隐式生产默认；对应能力保持关闭或最多进入研究、只读、影子或仿真。

## 2. 已定基线：不再列为开放争议

以下规则来自现有两份权威文档，专项决策只能细化，不能反向打开：

- Trading 是受管账户唯一日常订单出口；Freqtrade 是 Binance 与 Hyperliquid 的受控底层订单执行引擎。
- SYSTEM 和 MANUAL 初仓都必须人工明确批准并通过 Risk Engine；Risk Engine 拒绝不可覆盖。
- 自动加仓默认关闭；启用后低/中/高默认最多 1/2/3 次，最大有效杠杆为 3x/5x/10x。
- `1R_0 = Total Capital Snapshot_0 × 0.5%`；低/中/高整份经济仓位最大计划损失为 1R/2R/3R。
- `trade_funding_pct = N%` 生成的是完整战役共用的逻辑 Trade Funding Envelope，不是最大亏损、每次 Add 额度或必须逐笔从 Vault 提取的金额。场所已有已结算运营资金足够时只做内部预留；只有初仓前确有缺口时才走 Vault/CTO 划转，持仓中绝不补仓救援。
- 30%/50%/100% 冻结收益率只解锁候选；每次 Add 按当前 `E_campaign` 直接计算到冻结 `L_target` 的安全净增量，不配置每级固定数量或风险比例。
- 逐仓模式默认先执行单腿净增仓/净减仓并完成成交与保护对账；只有已认证 `ISOLATED_REMOVABLE` 才可随后做 excess-margin normalization，减仓后的 `POST_REDUCTION_MARGIN_NORMALIZATION` 只能使用本次场内释放并预留的保证金。
- 任意大于零的真实 Add 成交完整消费一次 Add；终态确认零成交不消费；动态去杠杆不返还已消费次数。
- Current Portfolio MTM Equity 完整包含最新正负未实现盈亏；未实现亏损立即收紧动态预算，未实现浮盈即使进入实时分母，也不能扩大 `Total Capital Snapshot_0`、冻结 1R、资金信封、档位或 Add 次数。
- Vault 风险计入默认 `EXCHANGE_ONLY`；计入风险、资金划转、自动利润归集和自动运营补充是独立开关。Vault 永不救活动仓位。
- Web/PWA 是主控制台；Telegram 是受限辅助入口。PWA 离线不得批准、恢复或假定操作成功。
- 完整目标一次性包含 Binance、Hyperliquid、Web/PWA、Telegram、SYSTEM/MANUAL 提案、人工初仓审核、三档风险、Add-1/2/3、动态减仓、保护、退出、Vault 只读/人工划转/自动归集/可选自动补充；各能力真实启用仍逐认证单位受证书限制。
- UI 与视觉系统采用 [thedankoe.com](https://thedankoe.com/) 启发的极简编辑风格，统一支持深色和浅色；不复制其品牌资产，也不牺牲交易信息密度、风险辨识和无障碍。
- 当前系统不建设独立自动代理，也不为假设能力预建领域实体；任何辅助建议源另行立项，且永远无密钥、签名、下单、资金或风控覆盖权。
- 未知事实禁止新增风险；单所故障不能自动换所、补单或对冲未知订单。
- FundPool、FundShare、管理费、公开募资和 DAO 不属于本系统，不做占位实现。
