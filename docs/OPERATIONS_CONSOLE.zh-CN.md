# 运营控制台行为说明

本文记录本地最新 TradeOps 控制台的页面职责与安全行为。完整接口合同仍以运行中的
`/openapi.json` 为唯一真源；本文只说明产品如何呈现这些合同。

## 执行模式

用户可见模式只有：

- **TESTNET / 测试模式**：满足执行条件的订单只发送到已配置的交易所测试端点。
- **LIVE / 生产模式**：满足执行条件的订单使用生产适配器，可能影响真实资金，但仍需
  逐项通过所有独立能力 Gate。

`SETUP` 只表示团队尚未选择执行模式，不能成为账户、提案、授权、订单、仓位或资金
事实的环境。已退出产品的 SHADOW 模拟系统不再作为模式、隐藏路由、API 回退或虚拟
余额来源。

页眉的**当前模式**是唯一允许修改团队当前模式的控件。拥有
`team.manage` 的管理员可查看目标模式切换条件、下单准备提示和最终确认控件。
切换到生产模式必须使用页面展示的精确确认文案；请求同时携带
`expected_version` 与幂等键，并写入审计。

切换成功不会开启实盘下单、自动加仓、资金划转、签名或广播。来源环境尚未执行的
交易授权与订单意图会失效；历史提案继续保留原环境。

## 账户管理

账户管理可以提前查看和配置 TESTNET、LIVE 两种账户。页面中的环境选项只改变账户
配置范围，不会切换团队模式。

每个账户按团队、环境、交易所和账户 ID 隔离，并支持：

- 添加与修改名称；
- 轮换凭据且永不回显敏感字段；
- 连接测试；
- 启用与停用；
- 二次确认删除及业务引用检查；
- 查看运行绑定与交易准备状态。

当账户仍被提案、授权、订单意图、交易所订单、未平或状态未知仓位、资金任务、运行
绑定或其他业务记录引用时，删除会失败关闭。执行服务从团队当前模式确定实际环境，
不会信任客户端传入的环境决定订单路由。

## 信号

Perptape 与 Webhook 是两套独立信号产品：

- **Perptape** 按币种和方向展示机会卡片，同一快照内合并突破周期，筛选项默认紧凑
  收起。多头标的名称使用克制的绿色，空头使用克制的红色。“突破详情”打开对应交易所
  与币种的 Perptape 市场扫描页，筛选查询只传入交易所原始标的名（例如
  `PROVEUSDT`），不拼接交易所或规范化币种前缀；交易所图表保持独立入口。
- **Webhook 信号**只展示已经通过对应信号源签名、请求时间、Nonce/重放、幂等、
  大小、版本和格式校验的事件。过期记录可以作为事实保留，但不会自动变成审核或执行授权。
- **信号源**中的服务端真源汇总和单个信号源卡片默认收起。展开后才展示脱敏健康状态、
  连接测试、编辑、凭据轮换、停用和删除等 RBAC 允许的操作。

信号新鲜度或行情就绪不等于提案资格。创建提案时，服务端会重新校验精确品种、团队
模式、账户范围、风险政策和当前事实。

## 审核队列与交易历史

- **审核队列**按提案创建时间倒序展示，最新记录在前。可按环境、标的、方向、
  风险档位和来源或状态筛选。
- **交易历史**是原 `/campaigns` 页面的用户可见名称，保留进行中和已关闭交易的授权、
  风险预留、订单、成交、保护、对账和最终结果；可按标的/账户、方向、交易所和状态筛选。
- 两个列表均默认每页 50 条，可切换为每页 100 条；单页不提供超过 100 条的选项。
- 达到独立审核阈值后，系统自动运行实时风控、签发短期授权、预留风险，并在租约、
  fencing 和幂等边界内调用精确账户 Freqtrade Worker。超时或结果不明时只查询原订单，
  不重复发送。

## 资金中心与绩效报表

资金中心负责生产金库配置和直接资金流程状态。NoTilt Vault 与 Safe Spending Limits
可以同时接入；管理员从中选择一个作为新建资金操作的当前金库，切换选择不会删除另一
金库的配置。每条操作会冻结所选金库，并重新校验地址、网络、资产、金额、费用、额度、
回执与能力 Gate。

浏览器表单只接收公开地址与账户范围，不要求钱包私钥、助记词、钱包密码或签名令牌。
人控钱包或有效多签政策始终是签名与广播边界。测试模式不展示生产 Vault、Safe、提现
或真实资金划转配置。

绩效报表负责账户权益历史和图表：

- 只允许选择团队当前模式下的账户；
- 账户多选只影响报表展示；
- 无法可信汇总时仍保留各账户独立曲线；
- 缺失、过期、错位或断连数据不会补零；
- 只有口径与时间可信时才绘制汇总曲线；
- 数据断档保持断档，不强制连线；
- 支持时间范围选择与全屏查看；全屏优先扩大实际图表，而不是放大外围留白。

## 风控、通知与页面框架

- **风控中心**区分日常政策修改与实时安全阻断。日常修改区域默认收起；管理员直接修改
  与普通成员提案审核继续遵循各自权限和审计规则。
- **通知中心**统一管理 Telegram、Slack、飞书/Lark 和邮件路由。凭据加密保存且只返回
  脱敏状态；账户或信号源页面不重复配置通知账户。最近投递记录可按事件/范围、
  渠道、状态和环境筛选，默认每页 50 条、最大 100 条。通知投递进程没有交易、资金、签名或广播接口。
- 桌面菜单可向左收起，移动端使用抽屉导航。页眉“当前模式”控件与主题控件紧密衔接，
  服务端仍会强制检查权限、准备度、版本、幂等和审计。

控制台支持中英文、浅色/深色、键盘焦点、响应式布局和减少动画设置。页面是否显示按钮
永远不能替代服务端授权。

## 本地验证边界

使用独立 Compose 控制台和只读同步 Worker：

```bash
TRADING_PUBLIC_PORT=8022 ./scripts/run_compose.sh --runtime
curl --fail http://127.0.0.1:8022/health/live
curl --fail http://127.0.0.1:8022/health/ready
```

构建成功、按钮可见或进程健康都不能证明交易所账户、订单发送或资金路径已经就绪。
必须结合真实 API 响应与页面状态验收；自动化验收不得发送任何 LIVE 订单。
