# 需求追踪与证据矩阵

> 文档编号：REG-TRACE-001
> 状态：BASELINE
> 日期：2026-07-18

## 1. 追踪原则

需求追踪只回答四个问题：用户要完成什么流程、哪些不变量不能破坏、什么代码/测试证明当前实现、还缺什么真实入口。它不为每个内部步骤创建 WP、证据包、快照、绑定或证书实体。

```text
用户流程
  → 核心业务不变量
  → 生产代码与权威状态
  → 自动化测试 / 运行验证
  → 当前结论与明确缺口
```

当前结论只使用下列状态：

| 状态 | 含义 |
| --- | --- |
| `IMPLEMENTED_SHADOW` | 有生产代码、数据库/纯计算入口和自动化测试，但无真实发送 |
| `PARTIAL` | 只有当前里程碑需要的部分实现，缺口明确且默认关闭 |
| `NOT_IMPLEMENTED` | 仅存在长期愿景或合同，没有当前可调用实现 |
| `DISABLED` | 已有简单 Gate 且默认关闭 |
| `RESEARCH_REQUIRED` | 参数或外部事实必须先由研究/运行验证决定 |

## 3. 当前端到端流程

| 流程 | 自动化证据 | 当前结论 |
| --- | --- | --- |
| Proposal → Approval → RiskDecision → Authorization | 自审、双人批准、过期/越权/超量、确定性风险测试 | `IMPLEMENTED_SHADOW` |
| Authorization → Reservation + OrderIntent | 原子事务、幂等重复、同 key 语义冲突测试 | `IMPLEMENTED_SHADOW` |
| OrderIntent → synthetic VenueOrder/Fill → Position/Protection | 部分/全成交、Unknown 持有风险、保护覆盖测试 | `IMPLEMENTED_SHADOW` |
| 场所事实 → Reconciliation → Campaign PnL | 订单/成交/仓位/保护差异与费用/资金费/滑点测试 | `IMPLEMENTED_SHADOW` |
| sender lease → 接管 → 旧 token 拒绝 | 对账后接管与 fencing 测试 | `IMPLEMENTED_SHADOW` |
| 浏览器中的内部用户流程 | M1 提案/审核/授权 + M2 Campaign/仓位/订单/风险/异常页面 | `IMPLEMENTED_SHADOW` |
| 真实交易所读取/发送 | Binance/Hyperliquid 窄只读与 TESTNET 合同已实现；无真实账户、凭据或网络副作用实证 | `CONTRACT_ONLY_DISABLED` |

## 4. 长期产品范围与缺口

| 产品目标 | 下一真实用户结果 | 当前状态 |
| --- | --- | --- |
| Web/PWA | 内部用户完成提案、审核、风险、授权和 SHADOW Campaign 运营 | `IMPLEMENTED_SHADOW` |
| SHADOW 运营页面 | Operator 操作 Campaign、事实、对账和 Unknown | `IMPLEMENTED_SHADOW` |

| Binance / Hyperliquid 只读接入 | 查看真实私有事实并对账 | `NOT_IMPLEMENTED` |

| AUTO_ADD | 冻结 AddUnit、Perptape 候选、最终风控、正成交消费与 Web/Mock Telegram 收紧入口 | `IMPLEMENTED_SHADOW_DEFAULT_DISABLED` |
| Margin | 一个可恢复的仓位/保证金用户流程 | `NOT_IMPLEMENTED` |

完整愿景不删除，但开发顺序以 [后续端到端开发路线](../08-implementation/后续端到端开发路线.md) 为准，不要求所有能力同时工程交付。

## 5. 风险与拒绝矩阵

| 风险 | 必须结果 | 当前验证 |
| --- | --- | --- |
| 重复命令 | 返回原回执，不复制 Proposal/Reservation/Intent | 已自动测试 |
| 相同 key 不同语义 | 明确 idempotency conflict | 已自动测试 |
| 自审或高风险单人批准 | 拒绝或保持待审 | 已自动测试 |
| 陈旧/未知仓位/未知保护 | 禁止新增风险 | 已自动测试 |
| 过期、越权、超量授权 | 拒绝 | 已自动测试 |
| Reservation 与 Intent 部分提交 | 整体回滚 | 已由同事务和集成测试验证 |
| OrderIntent Unknown | 不释放预留、不自动重发 | 已自动测试 |
| 多退出候选 | 唯一最小目标和最高紧迫度 | 已自动测试 |
| 活动意图存在时再次减仓 | 拒绝重复意图 | 已自动测试 |
| 订单/成交/仓位/保护不一致 | DIFFERENCE/UNKNOWN 并可人工处理 | 已自动测试 |
| sender 双主或旧 token | 拒绝旧 sender | 已自动测试 |
| Gate 未批准 | 保持 DISABLED | 已由迁移和集成测试验证 |
| UI/Telegram/VenueAdapter 不存在 | 不得描述为已支持 | 文档与入口清单验证 |

## 6. 证据规则

- 当前工程证据是版本化代码、单一初始迁移、自动化测试结果和 Git 提交。
- 纯字段复制、证明哈希和重复数据库约束不单独生成证据文档。
- 真实适配器出现后，保存其请求/回执、场所事实、对账与故障演练制品；不提前建设证书状态机。
- 测试结果必须给出真实数量、失败、覆盖率、环境和数据库边界；不能写“基本通过”。
- 未实现能力一律保持关闭，不能因长期文档写得完整而升级当前状态。
