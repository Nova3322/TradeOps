## 1. 目的

本文建立从产品需求到可复查证据的唯一追踪方法：

**业务需求 REQ → 风险场景 RISK → 状态 / 不变量 STATE → 验证 TEST → 持久证据 EVID → 发布结论**

目标不是增加文档数量，而是确保每个“支持”“安全”“已认证”都有来源、验证与失效条件。本文只建立基线和待填写位置；任何空白、`待实现`、`待验证` 或证据缺失都不能被解释为通过。

## 3. 状态与完成规则

### 3.1 需求状态

| 状态 | 含义 |
| --- | --- |
| `固定需求` | 业务语义已确定，仍可能未实现 |
| `待外部事实` | 设计已冻结，但实际部署、法律或负责人事实尚未提供；直接依赖能力关闭 |
| `待研究` | 需要预登记研究与时间外证据 |
| `待实现` | 合同明确但尚无实现证据 |
| `待验证` | 已有实现候选，但证据不完整 |
| `已认证` | 在明确版本、环境和范围内通过全部门 |
| `已暂停` | 证据、风险或健康失效 |
| `已退役` | 不再服务新提案 |

### 3.2 一条需求的完成定义

一条需求只有同时满足以下条件才可标记 `已认证`：

- 来源、适用范围和责任人明确。
- 所有依赖的 `DEC-*` 已关闭；研究参数已通过对应证据门。
- 正常、边界、拒绝、权限、并发、重启与故障测试适用项均通过。
- 关联风险场景已有控制，并证明失败时进入安全状态。
- 证据为持久制品，含版本、环境、运行 ID、时间与结果。
- 残余限制、有效期与自动失效条件已登记。
- 发布审批只在证书范围内授权，不能把局部通过扩展为全产品通过。

| 风险 ID | 风险场景 | 默认安全结果 |
| --- | --- | --- |

| `RISK-002` | 超额数量被静默缩量后下单 | 拒绝原提案，展示安全上限 |
| `RISK-003` | 过期、撤销或已消费授权重用 | 拒绝并审计 |

| `RISK-005` | 订单结果未知后盲目重发 | 转 Unknown Heat，只查询原意图 |
| `RISK-006` | 部分成交未保护 | 停止增险，补保护或退出 |
| `RISK-007` | 风险或流动性越界仍 Add | Add 归零 / 安全缩量，不发送越界量 |
| `RISK-008` | 盈利里程碑被当成单条件加仓 | 候选不执行，记录门失败 |
| `RISK-009` | Add 固定手数或重复消费 | 阻断并使能力证书失效 |
| `RISK-010` | 减仓订单意外反向开仓 | reduce-only / 等价防护阻断 |
| `RISK-011` | Freqtrade 自主策略与 Trading 竞争 | 关闭旁路，冻结执行单元 |
| `RISK-012` | 账户、仓位、订单或抵押池事实不明 | 禁止新增风险，对账 / 减仓 / 退出 |
| `RISK-013` | 自动跨所补单或接管未知订单 | 阻断并要求新提案 |
| `RISK-014` | Vault 余额被当作交易所保证金 | 阻断订单，风险 / 资金重新对账 |
| `RISK-015` | 同一资金在源端、在途、目的端双计 | 冻结新风险与划转，确定唯一归属 |
| `RISK-016` | Vault 为活动仓或清算压力救援 | 自动与人工请求均拒绝 |
| `RISK-017` | 资金划转与交易凭证混权 | 停用凭证、冻结服务、轮换与审计 |
| `RISK-018` | 稳定币脱锚 / 价格未知仍满额计价 | 贡献降级或归零，停止增险 |
| `RISK-019` | strict isolated 主动移出保证金 | 阻断动作，证书失效 |
| `RISK-020` | normalization 顺序错误或重复使用释放额 | 冻结抵押池，保持更小仓位并对账 |
| `RISK-021` | Web / PWA 离线批准或重复点击 | 拒绝，要求在线读取唯一回执 |
| `RISK-022` | Telegram 越权、过期或缺少强认证 | 拒绝并审计 |
| `RISK-023` | 多标签导致隐式自审 / 越权 | 显式拒绝优先，阻断动作 |
| `RISK-024` | 数据陈旧、规则漂移或未分类标的增险 | `eligible_to_trade = false` |
| `RISK-025` | 重启重放历史订单 / Add | 只对账，不重放业务请求 |
| `RISK-026` | 平仓请求已发即释放风险 | 保留 Heat 到真实对账完成 |
| `RISK-027` | 辅助建议源被错误授予提案修改、风险、签名、下单或资金权限 | 阻断输入，撤销错误权限并触发安全事件 |
| `RISK-028` | 审计 / 数据库不可用仍增险 | NO_NEW_POSITION 或更严，减险继续 |
| `RISK-029` | HIP-3 预言机、时段或 operator 异常 | 冻结该域 / 标的增险 |
| `RISK-030` | 外部人工改仓后系统沿用旧状态 | 冻结账户并强制对账 |

## 18. 维护流程

1. 新需求先分配 `REQ-*`，写明来源与安全默认。
2. 识别风险并复用或新增 `RISK-*`。
3. 指定涉及的 `STATE-*` 与不变量。
4. 在开发前选择 `TEST-*` 和证据形态。
5. 实现和验证只追加证据实例，不修改历史通过记录。
6. 决策、参数、代码、交易所规则、账户或证书变化时，计算受影响的 REQ 与证据并使相应认证失效。
7. 发布前检查所有阻断需求、开放缺口和证书有效期。
8. 生产事件后把真实失败映射回 REQ / RISK / STATE / TEST，补充验证，不能只修单点代码。
