# 后续端到端开发路线

> 状态：BASELINE
> 日期：2026-07-31
> 目标：保留完整产品愿景，按真实可操作用户流程逐步交付

## 交付规则

1. 一个里程碑必须让内部用户完成一个真实可操作的端到端流程。
2. 里程碑按用户结果组织，不按表、哈希、绑定、投影、服务或迁移数量组织。
3. 尚未实现的能力保持关闭；不为未来能力预建通用平台。
4. 每次新增持久实体必须证明它拥有不可替代、需跨重启的权威状态或不可逆外部副作用。
5. 专业级认证清单可以作为未来发布验收材料，但当前不建设 CapabilityCertificate、证据包或证书状态机软件平台。
6. 代码行数、表数量、迁移数量、WP 数量和文档数量都不是进度指标。
7. 任何里程碑都不能降低风险、幂等、Unknown、保护、对账、fencing 和审计不变量。

## 里程碑一：内部提案与审核工作台（M1 工程完成）

用户结果：内部 HUMAN Proposer 能创建/提交 MANUAL Proposal，内部 SERVICE strategy principal 能创建/提交带策略版本的 SYSTEM Proposal，Reviewer 能查看冻结内容并批准/拒绝，Operator 能看到服务端事实形成的风险决定和短期授权。

最小范围：

- 对外业务 API 与最小 Web/PWA 页面；
- 内部用户登录、五角色和账户/场所作用域；
- Proposal、Approval、RiskDecision、TradingAuthorization 的完整拒绝路径；
- 可见审计和异常回执。

当前结果：非生产环境可通过显式 Mock 身份在浏览器完成 Perptape SYSTEM/MANUAL 提案、冻结、通知、step-up 审核、RiskDecision 和 TradingAuthorization；默认关闭的真实 Telegram 私聊长轮询、内部用户绑定和审核深链已经实现。不能发送订单，危险 Gate 仍关闭；正式托管 IdP/Passkey、Webhook 部署与真实消息送达实证仍是外部缺口，不能用本地结果宣称已上线。

## 里程碑二：SHADOW Campaign 运营台（M2 工程完成）

用户结果：Operator 能把授权转换为风险预留和 SHADOW OrderIntent，查看 Campaign、目标仓位、模拟成交、保护、PnL 和对账差异，并处理 Unknown。

最小范围：

- 当前 `TradingService` 能力经业务 API 暴露；
- Instrument Catalog 和 SHADOW 场所事实录入；
- Campaign 当前目标与 reduce-only 意图；
- 对账、人工处理、fencing 接管和可读指标。

当前结果：Operator 可经业务 API 和 Web 将授权转换为原子风险预留与 OrderIntent，记录明确标记的合成 SHADOW order/fill/position/protection/equity/funding，计算目标与 reduce-only 意图，查看 PnL、对账和 Unknown 异常。Mock 与默认关闭的真实 Telegram 私聊适配器会通知成交、保护和异常，真实通道只执行服务端重新校验后的收紧风险动作。完整初仓到退出流程与 Unknown 持有风险路径已使用 PostgreSQL 自动化验证；不依赖真实交易所。

## 里程碑三：单一场所只读事实接入（M3 完成）

用户结果：Operator 能查看一个明确环境的 Binance 私有订单、成交、仓位、保护、权益和资金费事实，并在独立 `TESTNET|LIVE` scope 中与内部预期对账。

最小范围：

- 一个只读 VenueAdapter；
- 明确的新鲜度、Unknown 和去重规则；
- 恢复前对账与单一 sender lease 演练；
- 不实现真实订单发送。

完成标准：只读接入失败时 fail closed；不会创建重复场所事实；不向第二个场所抽象未验证的通用平台。

当前结果：已实现标准 USDⓈ-M 与 Unified Account PAPI 窄读 Adapter、签名与官方响应合同、环境隔离持久化、重复同步、外部事实差异、RBAC 和 Web 展示；2026-07-31 已完成 Unified Account 主账户真实读取。读取仍默认关闭，也不自动授权订单发送。

## 里程碑四：Binance 受控发送流程（M4/M10 完成）

用户结果：在用户另行批准的非生产环境中，Operator 能从已审核 Proposal 发出一笔受控订单，确认保护并退出。

最小范围：

- Binance USDⓈ-M TESTNET 窄客户端、client order identity、发送 fencing；
- 部分成交、撤销、Unknown、保护和恢复；
- 端到端对账和成本/PnL；
- 对应 Gate 只在批准作用域内启用。

当前结果：官方 TESTNET 与 Unified Account PAPI LIVE 主机硬边界、签名、query-before-send、部分成交、零成交撤销/拒绝、Unknown、原生保护、保护取消、恢复、退出、对账和 PnL 已由状态化本地合同与 PostgreSQL 自动化覆盖。2026-07-31 在用户明确授权下完成 5 XRP 的最小主网开仓到退出，最终空仓、无活动订单、Campaign CLOSED、Gate DISABLED。该实证不自动授权持续实盘、AUTO_ADD、资金动作或第二账户。

## 里程碑五：第二场所与受控程序接管（M5/M10 完成）

用户结果：相同 Trading 核心可在独立 `TESTNET:account:HYPERLIQUID` scope 管理 Hyperliquid Core 提案、显式 IOC、保护、Unknown、对账、退出和 PnL，而不会把 Binance 与 Hyperliquid 抽象成任意场所平台。

最小范围：

- Core `POST /info` 只读事实与官方 TESTNET `POST /exchange` 窄合同；
- 稳定 128-bit cloid、显式批准限价、query-before-send、cancel-by-cloid 和 trigger 保护；
- Trading 唯一拥有 Campaign、风险预留、OrderIntent、fencing、对账与 PnL；
- signer 只通过部署注入边界提供，代码和配置不保存私钥；
- HIP-3、Freqtrade 通用平台、保证金动作和跨所接管不进入本里程碑。

当前结果：官方 Core Info/Exchange 请求形状、主机和 `dex=""` 边界、环境隔离、官方 SDK signer、IOC 精度、Unknown 恢复、保护取消、退出、资金费和 PnL 已用状态化本地合同与 PostgreSQL 自动化完成。2026-07-31 使用 API Wallet 和默认主账户完成 0.00016 BTC 的最小主网闭环，最终空仓、无活动订单、Campaign CLOSED、Gate DISABLED。该结果不授予 HIP-3、资金、Margin 或无人值守持续实盘能力。

## 里程碑六：AUTO_ADD、风险减仓与自动退出入口（M6 SHADOW 工程完成）

用户结果：Operator 能在 Campaign 页面看到符合范围的后续 Perptape 候选，经冻结 AddUnit 和全部当前风险事实创建 SHADOW Add；能一次提交更小目标并形成 reduce-only Intent；冻结失效价或 KILL_SWITCH 能在 Perptape/交互层不可用时独立形成 EXIT。Mock 与真实私聊 Telegram 允许绑定内部用户的短时、版本化收紧风险动作，不允许增险。

最小范围：

- Proposal 冻结总/初仓数量、AddUnit、Add 触发价和失效价；低/中/高风险最多 1/2/3 Unit；
- Perptape 后续 READY 候选、盈利仓位、足额保护、授权、风险容量、Unknown、活动 Intent 和最终 Risk Engine 全部门控；
- 首个正成交才消费 AddUnit，零成交取消/拒绝不消费；
- TargetPositionArbiter 与 reduce-only Intent 同事务，自动退出不依赖 Perptape；
- Web、Mock Telegram 与真实私聊 Telegram 共用 Trading 服务、幂等回执、RBAC 和 Campaign target version。

当前结果：上述 SHADOW 流程与拒绝路径已使用一次性 PostgreSQL 自动化验证，`AUTO_ADD` 初始 Gate 仍为 `DISABLED`。真实 Telegram 代码和本地绑定已实现但网络开关未启用、没有真实送达实证；常驻自动管理 worker、真实 Perptape 服务和任何测试网/实盘 Add 均未运行。这不是独立策略、回测或真实收益证明。

## 里程碑七：Vault 与资金中心（NoTilt 三链计划和回执边界完成，真实外部事实阻塞）

用户结果：Treasury Admin 能在 Web 查看 Vault/场所资本事实与源端预留/在途，创建人工双向资金提案，经双人独立复核和独立 TransferAuthorization 后执行明确标记的 SHADOW/TESTNET Mock 划转，并以目的端权威事实和资金 scope 对账完成结算。

当前结果：资金角色与 SYSTEM_ADMIN 分离；交易授权不能代替资金授权；创建者不能审核、授权或执行；源端预留立即扣减风险可用资本；Unknown 保持占用且不重发；活动仓位、活动/Unknown 订单或缺少机器 MATCH 时拒绝资金路径。NoTilt 使用官方 SDK 固定读取 Ethereum/BSC/Arbitrum Registry 与 Vault budget，交易服务只生成交给独立钱包的持久化未签名交易；可信 RPC 回执按链、发送者、Vault、固定函数、参数、事件和确认深度验证，release 的请求、执行、超费取消与 deposit 可推进同一 CapitalTransfer。Binance、Hyperliquid 与 Vault USD 净值进入同一 LIVE 视图。当前 Arbitrum assignment 尚未激活、没有 Vault 地址，也没有交易所资金适配器，`CAPITAL_TRANSFER` 保持关闭。

## 里程碑八：自动利润归集与可选运营补充（M8 非凭据工程完成，真实自动资金阻塞）

用户结果：Treasury Admin 能配置一个非生产运营资金阈值，在两个独立 Gate 下评估利润归集或下一周期运营补充；系统只从已确认资本、已关闭 Campaign 实际净 PnL、空仓/无订单/无 Unknown 和机器 MATCH 计算金额，形成仍需双人复核的 TransferProposal。

当前结果：`AUTO_PROFIT_SWEEP` 与 `AUTO_OPERATING_REFILL` 均初始关闭且互不隐式启用。浮盈、净亏损补充、活动仓救援、陈旧事实、未对账、在途或 Unknown 均拒绝；候选计算不会签发 Authorization 或调用 Adapter。没有真实参数、签名器、常驻调度和真实到账实证，因此两个 Gate 保持关闭，测试结果只证明非生产合同。

## 里程碑九：实际结果、审计与恢复基线（M9 工程完成）

用户结果：内部用户能在一个页面按 `SHADOW|TESTNET|LIVE` 精确隔离查看 Campaign 来源、成交成本、分币种 PnL、绝对累计曲线和审计时间线；Operator 能确认数据库、Schema、Capability Gate 与外部配置边界，开发者能备份并只向可丢弃测试库恢复验证。

当前结果：`/results` 与对应 API 已交付，API 可按来源、来源类型/候选/版本、作用域、方向、风险档位、Campaign 和时间范围过滤；非生产事实有显式标签，不混合结算币种，也不在缺少期初资本/FX 真源时伪造百分比指标。运行状态不返回密钥值；备份/恢复脚本硬限制恢复目标为 `*_test`，并已用独立测试库验证 26 张业务表、五个关闭 Gate、Alembic revision 和 readiness。没有新增结果快照、审计投影、证据包、绩效账本或常驻 worker，也没有部署生产环境。

## 后续外部阻塞与愿景

后续工作必须由真实端到端需求和外部前置条件触发：托管 IdP/Passkey、Telegram Webhook/送达重试、生产 Secret Manager 与凭据轮换、常驻同步/执行 worker、生产数据库/部署/告警，以及实际 NoTilt Vault 地址、生效 assignment、真实交易所 withdrawal/deposit API 和钱包到场所的两端确认。Perptape 主站和 Binance/Hyperliquid LIVE 窄闭环已经实证，但持续运行仍保持关闭；Margin、HIP-3、真实资金划转和 AUTO_ADD 只能按具体外部合同另行交付，不建设通用平台，也不把小额实证解释成盈利或生产上线。
