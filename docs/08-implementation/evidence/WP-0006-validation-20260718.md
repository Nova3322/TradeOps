## 关键证据

1. final ORDER_PRECHECK 重新计算最新 MTM/UPNL、九类事实、七类 scope、Funding、Margin、杠杆、数量
   步长、冻结/动态损失上限；陈旧事实产生持久 DENY 决策，且无 Intent/Reservation。
2. ALLOW 决策、不可发送 SHADOW OrderIntent、RiskReservation、首笔 RESERVE ledger、两类当前状态、
   Initial/Add claim、audit 和 outbox 在同一事务提交。
3. 数据库延迟约束测试证明：单独插入 ALLOW 决策但不创建 Intent/Reservation 会在 commit 失败，事务
   回滚后仍只有原有完整原子图。
4. OrderIntent、Reservation 和 Decision 的 campaign/authorization/initial/add 组合外键、数量、Heat、
   Funding、Margin 与有效期由数据库再次绑定，不能拼接不同授权对象。
5. 根事实、ExecutionFact、RiskLedger 和历史拒绝 UPDATE/DELETE；直接把 SHADOW Intent 改成可发送由
   数据库拒绝且原值保持 false。
6. 同 Campaign 两个不同 Initial candidate 并发竞争只创建一个完整 Reservation；后到请求稳定返回
   `INITIAL_INTENT_ALREADY_ACTIVE`，没有半份账本。
7. 相同命令幂等键重放为 `ALREADY_PROCESSED`，不产生第二份 Intent/Reservation；候选本身另有
   `(campaign_id,candidate_ref)` 唯一语义绑定。
8. 部分成交把 0.2/0.5 的 Quantity 和相同比例 Heat/Funding/Margin 从 Reserved 迁到 Open；剩余保持
   Reserved，Initial 立即 CONSUMED、Campaign 立即 OPEN。
9. 后续 RESULT_UNKNOWN 把剩余 0.3 从 Reserved 迁到 Unknown，不释放；账本序号、状态版本和自动历史
   同步递增。
10. Initial 终态零成交把全部预留迁到 Released，Initial 保持 ACTIVE；新 candidate 可以重新执行完整
    风险复核并建立新的原子 Reservation，旧 Intent 没有被重放。
11. 初仓 FILLED -> POSITION_RECONCILED -> PROTECTION_CONFIRMED 后才激活 DORMANT Add package。
12. Add 的 30% 里程碑、趋势、保护、授权、`L_effective < L_min`、目标杠杆区间和基于当前仓位权益的
    目标差额均通过后，AVAILABLE -> CLAIMED 与 Reservation/Intent 同事务发生。
13. Add 终态零成交把全部风险释放并令 CLAIMED -> AVAILABLE；新的 candidate 可复核重试。任意 0.05
    正成交立即令 AddUnit CONSUMED，并在唯一 unit 场景令 package EXHAUSTED。
14. fact sequence 从 2 开始会稳定拒绝 `EXECUTION_FACT_OUT_OF_ORDER`；事实 payload/evidence hash、route、
    外部事实 id、时间和累计数量均有独立校验。
15. Quantity、Heat、Funding、Margin 四套桶在每次迁移后继续满足 Reserved + Open + Unknown + Released
    = Total；数据库状态守卫要求 current state 与无缺口 ledger/latest evidence 一致。
16. 新鲜 Risk request 若低报持久 Campaign/portfolio/scope/Funding 风险、遇到组织级 Unknown、缺失系统
    状态、非 NORMAL Add 或可用 Margin 不足均失败关闭。
17. 迁移 upgrade/downgrade/upgrade 和 Alembic drift 在 PostgreSQL 18.4 通过；迁移不 seed 决策、订单、
    Reservation、证书或能力启用事实。
18. `AUTO_ADD`、`CAPITAL_TRANSFER`、`LIVE_ORDER_SEND` 始终为 `DISABLED`；所有 OrderIntent 均由数据库
    固定 `execution_mode=SHADOW`、`dispatch_eligible=false`。
