## 关键证据

1. 相同完整输入、decision time 和版本产生完全相同的纯决策与 decision hash。
2. 1R 固定为冻结资本 0.5%；三档最大损失为 1/2/3R，最大有效杠杆为 3/5/10x。
3. Current Portfolio MTM Equity 由 settled equity、最新 UPNL 和合格 Vault 分量派生；负 UPNL
   立即降低 Dynamic Mode Cap，正 UPNL 不突破冻结/提案容量。
4. 属性测试对随机冻结资本、当前 MTM 与风险档位证明 effective cap 永不超过冻结或动态边界，
   安全数量永不超过请求数量。
5. 九类事实任一陈旧或 Unknown 均形成可审计 DENY，`max_safe_quantity=0`；缺少系统风险状态按
   `UNKNOWN` 持久化并拒绝。
6. 当前 Unknown Heat 完整进入 Trade Worst-Case Loss；预检不释放、迁移或覆盖账本事实。
7. 七级 Scope 分别比较 planned/stress；任一级超限拒绝人工请求、展示安全数量，最终数量仍为零。
8. 无效止损方向、最小数量/名义规则、leverage、Funding、Margin、保护、分类或证书均不能被其他
   作用域剩余容量覆盖。
9. 风险 decision、command receipt、audit 与 outbox 同事务提交；相同 idempotency key 重放不会
   创建第二份 decision/audit/outbox。
10. `risk_policies`、`risk_decision_snapshots` 与风险状态历史由数据库拒绝 UPDATE/DELETE；policy
    hash 损坏时不产生 ALLOW 快照。
11. 自动风险状态从 NORMAL 逐级收紧时，每个版本形成一条历史；服务与数据库都拒绝反向自动
    恢复。正式收紧命令把状态、历史、audit 与 outbox 原子提交并可幂等重放；两个并发收紧请求
    最终只能停在更严格状态。
12. 风险预检读取风险状态时持有行锁，避免与并发自动收紧拼接出无一致性状态。
13. 每份 decision 均由数据库固定为 `PROPOSAL_PRECHECK`、`execution_eligible=false`、
    `reservation_created=false`；数据库不存在 `risk_reservations` 或 `order_intents` 表。
14. Web actor 直接调用风险处理器被 `INTERNAL_SERVICE_REQUIRED` 拒绝；内部命令仍保存原始
    caller/channel/auth context 供追踪。
