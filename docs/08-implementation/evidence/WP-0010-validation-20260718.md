## 关键证据

1. 唯一新命令为 `execution.fact.record-reconciled.v2`；旧 `execution.fact.record.v1` 返回
   `COMMAND_TYPE_MISMATCH`，不存在兼容回落。
2. v2 request 禁止额外字段，旧 `reconciliation_run_ref` 不能进入新 payload。
3. 新事实保存 contract version、固定 kind、claim/run/input ID 与三类 canonical hash；旧字符串 ref 为 null。
4. claim 必须属于相同 OrderIntent/organization，且保持 SHADOW、external send false、live gate disabled。
5. run 必须与 claim exact scope、lease ID、fencing token 相等，并严格在 claim 后启动。
6. run 必须是该 scope 最新 run、状态 RUNNING、phase 为 COMPARING/ADJUSTING；terminal run 不能接受迟到事实。
7. 递归 supersedes 验证要求结果 run 继承 claim 采用的成功 run，不能接入旧 lease 或旁支历史。
8. input 必须是同一 run 对应来源的 COMPLETE snapshot，source version、input hash 和 event watermark 精确
   匹配；pre-claim event 或超过 run deadline 的记录均失败关闭。
9. VENUE_FILL 只能推进成交状态，VENUE_ORDER 才能证明零成交终态，VENUE_POSITION/PROTECTION 只能推进各自
   状态；错误 kind/source/status 稳定失败关闭。
10. 伪造 claim hash、run hash 或 input ID 分别返回稳定错误，数据库中不产生 ExecutionFact。
11. sender lease 被 fence 后，即使 claim、run 和 input 仍存在，也返回
    `EXECUTION_FACT_SENDER_LEASE_STALE`。
12. 相同 external fact 和完全相同绑定由重新实例化的 service 读取时返回 `ALREADY_RECORDED`，不重复迁移
    OrderIntent/Heat，支持进程重启后的幂等恢复。
13. 相同 OrderIntent sequence 的两个并发事实只有一个落库，另一个因顺序/版本竞争失败；最终仅一条事实。
14. PostgreSQL insert guard 独立拒绝直接插入 `fact_contract_version=1` 的弱事实，证明服务绕过路径关闭。
15. 现有部分成交→Unknown 仍把剩余风险迁入 Unknown；零成交终态仍释放；正成交仍消费 Initial/AddUnit。
16. FILLED→POSITION_RECONCILED→PROTECTION_CONFIRMED 的原有状态与 Heat 守恒链在每一步改用新的结果 run/
    input 后继续通过。
17. 原有 ExecutionFact、OrderIntent、RiskExposure、ledger/history 不可变和 deferred graph guard 全部保持。
18. `trading_execution_fact_bindings_total` 只使用 kind/source/result 固定低基数标签；原状态结果指标保留。
19. 0010 migration 在 PostgreSQL 18.4 完成 upgrade/downgrade/upgrade，Alembic 无 schema drift，readiness
    指向 0010 head。
20. Ruff、Mypy、145 项全量测试和 85% coverage gate 全部通过；最终覆盖率 86.70%。

## 测试数据与证据边界

credential fingerprint、source version、watermark、payload ref、external fact ID 和 hash 均为虚构值。

fixture 生成的七源 `COMPLETE` 不证明真实 collector 处理了分页、断线、限速、场所延迟或私有账户事实。
