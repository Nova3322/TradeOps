## 1. 验证范围

- exact protection 产生 durable `HOLD` target fact；
- missing protection 产生 durable zero target 并原子 `OPEN -> CLOSING`；
- command idempotent replay 与 semantic `NO_CHANGE`；
- zero target 在保护恢复后禁止自动放宽；
- expected target version 冲突；
- database UPDATE/DELETE immutability；
- canonical decision payload 与数值投影往返验证；
- migration、全量回归、branch coverage、静态检查、readiness 和现实能力门。

按用户明确约束，未调用、启用或建议 Codex Security，也未使用任何 Codex Security 审计 Skill、插件或模块。

## 2. 专项验证

```text
tests/integration/test_campaign_target_facts.py

```

confirmed exact protection：

```text
target_version=1
current_quantity=0.5

```

missing protection：

```text
target_version=1

action=EXIT
urgency=IMMEDIATE
reason=PROTECTION_MISSING
reduce_only_required=true
Campaign.status=CLOSING
Campaign.reason_code=TARGET_POSITION_ZERO_RECORDED
```

幂等与单调性：

```text
same command -> ALREADY_PROCESSED, replayed=true, fact_count=1
same semantic evaluation -> NO_CHANGE, object_version=1, fact_count=1
zero target then protection recovers -> CAMPAIGN_TARGET_POSITION_RELAXATION_FORBIDDEN
missing/wrong expected target version -> VERSION_CONFLICT
direct UPDATE -> database trigger rejection
direct INSERT with missing decision payload keys -> database trigger rejection
```

## 3. 数值与 hash 往返

早期专项测试发现 PostgreSQL `NUMERIC(38,18)` 会把 zero target 读回为指数形式；若从列值重新构造原 decision
JSON，会造成文本 hash 不一致。最终合同改为保存完整 canonical decision payload，并让数值、数组、时间和
hash 列成为 insert-guard 验证的投影。数据库往返后的 `target_fact_from_record` 已同时通过：

```text
TargetPositionDecision decision_hash validation
decision payload vs projected columns equality
target_semantic_hash validation
campaign-target-position-fact-v1 record_hash validation
```
