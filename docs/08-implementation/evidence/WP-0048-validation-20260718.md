# WP-0048 验证证据（2026-07-18）

## 1. 验证范围

- 无候选时确定性 HOLD；
- 更小目标与更高紧迫度的独立仲裁；
- zero target 的 EXIT 与固定 reduce-only 合同；
- 输入顺序不变性、hash 自校验；
- 重复、持平、扩仓、position binding 冲突、future/stale 候选失败关闭；
- 全量回归、branch coverage、静态检查、readiness 和现实能力门。

按用户明确约束，未调用、启用或建议 Codex Security，也未使用任何 Codex Security 审计 Skill、插件或模块。

## 2. 专项验证

```text
tests/unit/test_target_position_arbiter.py
4 passed in 0.09s
```

无候选：

```text
current_quantity=1
target_quantity=1
reduction_quantity=0
action=HOLD
requires_order=false
urgency=NONE
reduce_only_required=true
```

独立仲裁：

```text
DYNAMIC_DELEVERAGE: target=0.2, urgency=ORDERLY
SYSTEM_RISK_REDUCTION: target=0.5, urgency=IMMEDIATE

decision target=0.2
decision urgency=IMMEDIATE
reduction_quantity=0.8
action=REDUCE
```

输入顺序反转得到相同 decision hash。HARD_STOP 的 zero target 得到 `EXIT`；篡改为扩仓或
`reduce_only_required=false` 被模型自校验拒绝。

失败场景：

```text
duplicate source ref / binding mismatch / target >= current
  -> TARGET_POSITION_CANDIDATE_CONFLICT

future-dated or expired candidate
  -> TARGET_POSITION_CANDIDATE_STALE

current_quantity <= 0
  -> TARGET_POSITION_CURRENT_POSITION_INVALID
```

## 5. 结果判定

1. 多个减仓/退出来源现在共享一个无状态、确定性的目标仓位仲裁合同。
2. 更小目标与更高紧迫度分别取最安全结果，不依赖候选输入顺序。
3. 仲裁器不能扩仓，不能把无效候选降级为 HOLD，并固定要求后续订单为 reduce-only。
4. 本包不是退出执行链；candidate producers、durable target、OrderIntent 和真实场所认证仍未完成。
