### 2.2 Catalog 注册与完整性

测试确认：

- 只有 `instrument-catalog-service` 的 INTERNAL 命令可注册；
- 同一幂等命令重放为 `ALREADY_PROCESSED`，只产生一行、一个 audit 和一个 outbox event；
- record/evidence hash 错误在写入前被拒绝；
- risk cluster/evidence 必须 canonical sorted unique；
- 直接 `UPDATE` 返回 `instrument_catalog_records is immutable`；
- exact identity/catalog/classification version 不能重复。

### 2.3 Fail-closed classification

专项测试覆盖：

```text
missing exact record       -> INSTRUMENT_CATALOG_RECORD_NOT_FOUND
expired record             -> INSTRUMENT_CATALOG_OUTSIDE_VALID_WINDOW
bad record hash            -> INSTRUMENT_CATALOG_INTEGRITY_FAILED
discoverable=false         -> INSTRUMENT_NOT_DISCOVERABLE
classification incomplete -> INSTRUMENT_CLASSIFICATION_INCOMPLETE
UNCLASSIFIED sector        -> INSTRUMENT_SECTOR_UNCLASSIFIED
binding mismatch           -> INSTRUMENT_CLASSIFICATION_SCOPE_MISMATCH
multiple risk clusters     -> MULTI_CLUSTER_RISK_SCOPE_UNSUPPORTED
```

Catalog validator 保留详细原因；Risk Engine 在 proposal 与 final precheck 均转换为耐久
`INSTRUMENT_UNCLASSIFIED` DENY，数量为零、有效期等于 decision time，不创建 OrderIntent 或 Reservation。
ALLOW 决策的 `valid_until` 另由 Catalog validity 收紧。

### 2.4 决策绑定

ALLOW 集成场景断言：

- Risk/Execution decision 的 record ID、catalog/classification version 和 record hash 与 Catalog 行一致；
- composite FK 指向不可变 exact Catalog 记录；
- input snapshot 保存 validator snapshot，decision 保存 ID/hash/evidence/reason；
- proposal 和 final precheck 都不再读取 caller classification boolean。

## 5. 结果判定

1. 调用方不再能以布尔值声称标的已分类；v5 和旧字段均失败关闭。
2. Proposal/final precheck 从同一不可变 exact Catalog 事实独立验证分类与冻结 binding。
3. missing、过期、篡改、不完整、UNCLASSIFIED、mismatch 和多 cluster 均不能增加风险。
4. Catalog 记录与决策绑定可复算、可审计、不可原地改写，迁移不会静默删除历史事实。
5. 本包不构成真实发现、`eligible_to_trade` 或实盘能力；三项现实能力门继续为 `DISABLED`。
