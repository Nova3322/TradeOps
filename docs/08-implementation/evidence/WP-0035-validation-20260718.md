### 2.2 集合注册、完整性与不可变性

专项测试确认：

- 只有 `risk-fact-aggregator-service` 的 INTERNAL 命令可注册；
- 同一幂等命令重放为 `ALREADY_PROCESSED`，只产生一行、一个 audit 和一个 outbox event；
- record/evidence hash 错误、九类事实缺失、重复或非 canonical 顺序在写入前被拒绝；
- SHADOW-only、`real_funds_eligible=false` 由模型与数据库双重限制；
- 直接 `UPDATE` 返回 `risk_fact_sets is immutable`；
- exact scope/version 唯一，决策 composite FK 不能指向不存在的集合。

### 2.3 Fail-closed Fact Set

专项测试覆盖：

```text
missing exact set             -> RISK_FACT_SET_RECORD_NOT_FOUND
outside validity window       -> RISK_FACT_SET_OUTSIDE_VALID_WINDOW
bad record/evidence contract  -> RISK_FACT_SET_INTEGRITY_FAILED
latest invalid over older OK  -> no fallback to older set
UNKNOWN observation           -> FACTS_UNKNOWN
stale observation             -> FACTS_STALE
future timestamp              -> FACT_TIMESTAMP_IN_FUTURE
inconsistent event window     -> FACTS_INCONSISTENT
```

Fact Set Validator 保留详细原因；Risk Engine 在 proposal/final precheck 转换为
`RISK_FACT_SET_UNAVAILABLE` DENY，数量为零、有效期等于 decision time。最终预检缺失集合时不创建
OrderIntent 或 Reservation。ALLOW 的 `valid_until` 由 exact set validity 和逐事实 freshness 进一步收紧。

### 2.4 决策与并发绑定

ALLOW 集成场景断言：

- Risk/Execution decision 的 Fact Set ID/version/hash 与集合行一致；
- composite FK 指向 immutable exact set；
- input snapshot、decision、audit/outbox 保存 validator snapshot、ID/hash/evidence/reason；
- proposal 与 final precheck 均不再读取 caller observations；
- register 与两条预检链共用 exact-scope advisory transaction lock，final precheck 另锁定选中行。

## 5. 结果判定

1. 调用方不再能提交九类事实状态/时间/hash；v7 和旧 `facts` 均失败关闭。
2. Proposal/final precheck 从服务端最新 immutable exact set 独立解析完整九类 observation。
3. missing、过期、篡改、Unknown、陈旧、未来或不一致事实均不能增加风险。
4. 集合与决策绑定可复算、不可原地改写，最新无效集合不会回退旧健康集合。
5. 本包不构成真实 collector、真实事实认证或实盘能力；三项现实能力门继续为 `DISABLED`。
