## 已验证的关键行为

1. original run/claim 相同 lease/token 时继续派生 `ORIGINAL_LEASE`。
2. 原 run 完成后 fence 旧 lease，reacquire 取得更高 token，successor run 可沿 supersedes lineage 绑定原 claim。
3. successor run 使用自己的 current lease/token 和 exact COMPLETE input 追加迟到部分成交，结果派生
   `SUCCESSOR_LEASE`。
4. PostgreSQL insert guard 接受合法 successor graph，不要求复用已失效旧 lease。
5. 原 terminal run 在新 token 接管后仍不能复用；没有 successor run 时旧事实入口保持关闭。
6. current sender state、run lease/token、latest run、phase、deadline、lineage、input 和 route 仍全部强制。
7. successor 不创建第二条 ShadowDispatchClaim，不修改 client order identity，不产生外部发送权限。
8. 相同事实重启读取时 authority mode 从 immutable claim/run 关系重新派生，不重复迁移 Heat。
9. 0011 downgrade 恢复 same-lease-only guard，upgrade 恢复 successor guard；表和既有事实不丢失。
10. Ruff、Mypy、147 项全量测试和 85% coverage gate 全部通过；最终覆盖率 86.72%。
