## 关键证据

1. run root 精确绑定 organization、sender scope、current lease ID/token、SHADOW environment、trigger、
   observation window、deadline、固定七源 manifest 和 canonical hash；root 不可更新或删除。
2. start 会重新执行 WP-0008 current lease、owner/config/fingerprint、expiry 和 live gate 验证；旧 lease/token
   不能启动新 run。
3. 同一 exact scope 两个并发 start 只有一个 `COMPLETED`，另一个稳定返回
   `RECONCILIATION_ALREADY_RUNNING`。
4. 同 scope 后续 run 必须显式 supersede 最新终态；缺失链头返回
   `RECONCILIATION_SUPERSEDES_REQUIRED`，数据库 insert trigger 独立验证相同规则。
5. 七类 input 各最多一条，保存 COMPLETE/UNKNOWN、source version、水位、覆盖窗口、payload/evidence hash；
   重复源、未来观察和不覆盖冻结窗口均失败关闭。
6. 版本错误与乱序命令返回 `VERSION_CONFLICT`；COLLECTING 不能跳到 ADJUSTING，phase 不能回退或跳级。
7. 缺少任一源或存在 UNKNOWN input 时不能进入 COMPARING/SUCCEEDED；UNKNOWN 可以保存为不可逆安全终态，
   后续 input 被 `RECONCILIATION_RUN_TERMINAL` 阻断。
8. 七源完整后只能按 COLLECTING→COMPARING→ADJUSTING 前进；每次 state 变化写 append-only history。
9. BLOCKING Finding 使 success 返回 `RECONCILIATION_BLOCKING_FINDINGS_OPEN`；COMPARING 不能提前关闭，
   ADJUSTING 追加 `RESOLVED_SAFE` 证据后 unresolved count 才归零。
10. Finding 和 Resolution root 均不可变；数据库 deferred graph guard 重新计算 input/Finding/unresolved counts，
    直接伪造 progress count 在 commit 时被拒绝。
11. deadline 到期后不能 SUCCEEDED，但同一 run 可以进入 FAILED 安全终态；FAILED/UNKNOWN 都不产生 claim。
12. SUCCEEDED result 保存完整 input/finding hash manifest、terminal binding、
    `no_historical_replay=true` 和 `external_send_permitted=false`。
13. 服务与数据库都要求 SUCCEEDED 时相同 lease/token 仍为 current authority；fence/reacquire 后旧 run 不能
    绑定新 token。
14. 没有 run 的 claim 返回 `RECONCILIATION_SUCCESS_REQUIRED`；成功 run 精确绑定后才允许创建
    non-dispatchable ShadowDispatchClaim。
15. 同一 lease 新 run 启动或终结为 UNKNOWN 后，旧 SUCCEEDED 不再是 latest，不能继续 claim；不存在“曾经
    成功即可永久复用”的窗口。
16. claim 保存 reconciliation run ID/result hash，服务重算 root/result hash；数据库 trigger 再次验证 latest
    run、terminal result 和 WP-0008 sender/intent/certificate/live-gate graph。
17. claim 后 OrderIntent 仍为 `INTENT_CREATED`；没有 VenueOrder、Fill、网络调用、外部发送或历史业务重放。
18. 相同 command 重放返回 `ALREADY_PROCESSED`；新 command 不会覆盖旧 input、Finding、Resolution 或终态。
19. 0009 migration 在 PostgreSQL 18.4 完成 upgrade/downgrade/upgrade；降级恢复 WP-0008 claim guard，
    再升级恢复 latest-success guard，Alembic 无 schema drift。
20. Ruff、Mypy、135 项全量测试与 85% coverage gate 全部通过，覆盖率 86.50%。

## 测试数据与证据边界

测试使用虚构的 Binance execution domain、account、worker、credential fingerprint、source versions、
watermarks、payload refs 和 evidence hashes。没有连接 Freqtrade、Binance、Hyperliquid、私有账户流或任何
真实订单接口。

固定七源只是 SHADOW 对账输入合同；测试中的 COMPLETE 由 fixture 生成，不能替代真实 collector 对分页、
限速、查询窗口、场所 eventual consistency 和证据持久化的认证。
