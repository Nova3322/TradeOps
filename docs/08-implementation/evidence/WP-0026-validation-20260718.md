# WP-0026 验证证据（2026-07-18）

## 1. 验证范围

- LONG/SHORT base Heat 的服务端规范计算；
- certified binding 与 market contract multiplier 精确一致；
- 固定损失模型版本；
- v1 自报 base/scope planned 字段拒绝；
- proposal/final 命令 v2 与 schema version 2 强制；
- 同一个 incremental worst-case loss 进入 trade limit、authorization、reservation、Ledger 和七层 scope；
- requested scope stress 不得低于 canonical planned loss；
- 决策 JSON 保存三项新增损失证据；
- `NUMERIC(38,18)` 比例分配和分量总和守恒；
- 部分成交、加仓、零成交释放、Unknown 和 durable exposure 回归；
- 格式、lint、strict Mypy、全量测试与覆盖率门。

按用户特别约束，未调用 Codex Security 或任何 Codex Security 审计 Skill、插件、模块。

## 4. 定点比例回归

原始失败证据：

```text

result = DURABLE_EXPOSURE_INPUT_MISMATCH
```

改为 18 位定点分配后，完整 reservation、部分成交与 add 路径均恢复精确守恒。giveback/cost 向下取整，
余量由 base Heat 吸收；base 在 Open/Reserved/Unknown bucket 间的最后一个非零 bucket 吸收分配余量。

## 6. 结果判定

1. 调用方不再能直接提供 base Heat 或七层 scope planned loss。
2. base Heat 由一个版本化公式计算，并由同一结果驱动 trade、authorization、reservation、Ledger 和 scope。
3. durable component 在 18 位定点精度下严格守恒，不因循环小数误拒绝合法当前暴露。
4. giveback、cost 与 scope stress 的 canonical 事实来源尚未关闭，现实资金能力继续关闭。
