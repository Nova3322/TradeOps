## 已验证的关键行为

1. internal reconciliation service 只能在 latest、RUNNING、COLLECTING、未过期 SHADOW run 和 current lease 下调用
   `execution.venue-position-snapshot.record.v1`。
2. VenuePositionSnapshot 绑定 organization、venue、execution domain、account、instrument、position mode/side、
   margin mode、collateral pool 和 venue update identity；跨 scope fact 稳定拒绝。
3. ONE_WAY 只接受 BOTH side，并独立保存 LONG/SHORT/FLAT/UNKNOWN direction；HEDGE LONG 与 SHORT line 可在同一
   update identity 下独立存在，OPEN direction 必须与 position side 一致。
4. OPEN 强制正 quantity/entry/mark、精确 `quantity × mark × multiplier` notional 和已知 UPNL；可选 liquidation、
   leverage、initial/maintenance margin 出现时满足各自数值约束。
5. FLAT 明确保存 quantity/notional/UPNL 为零且不伪造 entry/liquidation/leverage；UNKNOWN 的数量、价格、notional、
   UPNL、保证金和清算事实全部为空，不会被当成零仓。
6. snapshot hash 和 evidence hash 受模型验证；改 quantity 而不重建 canonical evidence 返回
   `VENUE_POSITION_SNAPSHOT_INVALID`，不留下 fact/link。
7. 同一 external update 在后续 ReconciliationRun 复用原 canonical fact，只创建新 input membership；不同经济语义
   复用同一 identity 返回 `VENUE_POSITION_SNAPSHOT_CONFLICT`。
8. 每个 input 的 position link 数必须精确等于 frozen item count：缺失时不能进入 COMPARING，超量 normalization 在
   新 fact insert 前拒绝，不产生孤立记录。
9. PostgreSQL deferred manifest guard 阻断直接更新 run phase 绕过 position count；first-link guard 回滚无 exact
   immutable first link 的直接 position insert。
10. VenuePositionSnapshot 与 input link 的 UPDATE/DELETE 被 immutable trigger 阻断；wrong source/fact one-of 和重复
    membership 由数据库 check/FK/unique 约束阻断。
11. 既有 order/fill normalization、ExecutionFact v3、successor lease 和 reconciliation 路径完成 41 项定向回归，
    position 扩展未破坏 WP-0012/0013 合同。
12. `0014 -> 0013 -> 0014` 在 PostgreSQL 18.4 实际往返成功；回升后 metadata 无 drift、readiness 为真，三项现实
    capability gate 保持 DISABLED，position fact/link 表均无测试残留。
13. Ruff、strict Mypy、171 项全量测试和 85% coverage gate 全部通过；最终覆盖率为 86.77%。

测试只使用 disposable PostgreSQL、虚构 sender scope、lease、reconciliation input、position update 和本地 SHADOW
时间；没有连接 Freqtrade、Binance、Hyperliquid、私有 stream、REST backfill 或任何真实账户。WP-0014 没有让
VenuePositionSnapshot 驱动 `POSITION_RECONCILED`，没有创建 current Position Projection，也没有计算组合 MTM、PnL、
保护覆盖或保证金动作。本证据不能激活真实订单、Add、资金划转或任何场所/账户/标的的现实能力。
