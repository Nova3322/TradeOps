### 2.2 ADD canonical 保护风险

数据库集成场景使用同一 current position/protection source snapshot：

```text
position entry / Mark          = 100.5 / 120
protection trigger             = 110
quantity / multiplier          = 0.5 / 1
settlement currency            = USD (test-only exact scope)
current-to-protection loss     = 5
canonical Open Heat            = 0
canonical Giveback             = 5
active durable cost            = 0.1608
current Trade Loss             = 5.1608
```

旧 durable campaign Open Heat 为 5.25、Giveback 为 0，因此：

```text
replacement delta = 5 - 5.25 = -0.25
scope planned      = 5.4108 - 0.25 = 5.1608
scope stress       = 45.25 - 0.25 = 45
```

七层 scope 均断言上述 planned/stress 值。ADD decision 的 calculation hash 精确等于 canonical projection
hash；position/protection source refs 与 hashes 写入不可变 input snapshot。篡改 AddEligibility protection
snapshot hash 返回 `ADD_ELIGIBILITY_CANONICAL_FACT_MISMATCH`，未创建新意图或预留。

新 ADD 增量只包含：

```text
base Heat + cost stress
```

新 Reservation 的 `protected_profit_giveback_reserved=0`，current Giveback 不再作为新增动作重复冻结。

## 4. 结果判定

1. 调用方不能再提交新增 giveback；v3 命令和旧字段均被拒绝。
2. ADD 只有在 current position/protection、Mark、数量、币种和资格证据完全一致且 fresh 时才进入最终预检。
3. current Open Heat/Giveback 替换旧战役估算并同步调整所有 scope planned/stress，避免单仓与聚合风险口径分裂。
4. 当前仓位风险与新增动作风险分开记账，新 Reservation 不再重复冻结 current Giveback。
5. 持续风险监控、退出仲裁、requested scope stress 规范派生和真实场所事实仍未完成；本包不构成实盘
   能力，三项现实能力门仍为 `DISABLED`。
