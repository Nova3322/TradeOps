## 关键证据

1. 迁移后四张证书/证据表均为零行，不 seed 任何资格事实；`AUTO_ADD`、`CAPITAL_TRANSFER`、
   `LIVE_ORDER_SEND` 全部保持 `DISABLED`。
2. 数据库硬约束只允许 `environment=SHADOW` 且 `real_funds_eligible=false`；代码不存在 production 或
   small-live 签发命令。
3. SHADOW 签发原子创建 immutable evidence bundle、exact-scope certificate root、ACTIVE current state、
   初始 state history、command receipt、audit 和 outbox。
4. 证书精确绑定 Proposal 来源、策略、venue/domain/account、position/margin/collateral、instrument/
   multiplier/underlying/sector/risk cluster、方向、risk tier、Add count、settlement、worker/config hash、
   非秘密 credential fingerprint，以及全部策略/风险/Catalog/Adapter/client/whitelist 版本。
5. scope、policy versions、evidence bundle 和整张 certificate 都保存 canonical hash；数据库直接更新或
   删除 root/evidence/history 会被 trigger 拒绝。
6. Risk request 已没有 `capability_certificate_valid` 字段；提交旧布尔声明因 `extra=forbid` 直接拒绝，
   pure evaluator 只消费 Trading 派生的 `CapabilityValidationResult`。
7. Proposal precheck 引用不存在的证书时形成持久 DENY，主原因 `CAPABILITY_CERTIFICATE_INVALID`，具体
   `CAPABILITY_CERTIFICATE_NOT_FOUND` 保存于 immutable input snapshot；不产生执行副作用。
8. 有效证书在 TradingAuthorization 签发前重新加锁校验。证书未持久化时即使 Proposal 和人工 Approval
   完整，也不创建 Authorization、Campaign、Initial 或 Add 行。
9. final ORDER_PRECHECK 再次校验证书；scope/version/instrument multiplier、当前订单名义价值、交易损失
   和证书有效期都进入最终资格与最短 `valid_until`。数据库另行拒绝 OrderIntent 使用与其
   TradingAuthorization 不同的证书引用。
10. 独立 validator 用例证明 account scope、Adapter version、notional limit、loss limit、expiry 和 missing
    certificate 各自稳定失败关闭，且原因可机器判定。
11. `ACTIVE -> SUSPENDED` 与现有 Initial=`ACTIVE`、Add package=`DORMANT`、AddUnit=`AVAILABLE` 的
    `INVALIDATED` 传播在同一事务完成；结果计数分别为 1/1/1，旧授权不可恢复。
12. 使用同一精确 scope、以 `supersedes` 引用暂停证书签发新证书后，新证书为 ACTIVE，旧证书仍暂停，
    旧 Initial/Add 仍 INVALIDATED，不会复活 Proposal 或 Authorization。
13. 在证书到期前执行 EXPIRE 返回 `CAPABILITY_CERTIFICATE_NOT_EXPIRED`；时间边界到达后状态单向进入
    EXPIRED，state history 从 1 增至 2，真实资金资格仍为 false。
14. 直接尝试把 SUSPENDED current state 改回 ACTIVE 被数据库状态机拒绝。
15. 两个不同命令并发签发同一 certificate ID 时，advisory transaction lock 保证一条 COMPLETED、一条
    `CAPABILITY_CERTIFICATE_ALREADY_EXISTS`，数据库只有一张 root、一个 evidence bundle 和一条初始
    history。
16. 新签发与收紧命令均限制为固定 `capability-certification-service` INTERNAL/SYSTEM principal；worker
    不得签发或批准自己，issuer 不得自批。
