## 关键证据

1. 低/中风险一票、高风险两名不同 Reviewer 达到 quorum 后才可签发；签发快照保存 ApprovalDecision
   与每张批准 vote 的身份、IAM 决定、认证上下文、政策版本及冻结 hash。
2. Review 完成仍不会隐式创建授权；只有固定 internal service principal 可以调用独立签发命令。
3. 相同 proposal 的两个不同幂等命令并发执行，只产生一个 authorization、一个 Campaign 和一个
   Initial；后到命令返回相同权威身份。相同幂等键重放不产生第二份事实。
4. 每份授权由数据库固定为 SHADOW 且 `execution_eligible=false`；返回值明确
   `risk_reservation_created=false`、`order_intent_created=false`。
5. 数据库不存在 `risk_reservations` 或 `order_intents` 表；签发没有执行副作用。
6. Campaign 初态为 PENDING_ENTRY；授权过期不伪造 OPEN/CLOSED、真实仓位或对账完成。
7. Initial 数量等于 risk-approved quantity；价格上下界由冻结参考价和滑点生成；账户抽象、margin
   mode、collateral scope/pool、Instrument、方向和模板版本均被复制为不可变事实。
8. 1R 的 0.5% 公式、低/中/高 1/2/3R 档位公式和授权容量不超过冻结上限由数据库再次约束。
9. 高风险 Add=3 产生唯一 DORMANT package 和三个 AVAILABLE unit；数据库固定序号对应
   30%/50%/100%。低/中/高最大个数继续受 proposal 与 authorization 双重约束。
10. NO_PYRAMID 签发保留 Initial ACTIVE，但 Add package/unit 从创建即 INVALIDATED；重复同步不会
    增加版本或复活。NO_NEW_POSITION、REDUCE_ONLY、KILL_SWITCH 和 UNKNOWN 均拒绝新签发。
11. 已签发后同步 NO_NEW_POSITION 会同时 INVALIDATE 未消费 Initial、package 和 unit；REVOKE_ADD
    只撤销 Add，仍有效 Initial 保持 ACTIVE。
12. 注入时钟证明提前 EXPIRE 被拒绝，越过冻结有效期后仍可消费 Initial/Add 统一 EXPIRED。
13. 根、Campaign、Initial/Add spec、unit 和状态历史均拒绝 UPDATE/DELETE；数据库拒绝非法状态跳转
    与终态恢复 ACTIVE。
14. 每个初始/后续状态变化由触发器写入追加历史；服务命令仍产生同事务 audit 与 outbox。
15. 在授权根、Campaign 和 Initial 已显式 flush 后注入 Add 持久化故障，整个事务回滚：根、子事实、
    command receipt、audit 和 outbox 均为零，证明没有半签发状态。
16. 冻结 spec 缺少/破坏必需的证书或运行绑定时，即使人工批准已完成也以稳定原因码失败关闭。
17. 第二次签发若携带与既有根不同的 approval/hash 绑定会被拒绝；数据库组合外键也会拒绝把一份
    ApprovalDecision 与另一个 proposal version 拼接成 authorization。
18. `AUTO_ADD`、`CAPITAL_TRANSFER`、`LIVE_ORDER_SEND` 在新库升级和迁移往返后均为 DISABLED。
