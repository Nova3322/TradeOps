## 3. 结果判定

1. `PROTECTION_CONFIRMED` 只能由与既有 canonical position 完全同一仓位的
   `CONFIRMED` protection snapshot 推进。
2. protection request 的 canonical ID、input membership、hash、coverage、time 与 payload 均不可
   由调用方自报或改写。
3. application path、PostgreSQL direct-write path 和 successor recovery path 使用同一失败关闭边界。
4. `COMPLETED` 暂无新事实来源，避免把保护存在误当成整个执行生命周期已完成。
5. 所有 live capability gates 仍为 `DISABLED`；本工作包不构成实盘保护认证或实盘就绪证明。
