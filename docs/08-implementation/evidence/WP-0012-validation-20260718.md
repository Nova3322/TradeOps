## 已验证的关键行为

1. private venue order update 按 organization/venue/domain/account/order/update identity 生成不可变
   `VenueOrderObservation`，OPEN 与 REJECTED zero-fill 数量语义受模型和数据库共同约束。
2. private venue trade 按 organization/venue/domain/account/trade identity 生成唯一 `VenueFill`；quantity、price、multiplier、
   notional、side、reduce-only、费用和 event time 全部冻结。
3. CHARGE、REBATE、ZERO 三类费用符号分别为正、负、零；乱序成交按原 event time 独立保留。
4. 同一 trade 在后续 reconciliation run 复用一条 canonical fill，只新增该 frozen input 的 immutable link。
5. 同一 trade identity 复用不同价格/经济语义返回 `VENUE_FILL_CONFLICT`，原事实与 link 不变。
6. VenueOrder/VenueFill link 数少于 frozen input `item_count` 时，服务返回
   `RECONCILIATION_NORMALIZED_FACT_COUNT_MISMATCH`；补齐后才能进入 `COMPARING`。
7. 超过 frozen count 的新 fact 在任何 insert 前被拒绝，事务不会留下孤立 canonical fact。
8. wrong source/input binding 和非 reconciliation service principal 都稳定拒绝。
9. PostgreSQL deferred guard 阻断直接插入无 first link 的 canonical fact，并在提交时回滚；直接数据库推进
   缺事实的 run 也被 exact-count guard 阻断。
10. canonical facts 和 memberships 的 UPDATE/DELETE 由数据库 immutable trigger 阻断。
11. 0012 downgrade 删除新增对象并恢复 0011，upgrade 可重建 0012；metadata 无 drift，readiness 恢复正常。
12. Ruff、strict Mypy、155 项全量测试和 85% coverage gate 全部通过；最终覆盖率 86.40%。
