### 2.2 Canonical payload

测试确认：

- hash 覆盖 Mark、Index、可成交价、乘数、tick、最小数量/名义、资金费和规则版本；
- Decimal 等值不同 scale 产生相同 hash；
- direction、invalidation、slippage 与 loss-model 元数据不混入 MARKET payload；
- 测试 Risk Fact aggregator 对每个 Fact Set 的 MARKET observation 写入 exact payload hash。

### 2.3 Fail-closed binding

```text
valid set + KNOWN + matching hash    -> continues normal risk evaluation
valid set + KNOWN + mismatched hash  -> MARKET_FACT_BINDING_MISMATCH
valid set + UNKNOWN                  -> FACTS_UNKNOWN
invalid/missing set                  -> RISK_FACT_SET_UNAVAILABLE
stale MARKET                         -> FACTS_STALE
```

Proposal mismatch 产生 immutable DENY decision。Final ORDER_PRECHECK mismatch 同样 DENY，数量为零，并断言
`OrderIntent=0`、`RiskReservation=0`。ALLOW 与 DENY 的 decision/outcome/audit/outbox 均保留计算 hash 和
observation hash。

## 5. 结果判定

1. v9 proposal/final risk 不再接受与最新 KNOWN MARKET observation 内容不同的市场/规则输入。
2. Decimal canonicalization 避免仅因数值 scale 不同产生假漂移。
3. UNKNOWN、stale、invalid set 与 mismatch 保持独立、稳定的失败关闭原因。
4. 决策可同时展示计算 hash 与 observation hash，最终 mismatch 没有订单或风险预留副作用。
5. 本包不构成真实行情采集、场所认证或实盘能力；三项现实能力门继续为 `DISABLED`。
