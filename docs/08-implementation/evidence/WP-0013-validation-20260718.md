## 已验证的关键行为

1. 唯一新写命令为 `execution.fact.record-reconciled.v3`，新事实固定使用
   `fact_contract_version=3`；v1/v2 命令和直接数据库新写全部关闭，历史行保持只读。
2. `VENUE_ORDER` 必须引用 exact VenueOrderObservation 和 input link，`VENUE_FILL` 必须引用 exact
   VenueFill 和 input link；非 order/fill v3 事实不能携带 canonical refs。
3. organization、venue、execution domain、account、instrument、client order ID、side、position side 与
   reduce-only 均与 immutable claim、sender scope 和 frozen OrderIntent 完全匹配；order observation 还验证
   order type、time-in-force 和 original quantity。
4. canonical fact hash、link fact hash、run/input/source/input hash、raw payload/evidence refs、event/received time
   与命令投影完全一致，伪造 hash、link、external fact ID、数量或 payload 均稳定拒绝。
5. VenueFill 只提供本次成交增量；状态机从当前累计量推导 PARTIALLY_FILLED/FILLED 与 remaining，超过 frozen
   intent quantity 的 fill 被拒绝，状态与风险桶保持不变。
6. VenueOrderObservation 不能制造新成交；其累计量必须等于已消费 canonical fills。OPEN、CANCEL_PENDING、
   CANCELLED/EXPIRED zero/partial、REJECTED 和 UNKNOWN 按固定表映射，PARTIALLY_FILLED/FILLED observation
   不能替代 individual fills。
7. 已验证 `0.2` canonical fill 后，以同一 venue order ID 的 terminal cancel 产生
   `CANCELLED_PARTIAL`，保留 `0.2` open quantity 并释放剩余 `0.3` reserved quantity。
8. 同一 canonical order、fill 或 input link 只能消费一次；相同幂等命令返回原 ExecutionFact，不再次迁移
   Heat/Funding/Margin，改变序号或语义形成 identity conflict。
9. 同一 OrderIntent 的 canonical venue order ID 不能在后续 fill、cancel 或 unknown 中切换；wrong ownership、
   missing observed client ID 和 successor 使用错误 order ID 均被拒绝。
10. current successor lease 仍须通过 WP-0011 的连续 supersedes lineage，只能收敛迟到 canonical fact，不能
    改写原 claim、重发订单或取得额外发送权限。
11. PostgreSQL insert guard 独立复核 v3 fact、claim/run/input/current lease、canonical ownership、payload、
    status 与数量；deferred application guard 会回滚未在同一事务精确更新 OrderIntentState 和
    RiskExposureState 的直接插入。
12. 数据库约束阻断 missing canonical refs、forged quantities、重复 canonical fact/link 和旧合同直接插入；
    服务拒绝路径不留下 ExecutionFact、状态、风险账本、history、audit 或 outbox 部分写入。
13. 新增指标 `trading_execution_canonical_fact_bindings_total{fact_type,result}`，维度只接受
    VENUE_ORDER/VENUE_FILL 与 APPLIED/REPLAYED/REJECTED；稳定错误码覆盖 reference、link、ownership、
    quantity、semantics、unsupported status 和 order identity。
14. `0013 -> 0012 -> 0013` 在 PostgreSQL 18.4 实际往返成功，回升后 metadata 无 drift、readiness 恢复，
    三项现实 capability gate 仍全部关闭，数据库中无残留 v3 测试事实。
15. Ruff、strict Mypy、166 项全量测试和 85% coverage gate 全部通过；最终覆盖率为 86.56%。
