## 关键证据

1. scope 精确绑定 organization、venue/domain/account、account abstraction、position mode、margin mode、
   collateral scope/pool；完整字段唯一约束阻断平行 authority。
2. scope、lease 和 claim 都只能保存 `SHADOW` 且 live/external dispatch 为 false；数据库中
   `LIVE_ORDER_SEND`、`AUTO_ADD`、`CAPITAL_TRANSFER` 继续为 `DISABLED`。
3. acquire 原子创建 immutable scope、immutable lease、current state、初始 append-only history、command
   receipt、audit 和 outbox；相同 command 重放只返回原结果，不创建第二份事实。
4. 两个不同 worker 并发 acquire 同一 exact scope 时只有一个 `COMPLETED`；另一个稳定拒绝，数据库只有
   一个 scope、一个 lease 和 token 1。
5. renew 只延长 current lease expiry，version 前进而 token 不变；DB trigger 阻断同 lease 缩短 expiry、
   换 token 或非单调版本。
6. 显式 FENCE 把 state 置为 `FENCED`、清空 active lease 并把 token 从 1 推进到 2；旧 lease validator
   立即返回 inactive。
7. fence 后新 lease acquire 得到 token 3 而非复用 1/2；旧 owner 即使提交当前 state version 也不能续租。
   current owner 主动 RELEASE 后 token 再前进到 4，active lease 被清除。
8. worker clock 比 authority time 偏移 6 秒时 acquire 返回 `WORKER_CLOCK_SKEW_EXCEEDED`，不产生 scope
   或 lease root。
9. expiry 到达前执行 EXPIRE 返回 `SENDER_LEASE_NOT_EXPIRED`；边界到达后清除 owner、token 前进且不能
   恢复旧 lease。
10. claim 前把 `LIVE_ORDER_SEND` 改为 `SHADOW` 时服务稳定返回
    `LIVE_ORDER_SEND_NOT_DISABLED`；恢复为 `DISABLED` 后才允许 non-dispatchable claim。
11. claim 同时重校 current lease、OrderIntent state/version/window、exact route、worker/config/fingerprint、
    ACTIVE SHADOW CapabilityCertificate、notional/loss limit 和 live gate。
12. 成功 claim 保存确定性 client order identity、scope/lease/certificate/intent hash、reason code、worker
    observation 与 expiry；结果明确 `external_send_permitted=false`。
13. claim 后 OrderIntent 仍为 `INTENT_CREATED`，不存在 `DISPATCHING`、VenueOrder、Fill 或外部副作用。
14. 同一 command 重放返回 `ALREADY_PROCESSED`；使用新 command 再 claim 同一 OrderIntent 返回
    `ORDER_INTENT_ALREADY_CLAIMED`，数据库始终只有一条 claim。
15. 数据库直接更新 scope、lease、history 或 claim 被 immutable trigger 拒绝；直接回退 current token 被
    monotonic state trigger 拒绝。
16. 数据库直接插入 forged owner claim 被 current fenced graph trigger 拒绝；跨 scope service claim 也被
    阻断，不产生 claim，scope/lease/current token 使用复合外键保持绑定。
17. 0008 migration 在 PostgreSQL 18.4 完成 upgrade/downgrade/upgrade；Alembic 无 schema drift。
18. Ruff、Mypy、126 项全量测试与 85% coverage gate 全部通过。
19. 回滚再升级后 sender scope、lease 与 claim 均为零行，三项 capability gate 均为 `DISABLED`，
    readiness 返回 `(True, None)`。

测试使用虚构的 Binance execution domain、account、worker、config hash、credential fingerprint、
reconciliation ref、risk-state ref 和 CapabilityCertificate。没有连接 Freqtrade、Binance、Hyperliquid、
私有账户流或任何真实订单接口。

不是已冻结的生产 SLO、接管窗口或真实认证参数。
