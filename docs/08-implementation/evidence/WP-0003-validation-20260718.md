## 关键证据

1. 低/中风险一名独立 Reviewer 可形成审核 `APPROVED`；高风险第一票保持 `PENDING`，第二名独立 Reviewer 才终结。
2. 两个高风险 Reviewer 并发投票时保留两份不可变 vote、一个 `ApprovalDecision`、一个终态，决定版本为 2。
3. MANUAL 创建者自审被拒绝；SYSTEM 策略服务不能成为人类审核者，但合格人类 Reviewer 可审核该版本。
4. `NO_NEW_POSITION` 覆盖 Reviewer 权限并阻止 vote。
5. `REJECT` / `RETURN` 立即形成保守终态；终态后的迟到赞成票不产生第二 vote。
6. 同一 Reviewer 不能把已记录的赞成票改成拒绝票。
7. 过期提案形成 `EXPIRED` 决定，不记录 vote。
8. Telegram 批准缺少动作级认证返回 `MFA_REQUIRED`；绑定 Telegram 渠道、设备、动作和版本的 Passkey/WebAuthn 证据才允许 vote。
9. 数据库拒绝错误的 1R/档位亏损上限公式；服务拒绝 JSON 快照与冻结 hash 不一致的提案。
10. `proposal_versions`、`reviewer_votes` 和终态 `approval_decisions` 的篡改/删除被数据库触发器拒绝。
11. 纯授权判定不会写入 vote；审核 `APPROVED` 也不会创建 `trading_authorizations`。
12. WP-0001/0002 既有测试继续通过，三项真实能力仍为 `DISABLED`。
