# WP-0032 验证证据（2026-07-18）

## 1. 验证范围

- v5 RiskPrecheck / ExecutionIntent 命令与 payload schema；
- v1 至 v4 命令和旧 caller scope-stress 字段显式拒绝；
- Risk Policy 每个 scope 必须有版本化 stress scenario 和非空来源；
- gap、liquidity degradation、unprotected window 三项从同一 canonical requested notional 派生；
- planned/stress 分别比较各自 current usage 与 cap；
- ScopeRiskDecision 保存分量、模型、来源、动作后总额和通过状态；
- Reservation scope allocation 只消费 Risk Engine 决策值；
- durable partial-fill 比例重建、ADD canonical replacement delta 和七层 scope 口径；
- 全量回归、覆盖率、静态检查、schema drift、readiness 与现实能力门。

按用户特别约束，未调用 Codex Security 或任何 Codex Security 审计 Skill、插件、模块。

### 2.1 v5 与旧输入拒绝

```text

```

### 2.2 规范压力派生

初仓集成场景：

```text
quantity / executable / multiplier = 0.5 / 100.5 / 1
requested notional                 = 50.25
canonical base Heat                = 5.25
policy-bound cost stress           = 0.1608
incremental planned loss           = 5.4108

gap stress                         = 0.25125
liquidity degradation stress       = 0.5025
unprotected window stress          = 0.125625
incremental stress loss            = 6.290175
```

七层 scope 的 decision 和 Reservation allocation 均断言 planned=`5.4108`、stress=`6.290175`，模型为
`planned-loss-plus-scope-shocks-v1`，来源为 `test-only:scope-stress-research-v1`。测试值只验证公式和
合同，不是生产参数。

单元测试另行验证：

- 缺少 stress scenario 或空 source 无法构造 Risk Policy；
- planned cap 通过但派生 stress 超限时，独立返回 `SCOPE_STRESS_LIMIT_EXCEEDED`；
- 18 位边界输入的三个分量均向上取整；
- LONG/SHORT requested notional 和 stress 结果均由同一策略计算；
- decision 拒绝不满足 `stress = planned + 三项 add-on` 的自相矛盾证据；
- 旧字段因 `extra="forbid"` 被拒绝。

### 2.3 Durable 与 ADD 口径

初仓完整成交后的 durable scope stress 为 `6.290175`。ADD 最终预检以 canonical 当前保护风险替换旧
planned exposure，replacement delta=`-0.25` 同步作用于 planned 与 stress，因此 current 值为：

```text
current planned = 5.4108   - 0.25 = 5.1608
current stress  = 6.290175 - 0.25 = 6.040175
```

部分成交 `0.2 / 0.5` 后，planned=`2.16432`、stress=`2.51607`，证明 durable 重建按同一冻结 allocation
比例缩放，而不是重新读取 caller 数值。

## 4. 结果判定

1. 调用方不再能够选择或低报 scope stress；v4 和旧字段均失败关闭。
2. 每个 exact scope 的增量 stress 从冻结场景、同一 requested notional 和 canonical planned loss 派生。
3. planned/stress 独立比较各自 cap，Reservation 与 durable 重建只消费 Risk Engine 决策值。
4. 场景参数无生产默认，真实 `DEC-RISK-010` 研究与逐域认证仍未完成。
5. 本包不构成实盘能力；三项现实能力门继续为 `DISABLED`。
