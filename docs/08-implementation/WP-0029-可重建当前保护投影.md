# WP-0029：可重建当前保护投影

## 1. 交付目标与边界

WP-0028 已把完整活动保护集合的最差触发价保存为 immutable fact，但 Risk Engine 不能直接查询任意一条
历史快照作为“当前保护”。本包新增只读、可重建的 `venue_protection_current_projection`，把最新事件、
冲突、退化、未知、陈旧与当前仓位绑定收敛为统一查询合同。

本包不修改 Protected Profit/Open Heat/Giveback 公式，也不把投影接入增险决策。它只建立后续公式所需的
当前事实边界。

## 2. Exact-scope 与事件排序

查询 scope 为：

```text
organization
× venue
× execution_domain
× account
× instrument
× position_mode
× position_side
× margin_mode
× collateral_pool_id
× settlement_currency
```

`settlement_currency` 来自保护事实强引用的 immutable position snapshot。每个 scope 只按以下顺序选最新
候选，不按数据库到达顺序覆盖：

```text
event_time DESC
venue_observed_at DESC
first_received_at DESC
recorded_at DESC
venue_protection_snapshot_id DESC
```

最大 `event_time` 有多条候选时返回 `MAX_EVENT_TIME_COLLISION`，不使用后到事实打破经济语义冲突。

## 3. 当前仓位强绑定

保护投影只有同时满足以下条件才是 `CONFIRMED`：

- 最新保护候选唯一且自身状态为 `CONFIRMED`；
- 同 scope 的 current position projection 为 `CONFIRMED`；
- 保护事实引用的 `venue_position_snapshot_id` 精确等于 current position 的 source snapshot ID；
- 调用方提供显式 `as_of` 与经认证的 `max_age_ms`，保护事实仍为 `FRESH`。

因此，一个曾经有效的保护集合在出现更新仓位快照后不会继续保护新仓位。未重新确认保护时返回
`POSITION_NOT_CURRENT` 并隐藏价格、覆盖数量、order-set hash 与所有保护确认布尔语义。

## 4. 失败关闭合同

| 情况 | projection | reason |
| --- | --- | --- |
| 无 scope 行 | `UNKNOWN/MISSING` | `SOURCE_MISSING` |
| 最新源为 DEGRADED | `UNKNOWN` | `SOURCE_DEGRADED` |
| 最新源为 UNKNOWN | `UNKNOWN` | `SOURCE_UNKNOWN` |
| 最大事件时间冲突 | `UNKNOWN` | `MAX_EVENT_TIME_COLLISION` |
| 当前 position 不可用 | `UNKNOWN` | `POSITION_MISSING` / `POSITION_UNKNOWN` |
| 保护引用的 position 已被更新 | `UNKNOWN` | `POSITION_NOT_CURRENT` |
| 查询早于事实 | `UNKNOWN` | `SOURCE_FROM_FUTURE` |
| 超过调用方 freshness 门 | `UNKNOWN/STALE` | `SOURCE_STALE` |

任何 `UNKNOWN` 结果均不暴露：position binding、direction、quantity、trigger、order-set hash、venue-native、
reduce-only 或 replacement 语义，避免下游把未知解释为零风险。

## 5. 迁移、监控与回滚

迁移 `20260718_0027` 只创建普通 PostgreSQL view，不保存唯一业务状态。读取继续复用：

- `trading_venue_current_projection_queries_total{projection_type="PROTECTION",...}`；
- `trading_venue_current_projection_age_seconds{projection_type="PROTECTION"}`。

view 没有命令或写路径，直接 `UPDATE` 被 PostgreSQL 拒绝。回滚为：

```text
alembic downgrade 20260718_0026
```

删除 view 不删除 canonical position/protection facts；重新升级可确定性重建。

## 6. 需求追踪

| 权威要求 | 本包证据 |
| --- | --- |
| 数据陈旧、保护不足、账户事实未知时禁止增险 | stale/degraded/unknown/missing 一律隐藏可用保护语义 |
| 真实仓位必须有已确认保护或受控退出 | 保护必须精确引用 current position source snapshot |
| 可重建查询投影，Redis 不保存唯一事实 | 普通 SQL view 从 immutable facts 重建，无独立写状态 |
| 每个执行域分别认证 | exact scope 保留 venue/domain/account/mode/pool/instrument/currency |
| 测试、监控、错误处理、回滚与证据 | 10 项投影测试、现有指标、reason contract、view 往返与验证记录 |

## 7. 明确未完成范围

- 投影来源仍是本地测试构造的 shadow facts，尚无真实 Binance/Hyperliquid collector；
- Risk Engine 尚未把 current position 与 current protection 投影用于规范 Open Heat/Giveback；
- 权威公式不需要历史盈利 peak；仍缺的是当前 entry、Mark、保护价、数量、乘数及成本的互斥分解；
- 保护触发价不是成交保证价，穿透与压力退出继续由独立 cost-stress policy 处理；
- 真实 OMS/Freqtrade/VenueAdapter、Web/PWA、Telegram、Margin、Vault/CTO、PnL 与运维仍未完成；
- `LIVE_ORDER_SEND`、`CAPITAL_TRANSFER`、`AUTO_ADD` 继续为 `DISABLED`。

按用户特别约束，Codex Security 及其审计 Skill、插件和模块保持停用；本包仅使用正常架构设计、
代码检查、数据库迁移和工程测试。
