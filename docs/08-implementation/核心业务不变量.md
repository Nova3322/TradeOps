# 核心业务不变量

> 状态：BASELINE
> 日期：2026-08-01
> 原则：保留业务语义，尽量用核心对象字段、纯函数、事务和普通查询表达

| 能力 | 权威实现与状态 | 关键自动化验证 |
| --- | --- | --- |
| 基础运行 | `config`、`database`、`api`、`logging`、`metrics` | 配置拒绝非 PostgreSQL；健康检查；Schema revision 与默认门检查 |
| 内部身份与 RBAC | `User.principal_type`、`RoleAssignment`、`TradingService.can_user` | 五角色、账户/场所作用域、默认拒绝；HUMAN 不能冒充 SYSTEM |
| Proposal | `Proposal` 当前状态、版本、冻结 payload、策略标识/版本 | DRAFT 到审核终态；幂等创建不复制 Proposal；SYSTEM 仅接受 SERVICE principal |
| Approval | `Approval` + Proposal/TransferProposal/RiskControlChangeRequest 状态；数据库 exactly-one parent 约束 | 禁止自审；按父对象验证独立 Reviewer 和唯一投票，风险恢复固定两名不同 HUMAN Reviewer |
| Risk Engine | `evaluate_risk` 纯函数；服务端事实查询；`RiskPolicy`、`RiskDecision` | 相同输入相同结果；负值拒绝；调用者不能伪造占用、新鲜度、仓位、权益或保护 |
| System Risk State | `RiskPolicy.system_state` | KILL_SWITCH、REDUCE_ONLY、NO_PYRAMID 阻断对应新增风险 |
| 受复核风险恢复 | `RiskControlChangeRequest` + `RiskPolicy.revision` + `CapabilityGate.version` | 15 分钟冷却、24 小时 TTL、双 HUMAN、step-up action/object/version、执行重验、scope/版本漂移和生产无 LIVE scope 均 fail closed |
| 原子风险预留 | `RiskReservation` + 全局 risk-capacity transaction lock | 并发下 Reservation、OrderIntent、CommandReceipt 原子写入且不超总容量；Unknown 继续占用 |
| TradingAuthorization | 有范围、数量/风险上限、有效期和 Add 次数的短期行 | 过期、越权、超量、政策/事实变化和关闭的 AUTO_ADD 均拒绝 |
| Campaign | 一笔经济交易的 Proposal/Authorization/Intent/Fill/Position/PnL 关联；作用域唯一未关闭约束 | 只有仓位归零、EXIT 终态且全 scope MATCH 后才能 CLOSED 并释放 OPEN 风险 |
| TargetPositionArbiter | `select_target_position` 纯函数；Campaign 只保存当前目标 | 选择最小目标、最高紧迫度并合并原因 |
| OrderIntent | 一张表保存有限当前状态；减仓绑定目标版本与仓位事实；场所事实分表 | 活动意图阻止重复减仓；成交校验状态、方向、数量、venue 和语义幂等 |
| 幂等命令 | `CommandReceipt` + PostgreSQL advisory transaction lock | 同 key 同语义返回原回执；不同语义明确冲突 |
| Instrument Catalog | `Instrument` | 场所/标的身份、tick/lot/min notional/multiplier/collateral/active/更新时间 |
| 场所事实 | VenueOrder/Fill、Position、Equity、Protection、Funding | `observed_at` 与写入时间分离；成交去重；订单/成交、仓位、保护差异可对账 |
| 保护状态 | `ProtectionOrder` 与当前 Position 关联 | 未知或覆盖不足被对账识别并禁止依赖其增险 |
| PnL 与成本 | `compute_pnl` + Campaign 汇总 | 成交、手续费、资金费、滑点、已实现/未实现/总 PnL；无 FX 时拒绝币种混算 |
| reconciliation | 单表 `ReconciliationRun.differences` + scope 计算 | MATCH 只能计算产生并覆盖作用域内全部活动 Campaign；RESOLVED 不等于 MATCH |
| sender fencing | 每执行作用域一行 `SenderLease` | 接管要求旧 lease 到期后新鲜计算型 MATCH；token 单调增加；错误 scope 和旧 token 被拒绝 |
| Capability Gate | 五行简单开关 | 默认关闭；合法启用不破坏 DB readiness，也不绕过业务硬门 |
| Perptape 候选身份 | source exchange + raw symbol + canonical symbol + timeframe + direction + trigger time | 同 canonical symbol 的不同报价合约不冲突；旧 ID 仅在唯一匹配时兼容，歧义拒绝 |
| 基本审计 | `AuditEvent` + 核心记录字段 | actor、时间、原因、correlation/idempotency、版本和关键状态变化落库 |

## 跨能力硬门

1. 信号和人工输入只能创建 Proposal，不能直接产生真实订单。
2. Proposal 创建者不能审核自己的 Proposal；高风险必须由两个不同 Reviewer 批准。
3. Risk Engine 是确定性纯计算；其持久化入口只使用服务端事实，陈旧/未知仓位、权益或保护一律不能新增风险。
4. Approval 只签发短期、有限范围的 TradingAuthorization，不产生永久交易权限。
5. Reservation、OrderIntent 和幂等回执必须在同一事务提交或回滚。
6. 订单结果 Unknown 时保留风险容量，不自动重发；只有确认零成交的取消/拒绝才释放全部预留。
7. 多个退出/减仓候选只计算一个最小目标仓位；Campaign 只保存当前目标，不保存可重建计划。
8. 一个 Campaign 存在活动 OrderIntent 时不得生成第二个减仓意图。
9. 场所真实订单、成交、仓位、保护、权益和资金费与内部预期分开保存，并由对账比较。
10. 自动利润归集只使用已关闭 Campaign 的净实际 PnL、已确认可划出余额和新鲜机器 MATCH；浮盈、在途和 Unknown 不能成为可归集利润。
11. 自动运营补充与利润归集分开启停，只能为空仓下一周期补到冻结目标；活动仓、净已实现亏损、未解决订单或缺少 MATCH 时不得从 Vault 补充。
12. 恢复发送前必须先对账；每个 execution scope 只有一个有效 lease owner，旧 token 永远不能发送。
13. 未保护、保护不足或保护未知的真实仓位不得新增风险。
14. Capability Gate 不替代业务授权、风险判断、对账或 fencing；五个危险能力默认关闭。
15. INITIAL/ADD 创建前必须在全局容量锁内完成最终风险复核；Reservation、OPEN 和 UNKNOWN 都计入占用。
16. ADD 还要求已有 Campaign、非零盈利仓位、完整新鲜保护、NORMAL 状态、次数/数量/风险余量且无活动意图。
17. HUMAN 只能提交 MANUAL Proposal；SYSTEM Proposal 必须冻结 SERVICE principal、strategy id 和 strategy version。
18. 手工处理后的 RESOLVED 只表示处理动作结束；必须重新计算得到更新的 MATCH 才允许 sender 接管。
19. 风险恢复不是风险状态的反向直接更新：请求冻结政策/Gate 版本和 scope，两名不同 HUMAN Reviewer 分别以动作级 step-up 批准，冷却和 TTL 满足后执行仍须重新读取全部权威事实。
20. 生产风险恢复必须从运行配置发现至少一个 LIVE scope；未配置、事实缺失、Unknown、非 MATCH 或版本/scope 漂移一律 fail closed。`KILL_SWITCH` 不走常规恢复流程。
21. 风险暂停、TradingAuthorization 签发和恢复遵守同一风险容量锁序；收紧撤销的旧 Authorization/AddUnit 永不因恢复而复活。已发送或 Unknown Add 的后续正成交仍必须消费保留的责任槽。
22. 资金中心的 `0 USD · MISSING` 是缺少 Vault 事实时的可见占位，不是已确认余额；真实净值默认只汇总 LIVE，SHADOW/TESTNET 只能出现在独立模拟区。
23. Telegram 只能通知、跳转 Web 审核和提交经二次确认的只收紧动作；不得批准/执行资金划转或风险恢复，也不得把消息按钮当作授权事实。

## SHADOW 端到端验证

核心集成测试覆盖：

```text
Proposal
  → Approval
  → RiskDecision
  → TradingAuthorization
  → RiskReservation + OrderIntent
  → synthetic VenueOrder + VenueFill
  → Position + Protection + Equity + Funding
  → Reconciliation
  → Campaign PnL
```

该流程只写一次性 PostgreSQL 测试库和 SHADOW 事实，不连接真实交易所，也不发送真实订单。
