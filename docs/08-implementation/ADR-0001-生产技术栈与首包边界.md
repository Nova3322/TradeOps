# ADR-0001：生产技术栈与首包边界

> 状态：Accepted for engineering baseline；生产区域与现实权限仍未认证
> 日期：2026-07-18
> 约束：本 ADR 只落实 `DEC-ARCH-003` 的工程技术选择，不改变任何产品、风险、执行或资金真源

## 决策

- Trading 核心控制面采用 Python 3.12、FastAPI、SQLAlchemy 2、Alembic 与 PostgreSQL 18。
- Python 依赖由 `uv` 管理并提交 `uv.lock`。应用声明兼容 Python `>=3.12,<3.15`，生产镜像固定到经过验证的 3.12 补丁版本。
- Web / PWA 后续采用 React 19.2、TypeScript 与 Vite 8；前端不保存权威业务事实。
- Freqtrade 与 VenueAdapter 保持独立 worker / sidecar 故障域；Freqtrade 当前官方要求 Python 3.11+，因此与本基线兼容，但其版本仍按执行证书独立冻结。
- PostgreSQL 同时承载关系事实、不可变审计账本、command receipt、transactional outbox 与 consumer inbox。Redis 以后只用于可重建缓存。
- 首个包不引入独立消息中间件。先把 outbox 的耐久和幂等合同做实；是否增加消息设施由吞吐、隔离和恢复证据决定，不能产生第二事实源。
- 生产部署采用“单区域、多故障域、可恢复”的目标；具体云、区域与 HA 数字在司法辖区、RTO/RPO 和 owner 事实补齐前保持未认证。

## 依据

- Python 3.12 满足 Freqtrade 官方的 Python 3.11+ 要求，并降低控制面与 Python 执行 worker 的运行时分裂。
- SQLAlchemy 的 Session 明确对应单一逻辑事务，适合把状态迁移、审计和 outbox 原子提交。
- PostgreSQL 18 是当前受支持的稳定主版本；不采用 PostgreSQL 19 beta。
- React 与 Vite 只承担控制台和 PWA，不进入订单、授权或账本真源。
- `uv.lock` 提供跨平台精确依赖解析，避免未审计的运行时漂移。

## 首个可验证开发包：WP-0001

范围固定为耐久控制面基础：

1. 统一命令信封与语义请求哈希。
2. PostgreSQL command receipt 与幂等冲突检测。
3. 状态、不可变审计事件与 transactional outbox 同事务提交。
4. consumer inbox 的一次处理语义。
5. `LIVE_ORDER_SEND`、`CAPITAL_TRANSFER`、`AUTO_ADD` 三个真实写能力默认 `DISABLED`，且本包不提供启用接口。
6. 数据库迁移、降级、健康检查、结构化日志与低基数指标。

本包明确不实现 Proposal、Approval、Risk、OMS、Venue、Freqtrade、Margin、CTO、Telegram 或 Web 页面，也不包含任何真实交易、资金或签名路径。后续业务包只能复用本包的事务与事件合同，不得另建旁路。

## 失效与回滚

- 依赖、数据库主版本或运行时升级会使本 ADR 的验证证据失效，需要重跑迁移、并发幂等、失败回滚和恢复测试。
- WP-0001 可用 `uv run alembic downgrade base` 回滚全部首包表、触发器和种子；执行前必须确认没有后续迁移依赖。
- 回滚软件或数据库结构不得重放业务命令、复活授权或开启任何真实写能力。
