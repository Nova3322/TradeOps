# WP-0001：耐久控制面基础

> 状态：Implementation
> 需求引用：`REQ-OPS-001`、`REQ-SEC-001`、`STATE-001`、`TEST-003/004/005/009/010/016`
> 上位合同：`DEC-ARCH-002`、`DEC-ARCH-003`、统一 API / Event / Audit 契约

## 交付合同

本包提供以后所有状态命令共用的最小耐久事务边界：

```text
CommandEnvelope
  -> command_receipt 幂等占位
  -> 领域处理器（同一数据库事务）
  -> immutable audit_event + outbox_message
  -> command_receipt 终态
  -> COMMIT
```

任何异常都回滚整笔事务。重复命令只有在语义哈希相同时返回原结果；同一幂等键配不同语义返回 `CONFLICT`。消费者用 `consumer_name + message_id` 原子占位，重复消息不再次执行处理器。

## 安全默认

- 首次迁移强制建立 `LIVE_ORDER_SEND`、`CAPITAL_TRANSFER`、`AUTO_ADD`，状态均为 `DISABLED`。
- 本包只有“确认/收紧为关闭”的服务，没有启用接口。
- 数据库不可达时 readiness 返回失败；应用不能用内存、Redis 或本地文件代替耐久事实。
- 审计表由数据库触发器阻止 UPDATE / DELETE。
- 日志和指标不记录 payload、幂等键、凭据、账户、标的或用户身份等高基数/敏感值。

## 本地验证

纯本地验证：

```bash
uv sync --locked
uv run ruff format --check src tests migrations
uv run ruff check src tests migrations
uv run mypy src
uv run pytest -m 'not integration'
```

PostgreSQL 集成验证使用一次性数据库，并显式设置测试连接；Alembic 只读取应用的
`TRADING_DATABASE_URL`，测试夹具再读取 `TEST_DATABASE_URL`：

```bash
export TEST_DATABASE_URL='postgresql+psycopg://...'
TRADING_DATABASE_URL="$TEST_DATABASE_URL" uv run alembic upgrade head
uv run pytest --cov
TRADING_DATABASE_URL="$TEST_DATABASE_URL" uv run alembic downgrade base
TRADING_DATABASE_URL="$TEST_DATABASE_URL" uv run alembic upgrade head
```

不要把真实密码写入命令历史、仓库或证据文件。上例只说明变量形态。

## 运行与错误处理

- `GET /health/live` 只证明进程存活。
- `GET /health/ready` 检查数据库与三项能力门种子；失败返回 `503` 和稳定错误码。
- `GET /metrics` 暴露低基数命令结果、命令耗时与数据库 readiness 指标。
- 非预期处理器错误原样抛出给上层错误边界，同时递增 `ERROR` 结果指标；事务中不得留下 receipt、审计或 outbox 半成品。

## 回滚

1. 停止所有使用本迁移的应用实例。
2. 确认不存在后续迁移或真实能力证书。
3. 导出必要的非敏感证据摘要。
4. 执行 `alembic downgrade base`。
5. 验证相关表、触发器和函数已移除。

首包尚无真实订单、授权或资金事实；一旦后续包依赖这些表，禁止把该降级步骤当作生产数据恢复方案。
