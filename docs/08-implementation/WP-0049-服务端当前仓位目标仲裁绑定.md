# WP-0049：服务端当前仓位目标仲裁绑定

## 1. 交付目标与信任边界

WP-0048 的纯 `TargetPositionArbiter` 可以阻止候选扩大传入的 current quantity，但如果调用方同时伪造
current-position binding hash 和 quantity，单独调用纯函数仍无法知道真实场所仓位。

WP-0049 新增 `CampaignTargetPositionEvaluationService`。服务端先通过 WP-0045 解析 fresh canonical
Campaign current position，再把真实 binding hash、真实 current quantity 和同一查询时刻传给纯仲裁器。
调用方不再提供仲裁基准数量。本包仍不持久化 decision，不生成 OrderIntent。后续 WP-0050 已实现
canonical 保护健康失败的首个服务端候选；其他候选来源仍待实现。

## 2. 服务端绑定流程

```text
campaign_id + ProjectionQueryContext
  -> CampaignCurrentPositionBindingService.resolve
  -> exact binding_hash + current_quantity
  -> TargetPositionArbiter.arbitrate
  -> HOLD / REDUCE / EXIT decision
```

current-position resolver 继续执行原有 exact opening prefix、scope、direction、quantity、multiplier、facts time
与 TTL 约束。missing/UNKNOWN/stale/conflict position 会在进入仲裁器前失败关闭。

候选必须携带服务端刚解析的 binding hash，并严格缩小该真实 quantity。调用方不能通过提交更大的虚构
current quantity，让原本会扩仓或持平的 target 被误判为减仓。

## 3. 结果与失败语义

服务返回 WP-0048 的 `target-position-decision-v1`：

- 无候选时 target 等于服务端 current quantity，返回 HOLD；
- 合法候选按更小 target/更高 urgency 独立仲裁；
- binding mismatch 或 target 不小于服务端 current quantity 返回
  `TARGET_POSITION_CANDIDATE_CONFLICT`；
- current position 过期返回 `CAMPAIGN_CURRENT_POSITION_UNAVAILABLE`。

新增 bounded metric：

```text
trading_campaign_target_position_evaluations_total{result}
```

## 4. 数据库与未完成范围

本包不新增表或 Alembic revision；schema 仍为 `20260718_0035`。evaluation 是查询时计算，不改变 Campaign、
RiskLedger、OrderIntent 或 sender 状态。

仍未完成：

- durable Campaign target fact、revision/去重/替换与并发锁；
- 独立硬止损、趋势、动态去杠杆及其他系统风险候选生产器（WP-0050 已实现保护失效退出候选）；
- reduce-only OrderIntent、sender claim、部分成交、Unknown 与 position reconciliation；
- 保护 replacement、超量减仓防护、完全退出与风险关闭；
- OMS/Freqtrade/VenueAdapter 和逐场所 reduce-only 认证。

`LIVE_ORDER_SEND`、`CAPITAL_TRANSFER`、`AUTO_ADD` 继续为 `DISABLED`。按用户明确约束，Codex Security
及其所有审计 Skill、插件和模块保持停用；本包只执行常规架构约束、代码检查、数据库约束与测试。
