# WP-0025：风险预留损失组件冻结

> 后续状态：WP-0026 已移除 `requested_reserved_heat`，base Heat 改由 Risk Engine 按价格、失效价、
> 数量和 certified contract multiplier 规范计算；当前合同以
> [WP-0026](WP-0026-规范化Base-Heat与Scope增量.md) 为准。本文件保留 WP-0025 当时的迁移与分量冻结证据。

## 1. 交付目标

WP-0025 修正最终预检当前损失的分类语义。此前 `RiskReservation.reserved_heat` 保存完整 incremental
worst-case loss，但 durable exposure 聚合器只能把它全部归入 Open/Reserved/Unknown Heat，无法在
后续预检中独立还原 protected-profit giveback 与 cost stress add-on。

本包在不可变 reservation 上冻结三项原始分量，继续复用现有 `RiskLedgerEntry` 与
`RiskExposureState` 的 combined total Heat 守恒，不新增状态机或第二套账本。

## 2. 不可变分解合同

每个新 reservation 必须满足数据库约束：

```text
reserved_heat
  = base_heat_reserved
  + protected_profit_giveback_reserved
  + cost_stress_add_on_reserved

base_heat_reserved > 0
protected_profit_giveback_reserved >= 0
cost_stress_add_on_reserved >= 0
```

字段分别来自最终通过 Risk Engine 的：

- `requested_reserved_heat`；
- `requested_protected_profit_giveback`；
- `requested_cost_stress_add_on`。

`reserved_heat`、`RiskLedgerEntry.heat` 和 `RiskExposureState.total_heat` 仍保存三项之和，因此既有
Reserved/Open/Unknown/Released bucket 守恒、部分成交比例迁移和对账逻辑不变。CapabilityCertificate
发送前校验继续使用 combined total loss，不会因分解而缩小证书检查值。

## 3. 当前五项损失复算

公共 durable exposure 聚合器对每个 reservation 计算：

```text
active_ratio
  = (state.open_heat + state.reserved_heat + state.unknown_heat)
    / state.total_heat

base_heat_ratio
  = reservation.base_heat_reserved / reservation.reserved_heat

current Open Base Heat     = state.open_heat × base_heat_ratio
current Reserved Base Heat = state.reserved_heat × base_heat_ratio
current Unknown Base Heat  = state.unknown_heat × base_heat_ratio

current Protected-Profit Giveback
  = frozen protected-profit giveback × active_ratio

current Cost Stress Add-on
  = frozen cost stress add-on × active_ratio
```

因此五项当前损失之和精确等于该 Campaign 的 active combined total Heat。部分成交后终态取消会同时
按 active ratio 收敛 base Heat、giveback、cost 和 scope allocation；Unknown 则保留相应分量并继续
冻结新增风险。

聚合器还显式校验：

```text
RiskExposureState.total_heat == RiskReservation.reserved_heat
```

不一致返回 `DURABLE_EXPOSURE_INTEGRITY_FAILED`。正常更新路径之前还受数据库
`risk exposure root totals and versions are monotonic` trigger 保护。

## 4. Snapshot v2

`durable-risk-exposure-v2` 的每个 component 新增：

- combined `total_heat`；
- 三项 frozen reservation component；
- active protected-profit giveback；
- active cost stress add-on。

聚合层新增 Campaign 当前 giveback 与 cost。最终 `ORDER_PRECHECK` 将这些值写入
`TradeLossComponents`，不再固定写零。proposal precheck 仍代表尚无 Campaign 的新初仓，因此五项
当前 trade loss 全部为零；组织内其他 Campaign 继续通过 funding、margin 和 scope 限制新提案。

## 5. 迁移与回滚

迁移 `20260718_0025` 为 `risk_reservations` 增加三个非空 Numeric 字段并替换 amount check。存在
legacy reservation 时升级明确失败，因为无法从 combined Heat 可信反推历史分解；存在新 reservation
时 downgrade 同样失败。

空 reservation 表回滚路径为：

```text
0025 -> 0024 -> 0025
```

## 6. 明确未完成范围

- 本包冻结最终预检已接受的三项分量，但尚未让 Risk Engine 从 canonical 价格、失效价、订单成本、
  滑点、资金费和保护事实独立推导“新增”分量；调用方新增损失模型的真源绑定仍需后续工作包关闭；
- protected-profit giveback 的实时保护价/峰值利润来源与 cost stress 的动态场所费用事实尚未实现；
- 真实 venue collector、Freqtrade/VenueAdapter、Web/PWA、Telegram、Margin、Vault/CTO、PnL 和完整
  运维目标仍待实现；
- `LIVE_ORDER_SEND`、`CAPITAL_TRANSFER`、`AUTO_ADD` 继续为 `DISABLED`。

按用户特别约束，Codex Security 及其审计 Skill、插件和模块保持停用；本包仅使用常规架构设计、
数据库约束、静态检查和自动化测试。
