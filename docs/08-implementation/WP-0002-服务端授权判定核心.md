# WP-0002：服务端授权判定核心

> 状态：Implemented
> 需求引用：`DEC-PROD-004/005`、`DEC-SEC-001`、`IAM-SESSION-001..004`、`UAT-IAM-001..010/013..015/017`
> 上位合同：《身份权限与审批矩阵》《API 事件数据与审计契约》

## 交付合同

本包建立服务端授权判定所需的耐久事实和确定性计算：

```text
当前主体状态
  ∩ 当前有效角色标签
  ∩ 至少一个匹配 ABAC 作用域
  ∩ 在线渠道与动作级 Passkey/WebAuthn 证据
  ∩ 职责分离 / 禁止自审
  - 当前有效显式拒绝
  -> immutable AuthorizationDecision
```

角色允许动作以《身份权限与审批矩阵》的动作 ID 为固定策略。作用域至少绑定组织，并可继续收窄到账户、场所、板块、风险档位、动作和渠道。没有主体、没有角色、没有作用域、事实未知或动作不在策略目录时均拒绝。

## 审核资格边界

- 只有当前有效 `REVIEWER` 标签和匹配作用域能获得 `ACT-PROPOSAL-APPROVE` 资格。
- 同一人即使同时拥有 `PROPOSER + REVIEWER` 也不能审核自己创建的提案版本。
- 低、中、高风险的判定结果分别给出 `required_quorum = 1 / 1 / 2`。
- 冻结版本、有效期、Risk Engine 预检和系统风险状态任一不合格时均拒绝批准资格。
- `SYSTEM_ADMIN` 不继承 Reviewer、Risk Admin、Treasury Admin 或执行权限。
- 显式拒绝优先于所有允许标签。

这里的 `ALLOW` 只表示某主体在该时刻、该作用域、该对象版本上有资格发起具体动作。它不是 `ReviewerVote`、`ApprovalDecision`、`TradingAuthorization`、Risk Reservation 或订单许可；本包不创建这些业务事实。

## 动作级认证

敏感动作要求耐久 `ActionAssurance`：

- 只接受 `PASSKEY_WEBAUTHN + ACTION_STEP_UP`；
- 精确绑定主体、设备、渠道、动作、对象 ID 和对象版本；
- 有明确签发时间、过期时间和验证方引用；
- 使用 `SELECT FOR UPDATE` 原子消费，并发请求最多一个成功；
- 主体/设备/动作/对象/版本/有效期/验证方在签发后不可修改；
- 已消费时间不可撤销，`REVOKED` 不可恢复，历史行不可删除。

当前没有 MFA 签发 API，也没有把任何身份或角色种入数据库。未来托管 IdP 适配器必须验证真实 Passkey/WebAuthn 结果后才能写入这类证据；开发代码不能用请求布尔值或 Telegram 身份替代。

## 数据与事务

迁移 `20260718_0002` 增加：

- `identity_principals`
- `role_assignments`
- `permission_scopes`
- `explicit_denies`
- `action_assurances`
- `authorization_decisions`

授权判定通过 WP-0001 的 command receipt、不可变审计和 outbox 事务边界提交。每次允许或拒绝都保存稳定原因码、策略版本、匹配角色、命中拒绝、对象版本、作用域、认证引用和请求哈希。`authorization_decisions` 由数据库触发器禁止 UPDATE / DELETE。

readiness 要求 Alembic revision 精确为 `20260718_0002`，同时继续要求三项真实能力门存在。旧 schema、数据库不可达或门禁丢失均返回稳定失败，不允许回退到内存事实。

## 明确不包含

- 托管 IdP 供应商选择、登录、Passkey 注册或挑战验证端点；
- 用户、标签或作用域授予/扩大 API；扩权以后必须走双人复核；
- Proposal 创建/冻结；
- ReviewerVote 与 ApprovalDecision 聚合；
- RiskDecision、TradingAuthorization、OMS、Freqtrade、VenueAdapter；
- Web/PWA/Telegram 页面或动作入口；
- 任何真实订单、签名、资金或能力启用路径。

## 验证与回滚

验证命令沿用 WP-0001，并必须用一次性 PostgreSQL 运行完整测试。关键场景包括默认拒绝、多标签自审、作用域越界、显式拒绝、标签撤销、1/1/2 quorum 输出、一次性 MFA 重放/并发、审计不可变和迁移往返。

回滚前停止所有依赖授权表的实例，然后执行：

```bash
TRADING_DATABASE_URL="$TEST_DATABASE_URL" uv run alembic downgrade 20260718_0001
```

降级只删除 WP-0002 的身份与授权事实、触发器和函数，保留 WP-0001 的 command receipt、审计、outbox、inbox 和三项默认关闭门禁。未来一旦存在真实身份或审批依赖，结构降级不能当作数据恢复方案。
