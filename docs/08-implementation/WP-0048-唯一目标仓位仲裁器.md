# WP-0048：唯一目标仓位仲裁器

## 1. 交付目标与领域边界

权威领域合同要求硬止损、趋势退出、动态去杠杆和系统风险减仓不能各自形成并行订单链，而必须先合并为
一个更小目标仓位。`TargetPositionArbiter` 同时被明确限定为 Campaign 内纯规则：不拥有独立 ID、表、
状态机、服务、密钥或交易所连接。

WP-0048 实现该纯规则模块。它只消费已经规范化的减仓候选，确定性返回唯一目标剩余仓位、独立最高紧迫度
和完整解释。本包不生成或持久化 OrderIntent，不调用 OMS/Freqtrade/VenueAdapter，也不实现候选来源。

## 2. 规范化减仓候选

`TargetPositionCandidate` 支持四类固定来源：

```text
HARD_STOP
TREND_EXIT
DYNAMIC_DELEVERAGE
SYSTEM_RISK_REDUCTION
```

每个候选绑定：

- namespaced source ref、policy version 和 reason code；
- exact current-position binding hash；
- 目标剩余 quantity；
- `ORDERLY / URGENT / IMMEDIATE` 紧迫度；
- facts time、valid-until 和自校验 candidate hash。

候选必须严格缩小当前正仓位。目标等于或大于当前 quantity、重复 source ref、position binding 冲突、
future-dated 或过期候选均固定拒绝；仲裁器不会把无效候选静默当作 HOLD。

## 3. 双维度唯一仲裁

目标仓位和紧迫度分别仲裁：

```text
target_quantity = min(all candidate target quantities)
urgency = max(all candidate urgency ranks)
reduction_quantity = current_quantity - target_quantity
```

因此，更小目标与更高紧迫度可以来自不同候选。输出分别保存 selected target sources/reasons 与 selected
urgency sources/reasons，同时保留全部 reason codes 和 canonical-ordered input hashes。输入顺序改变不会改变
decision hash。

结果语义：

```text
no candidates        -> HOLD, target=current, requires_order=false
0 < target < current -> REDUCE, requires_order=true
target = 0           -> EXIT, requires_order=true
```

所有结果固定 `reduce_only_required=true`。这只是 OMS 后续必须遵守的合同，不代表场所 reduce-only 语义已经
认证或订单已经发送。

后续 [WP-0049](WP-0049-服务端当前仓位目标仲裁绑定.md) 已由服务端解析 WP-0045 fresh canonical
position 后再调用本仲裁器，关闭 caller 自报 current binding/quantity 的边界；durable target 和退出
OrderIntent 仍未实现。[WP-0050](WP-0050-Canonical保护失效退出候选.md) 已提供首个 canonical 保护健康
失败候选，但尚未建立其他候选来源。

## 4. 确定性与监控

输出使用 `target-position-decision-v1`，包含 Campaign、current-position binding、current/target/reduction
quantity、action、urgency、所有来源解释、facts/evaluation time 和自校验 hash。

新增 bounded metric：

```text
trading_target_position_arbitrations_total{result}
```

## 5. 数据库与未完成范围

本包不新增表或 Alembic revision；schema 仍为 `20260718_0035`。纯仲裁器不持久化任何状态，符合现有
领域边界。

仍未完成：

- 从 WP-0045 fresh current position 服务端构造 arbitration request；
- 独立硬止损、趋势、`L_effective > L_max` 与其他系统风险候选生产器（WP-0050 已实现保护失效退出候选）；
- durable Campaign target fact、去重/替换语义和 reduce-only OrderIntent；
- 未完成退出订单、保护 replacement、部分成交、Unknown 与真实仓位对账；
- OMS/Freqtrade/VenueAdapter、逐场所 reduce-only 认证和故障接管；
- 完全退出后的风险关闭与财务归因结算。

`LIVE_ORDER_SEND`、`CAPITAL_TRANSFER`、`AUTO_ADD` 继续为 `DISABLED`。按用户明确约束，Codex Security
及其所有审计 Skill、插件和模块保持停用；本包只执行常规架构约束、代码检查和测试。
