# WP-0052：耐久目标跨当前绑定延续

## 1. 交付目标

WP-0051 禁止新 target 高于 latest durable target，但单纯“拒绝放宽”不能生成绑定最新 current-position hash
的后续裁决：保护恢复或 position snapshot 更新后，旧 zero target 仍然有效，却可能只得到一个拒绝结果。

WP-0052 把 latest durable target 作为 Campaign 自身的规范化仲裁来源重新输入 WP-0048。只要 durable target
严格小于 fresh canonical current quantity，就生成 current-binding candidate，使已收紧目标在新事实窗口中
继续得到可保存的 `REDUCE/EXIT` decision。

## 2. Carry-forward 候选

候选固定为：

```text
source_type=SYSTEM_RISK_REDUCTION
source_ref=durable-target:<campaign_id>
policy_version=campaign-target-carry-forward-v1
reason_code=DURABLE_TARGET_ACTIVE
target_quantity=<latest durable target>
urgency=<latest durable urgency>
current_position_binding_hash=<fresh server-resolved binding>
facts_as_of=<server evaluation time>
valid_until=<fresh current-position validity>
```

source ref 不包含 target version/fact ID，防止每次 append 后因来源名字变化制造无限 revision。candidate hash 仍
包含当前事实时间和 binding，用于单次输入完整性；`target_semantic_hash` 忽略瞬时 candidate hash，因此同一
carry 语义稳定后返回 `NO_CHANGE`。

当 latest target 等于或高于 current quantity 时不生成 carry candidate：目标已达到或不再构成严格减仓。
当前 WP-0045 仍只接受 opening-prefix quantity，因此实际部分减仓后的 reached 判定要等后续 current binding
扩展后才能覆盖完整生命周期。

## 3. 保护恢复与多来源语义

第一次保护缺失写入 v1 zero target。下一次仍缺保护时，仲裁输入同时包含：

- `PROTECTION_MISSING`；
- `DURABLE_TARGET_ACTIVE`。

这会生成一次解释更完整的 v2；后续相同事实返回 `NO_CHANGE`。如果保护随后恢复，保护失败来源消失，但
durable carry 继续把 target 固定为 0，生成只含 `DURABLE_TARGET_ACTIVE` 的新事实。系统不会把恢复保护解释为
取消已经进入 `CLOSING` 的退出目标。

数据库 monotonic target guard 和服务层 `CAMPAIGN_TARGET_POSITION_RELAXATION_FORBIDDEN` 仍作为纵深防护；
正常路径通过 carry-forward 得到当前 binding 的确定性 target，而不是依赖异常拒绝维持安全状态。
