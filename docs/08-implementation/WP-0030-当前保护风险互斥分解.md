# WP-0030：当前保护风险互斥分解

## 1. 交付目标与边界

WP-0029 已能失败关闭地取得同一 exact scope、同一 current position snapshot 的当前仓位与保护事实。
本包新增 `CurrentProtectedPositionRiskProjection`，从这两项已确认事实确定性派生：

- 当前 Mark 回到最差活动保护触发价的损失；
- 其中仍属于 Open Heat 的部分；
- 其中属于 Protected-Profit Giveback 的部分。

三项金额保留事实自身的 `settlement_currency`。它们不是 USD 报告值，也不得把 USDT、USDC 或其他
结算资产默认视为 1 USD。本包没有把结果接入 Risk Engine、Add、Reservation 或 scope stress，也没有
删除现有调用方临时提交的 giveback 字段。

## 2. 输入真源与失败关闭

读取入口 `VenueCurrentProjectionService.current_protected_position_risk` 只组合：

1. `venue_position_current_projection` 的 `CONFIRMED/FRESH/VENUE_CONFIRMED` 当前仓位；
2. `venue_protection_current_projection` 的 `CONFIRMED/FRESH/VENUE_CONFIRMED` 当前保护；
3. 两者完全相同的 organization、venue、execution domain、account、instrument、position mode、
   position side、margin mode、collateral pool 与 settlement currency；
4. 保护事实的 `source_position_snapshot_id` 精确等于仓位投影 source snapshot ID；
5. direction、quantity、正数 entry、Mark、trigger 和 contract multiplier 可用且一致。

任何输入为 missing、stale、degraded、unknown、冲突、非 OPEN、scope/方向/数量/快照不一致或数值无效，
结果一律为 `UNKNOWN`，并隐藏 source ID、价格、数量和全部损失金额。UNKNOWN 不解释为零风险。

## 3. 互斥公式

设：

```text
Q = 当前真实 quantity
M = contract multiplier
E = entry price
P = current Mark
S = worst active protection trigger
```

LONG 必须满足 `S < P`：

```text
Current-to-Protection Loss = (P - S) × Q × M
Open Heat raw             = max(0, min(E, P) - S) × Q × M
```

SHORT 必须满足 `S > P`：

```text
Current-to-Protection Loss = (S - P) × Q × M
Open Heat raw              = max(0, S - max(E, P)) × Q × M
```

金额使用 18 位小数向上取整。为避免两个分量各自舍入后重复占用，先保守确定总损失和 Open Heat，再令：

```text
Open Heat                = min(rounded total, rounded raw Open Heat)
Protected-Profit Giveback = rounded total - Open Heat
```

所以任何已确认结果都满足：

```text
Current-to-Protection Loss = Open Heat + Protected-Profit Giveback
```

当前处于亏损的部分全部归入 Open Heat；保护触发价已越过 entry 后，Open Heat 为零，Mark 到保护价的
回吐全部归入 giveback。同一份利润不会同时出现在两项中。

## 4. 不可变计算证据

`calculation_version=protected-position-risk-v1`。`calculation_hash` 绑定：

- exact scope（含 settlement currency）；
- position/protection snapshot ID 与 hash；
- direction、quantity、entry、Mark、trigger、multiplier；
- 三项互斥金额；
- 两个输入中较早的 `facts_as_of`；
- calculation version。

组合结果使用较早的事实时间，避免把一组输入的整体时效误报为较新的单项事实时间。源事实仍各自由
快照 ID/hash 独立追溯。

## 5. 需求追踪

| 权威要求 | 本包证据 |
| --- | --- |
| `DEC-RISK-005` 采用完整互斥组件 | 总损失严格等于 Open Heat + Giveback |
| 同一利润不得重复抵扣 | giveback 是保守总损失减 Open Heat 的精确余数 |
| 公式不可机械判定时不得增险 | 任一输入未知或不一致时只返回隐藏金额的 UNKNOWN；Risk Engine 接入前 AUTO_ADD 仍关闭 |
| 交易所事实优先 | 只消费 current canonical position/protection projection |
| 报告 USD 并保留原币 | 本包只保留 settlement currency，不做未经证据的 FX/USD 转换 |
| 可复算与可追溯 | 版本化公式、source IDs/hashes 与 calculation hash |

## 6. 明确未完成范围

- Risk Engine、Risk Ledger、Reservation、Add 与 scope stress 尚未消费本投影；
- 当前 v3 风险请求中的临时 giveback 输入尚未删除，不能宣称调用方自报缺口已关闭；
- 触发价不是成交保证价；fee、slippage、stop penetration 与 funding stress 继续由 WP-0027 的独立
  cost-stress 组件承担；
- settlement currency 到 USD 的 FX、稳定币折扣与脱锚事实仍为 `RESEARCH_REQUIRED`；
- 仓位和保护仍来自本地测试事实，尚无真实 Binance/Hyperliquid collector 或逐场所认证；
- 真实 OMS/Freqtrade/VenueAdapter、Web/PWA、Telegram、Margin、Vault/CTO、PnL 与运维仍未完成；
- `LIVE_ORDER_SEND`、`CAPITAL_TRANSFER`、`AUTO_ADD` 继续为 `DISABLED`。

按用户特别约束，Codex Security 及其审计 Skill、插件和模块保持停用；本包只使用正常代码检查、
类型检查、单元测试、数据库集成测试与全量回归。
