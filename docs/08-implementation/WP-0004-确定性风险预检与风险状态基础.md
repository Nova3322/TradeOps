# WP-0004：确定性风险预检与风险状态基础

> 状态：Implemented
> 需求引用：`REQ-RISK-001..009`、`TEST-002/003/008/009`、`EVID-004/007/011`
> 上位合同：《风险引擎规格》《领域模型与状态机》《API 事件数据与审计契约》

## 交付边界

本包实现不具备执行效力的 `PROPOSAL_PRECHECK`：

```text
版本化 SHADOW 风险政策（必须显式存在且 hash 完整）
  + 完整认证单位与市场/账户/仓位/订单/账本等事实引用
  + 包含最新 UPNL 的 Current Portfolio MTM Equity
  + 当前 Trade 与七级 Scope 风险
  + 当前 SystemRiskState
  -> 确定性 ALLOW / DENY + 稳定原因码 + 安全数量提示
  -> 不可变 RiskDecisionSnapshot
  -> command receipt + audit + outbox（同一数据库事务）
```

它不签发 `TradingAuthorization`，不创建 `RiskReservation`、RiskLedger 分录或
`OrderIntent`，也不连接 Freqtrade 或场所。每份快照由数据库约束
`execution_eligible=false` 与 `reservation_created=false`；因此预检 `ALLOW` 只表示候选可继续
进入后续冻结/人工审核，不表示可以下单。

处理器只接受 Trading 内部 service principal 的 `INTERNAL` 命令；Web/PWA/Telegram actor 不得
直接调用。原始 caller、channel 和认证上下文由 Proposal 模块作为冻结输入继续传递并写入快照。

## 固定计算合同

- `1R_0 = Total Capital Snapshot_0 × 0.5%`。
- 低/中/高 `Frozen Trade Loss Cap = 1R_0 × 1 / 2 / 3`。
- 低/中/高最大有效杠杆为 `3x / 5x / 10x`，并继续与场所实时上限取严。
- `Current Portfolio MTM Equity = Exchange Settled Equity ex-UPNL + latest UPNL + Eligible Vault Equity`。
- `Dynamic Mode Cap = Current Portfolio MTM Equity × 0.5% × tier multiplier`。
- 当前 Trade 上限取冻结上限、动态上限、提案请求损失上限和可选政策绝对上限中的最小值。
- 权益上升不会扩大冻结/提案边界；权益下降（包括最新未实现亏损）立即收紧动态上限。
- 当前 Trade Worst-Case Loss 显式相加 `Open + Reserved + Unknown + Protected-Profit Giveback + Cost Stress Add-on`；本包不会释放或迁移任何 Heat。
- Funding Envelope 使用政策中显式提供的研究值计算并与允许亏损分开；实现没有 1.5% 或其他生产默认值。

手工初仓请求超限返回 `DENY` 和 `max_safe_quantity`，`final_quantity=0`；不会静默缩量下单。
`ALLOW_WITH_CAP` 只保留为后续受控 Add 的代码合同；本预检表由数据库限制为 `ALLOW/DENY`，未来
接入 Add 时必须通过显式迁移扩展，不能在当前阶段伪造该结果。

## 输入完整性与失败关闭

认证绑定包括策略/参数、授权政策、Instrument、venue、execution domain、账户抽象、margin
mode、collateral scope/pool、Adapter、Freqtrade worker、账户能力、Catalog 与 CapabilityCertificate
引用。市场合同保存 mark/index/可成交价、失效价、合约乘数、tick、最小数量/名义值、funding、
滑点、规则版本和损失模型引用。

以下九类事实必须全部存在、唯一、携带 source/version/payload hash、事件时间和接收时间：

- Market；
- Account；
- Vault（Exchange-only 也要明确绑定零贡献/排除事实）；
- Positions；
- Orders；
- Ledger；
- Catalog；
- Venue Capability；
- Protection。

任一事实 Unknown、陈旧、未来时间越界、时间顺序非法或超出一致性窗口时，安全数量为零。
Instrument 未分类、证书无效、保护不可用、无效止损方向、交易规则不满足、组合 MTM 非正、
政策缺失/损坏或系统状态禁止初仓时同样失败关闭。政策行不由迁移种入；缺少政策或系统风险状态
时不会得到可执行结果。

七级 Scope 为底层资产、风险簇、板块、execution domain、venue、collateral pool 和全组合。
每级分别比较计划损失和独立 Stress Loss，避免把 Stress Heat 与已包含同一损失的计划 Heat
重复相加。正式数值仍由 `DEC-RISK-003/007/010` 研究冻结；测试中的数值只存在于测试夹具。

## 风险状态

自动状态严格按以下顺序只向右迁移：

```text
NORMAL -> NO_PYRAMID -> NO_NEW_POSITION -> REDUCE_ONLY -> KILL_SWITCH
```

服务对当前行使用 `SELECT ... FOR UPDATE`；数据库触发器再次验证组织不变、版本加一、状态严格
收紧和证据引用非空。每次插入或更新自动写入 append-only
`system_risk_state_transitions`。同状态重试是无写入幂等结果；反向自动恢复在服务层和数据库层均
被拒绝。人工逐级恢复尚未实现，后续必须作为独立、强认证、带对账/冷却证据的路径增加，不能
放宽本触发器冒充恢复。

状态收紧的正式入口同样只接受 internal service principal，要求当前版本，并把当前状态、追加
历史、command receipt、audit 与 outbox 原子提交；重复命令不会产生第二次迁移或事件。

风险预检读取风险状态时锁定同一当前行，使并发收紧与决策串行：收紧先提交则预检看到更严格
状态；预检先提交则其快照只在收紧前的有限有效期成立。

## 持久化、监控和稳定错误

迁移 `20260718_0004` 增加：

- `risk_policies`：显式 SHADOW、版本化、不可变；无 seed；
- `risk_decision_snapshots`：输入、派生资本、调用上下文、输出及两份 canonical hash；
- `system_risk_state_transitions`：初始/自动收紧的追加式历史；
- `system_risk_states.transition_source_ref` 与数据库单调迁移触发器。

指标包括风险决策结果/主原因、求值时延、陈旧输入数和系统风险状态迁移。稳定错误/原因至少区分
政策不可用或损坏、输入合同无效、事实 Unknown/陈旧/时间错误、分类/证书/保护、系统状态、
Trade/Scope/Funding/Margin/Leverage/交易规则超限。

事务写失败会同时回滚 decision、receipt、audit 和 outbox；预检不会留下“已允许但无证据”的
旁路事实。

