# 测试验证与发布计划

> 文档状态：Draft，待质量负责人、风险负责人、安全负责人和发布批准人批准
> 版本：0.1
> 日期：2026-07-18
> 适用范围：Binance、Hyperliquid、Web/PWA、Telegram、风险、执行、资金与运营完整产品的工程验收和能力认证
> 决策真源：`docs/00-governance/待确认决策清单.md`；`RESEARCH_REQUIRED` 参数须以证据冻结，`OPEN` 外部事实缺失时对应能力关闭

## 1. 目标

测试体系需要分别证明四件事：

1. **策略证据**：成本后正期望和加仓增量有独立证据。
2. **风险正确性**：任何动作都不突破冻结授权和最新组合预算。
3. **执行安全性**：订单、保证金、保护、退出和恢复与真实场所语义一致。
4. **运营可恢复性**：依赖、进程、网络、数据或人工入口失败时能够 fail closed、对账和恢复。

“测试通过”不代表盈利保证；一个场所、账户、margin mode、执行域或策略版本的证据不能自动继承给另一个认证单位。

产品范围一次性完整交付。历史回放、影子、仿真、小额实盘和容量提升只是同一系统的证据环境与能力激活门，不是场所先后或功能分期；工程完成不得用局部证书替代，未获证能力也不得获得真实写权限。

## 2. 测试权威与需求追踪

### 2.1 追踪链

每项可发布能力必须形成：

```text
上位原则 / REQ / RISK / SEC / OPS
  → 领域不变量与状态迁移
  → API / Event / Venue 合同
  → TEST 用例
  → 自动或人工证据
  → 缺陷 / 风险例外
  → 发布证书与制品版本
```

测试不得复制另一套业务真源。测试矩阵只引用稳定 ID、冻结版本和证据位置。

### 2.2 最小追踪矩阵字段

| 字段 | 说明 |
| --- | --- |
| `requirement_id` | 被验证的 REQ / RISK / SEC / OPS / STATE / API / EVENT / EXEC ID |
| `test_id` | 唯一 TEST ID |
| `certification_unit` | 策略、来源、方向、板块、场所 / DEX、账户、margin mode、风险档位、Add 层级、版本 |
| `test_level` | 属性、状态机、契约、回放、集成、仿真、故障注入、安全、影子或实盘 |
| `preconditions` | 数据、账户、功能开关、风险状态和依赖 |
| `oracle` | 预期事实源、允许状态和数值边界 |
| `evidence_uri` | 日志、报告、快照、交易所回执或审计包 |
| `result` | Pass / Fail / Blocked / Not Run；不得用“基本通过” |
| `build_and_config` | 代码、策略、风险、数据、VenueAdapter、Freqtrade / CCXT 和配置版本 |
| `executed_at / executor` | 时间、自动任务或执行人 |
| `defect_or_exception` | 关联缺陷、到期例外和批准人 |

发布时所有 P0 / P1 需求都必须有正向、拒绝和恢复路径测试；关键安全不变量不得以风险例外放行。

## 3. 环境与事实隔离

| 环境 | 允许行为 | 禁止行为 |
| --- | --- | --- |
| 单元 / 属性测试 | 纯模型和确定性测试 | 使用生产凭据 |
| 历史回放 | 重放冻结事件与场所语义 | 把调参样本当时间外证据 |
| 实时影子盘 | 读取真实数据、生成但不发送意图 | 任何真实订单或资金动作 |
| OMS 仿真 / Sandbox | 模拟部分成交、Unknown、保护和故障 | 以模拟成本替代真实成本认证 |
| 小额实盘 | 只在批准认证单位和容量内发送真实订单 | 自动扩容、跨所继承、跳过保护或恢复门 |
| 认证容量运行 | 仅使用已认证版本、功能和容量 | 研究配置热改生产或跨证书扩大范围 |

研究、测试和生产账户、数据库、凭据、Bot、Telegram、链上钱包和审计空间必须隔离。生产数据复制到测试前完成脱敏。

## 4. 测试类型与最低覆盖

| 类型 | 主要对象 | 必须证明 |
| --- | --- | --- |
| 单元测试 | 纯计算、验证器、映射 | 边界值、舍入、精度、费用、时效和拒绝原因确定 |
| 属性测试 | 风险、数量、Heat、资金 | 对任意输入均不突破不变量，收紧不扩大授权 |
| 状态机测试 | Proposal、Authorization、Campaign、Add、Order、Protection、Transfer、Risk State | 只有合法迁移；终态、并发、重放和恢复正确 |
| 契约测试 | API、事件、Perptape、Freqtrade、Venue、Vault / CTO、Telegram | schema、版本、幂等、错误码、时序和兼容性 |
| 历史事件回放 | OMS 与场所事实 | 部分成交、Unknown、规则变化、重启不会重复增险 |
| 集成测试 | 完整控制链 | 身份、风控、账本、订单、保护、对账和审计闭环 |
| 故障注入 | 网络、进程、数据库、时钟、第三方 | fail closed、保护 / 退出可用、恢复不重放 |
| 安全测试 | 身份、PWA、Telegram、凭据、旁路 | 不可冒用、越权、重放、泄密或绕过唯一出口 |
| 产品体验与可访问性 | Web/PWA 深浅主题、七导航域、桌面与手机 | 核心旅程信息等价、无状态丢失、键盘和缩放可用、风险不依赖颜色 |
| 性能 / 容量测试 | 数据、风控、OMS、审计、告警 | 在批准容量和压力下满足候选 SLO，超限安全降级 |
| 影子与实盘验证 | 真实市场和成本 | 真实语义、滑点、资金费、保护与操作过程符合证书 |

## 5. 核心属性与不变量测试

至少为以下属性建立生成式和边界测试：

1. 未获有效 Approval / Authorization 的任何请求都不能生成增险 OrderIntent。
2. 显式拒绝优先于任意标签并集；作用域外动作永远拒绝。
3. 冻结 `Total Capital Snapshot_0`、`1R_0` 和 `FundingEnvelope_0` 不因批准后行情或资金变化被静默重写。
4. Add 前使用包含未实现盈亏的最新 Current Portfolio MTM Equity；更严格预算总是胜出。
5. 每次 Add 只补向冻结目标杠杆，风险 / 资金 / 流动性限制只能缩小数量，不能越过目标。
6. 任意正成交只消费一次 Add；终态确认零成交不消费；Unknown 不释放、不重发。
7. Open、Reserved、Unknown Heat 互斥记账；平仓未确认不释放风险。
8. `L_effective > L_max` 只产生 reduce-only 动态去杠杆，不消费或返还 Add。
9. 活动仓位不能获得 Vault 运营补充；转账在途不能作为交易所保证金或两端双计。
10. 风险状态在同一事件中只能自动收紧；恢复不能复活旧提案、旧授权或旧订单。
11. 同一账户同一时刻最多一个活动订单发送者；fencing 失败时不得发送。
12. 真实仓位出现后必须在场所认证窗口内获得足额保护，否则停止增险并减仓 / 退出。
13. 用户请求数量超限必须拒绝并展示安全上限，不能静默缩量后直接执行。
14. 交易所、账本或审计事实未知时，增险总为拒绝。

### 5.1 Web / PWA 视觉与可访问性硬门

以下门在深色、浅色主题分别执行，并纳入 `TEST-017` 与发布证据；任何一项失败都不能声明完整产品工程完成：

| 验收范围 | 必须证明 |
| --- | --- |
| 视口 | `1440×900`、`390×844` 的七个导航域和核心旅程无裁切、遮挡或关键字段缺失；`360px` 最小宽度无关键内容溢出 |
| 主题等价 | 两主题具有相同信息、动作、图表语义和安全能力；切换主题不丢草稿、筛选、对象版本、步骤或业务状态 |
| 键盘 | 可完成导航、筛选、提案、审核和危险动作确认；焦点明显、顺序合理且无键盘陷阱 |
| 200% 缩放 | 总览、提案、仓位、资金和异常内容可重排，文字不截断，风险信息与动作不重叠或消失 |
| 无颜色依赖 | 风险状态、错误、图表和回执同时使用完整文字、原因及图标/结构；移除颜色后仍可区分 |
| 对比度与点击目标 | 深浅主题分别达到 WCAG 2.2 AA；关键交互目标至少 `44×44px` |

## 6. 状态机与并发测试

### 6.1 必测状态机

- Proposal / Approval / Authorization：版本冻结、过期、撤销、拒绝、自审、MFA、重复批准。
- Campaign / Add：候选解锁、锁定、正 / 零 / 部分成交、Unknown、失效和不重新武装。
- OrderIntent / Order：创建、发送、确认、部分成交、撤销、拒绝、结果未知、补查和终态。
- Protection / Exit：保护不足、保护恢复、多个退出竞争、仓位为零、财务结算。
- CapitalTransfer：提案、批准、源端预留、链上 / 场所在途、目的端结算、失败、回滚和双计防止。
- Risk State：NORMAL 到 KILL_SWITCH 的单向收紧、冷却、对账和人工逐级恢复。

### 6.2 并发与竞争

- Web 与 Telegram 同时批准或拒绝同一提案。
- 两个 worker 同时竞争发送权。
- 加仓候选、止损和动态去杠杆同时到达。
- 撤单与成交乱序到达。
- 资金划转确认与账户权益刷新乱序。
- 标签撤权与按钮点击同时发生。

断言以最终事实、版本和原子消费为准，而不是请求先后到达应用的偶然顺序。

## 7. 契约测试

### 7.1 内部 API 与事件

- schema 必填、枚举、精度、时间、版本和向后兼容。
- command 与 event 分离；每个 command 有 idempotency key，每个 event 有顺序和来源。
- 拒绝原因机器可读且对用户可解释。
- correlation ID 能贯穿提案、风险、授权、订单、保证金、资金、审计和告警。

### 7.2 外部依赖

- Perptape：陈旧、缺失、重复、乱序和分类未知只产生不可交易或 Unknown，不解释为“无信号”。
- Freqtrade：默认订单、重试、超时、重启、数据库状态和交易所事实的差异不会扩大意图。
- Binance / Hyperliquid：订单状态、精度、最小量、reduce-only、保护、margin mode、限速和错误码逐执行域冻结。
- Vault / CTO：余额、控制权、whitelist、等待期、释放、链确认、地址资产网络和两端对账。
- Telegram / PWA：身份绑定、按钮过期、重复点击、离线、旧版本、撤权和 MFA。

任何第三方升级导致契约差异时，受影响证书失效，不能仅因构建通过就自动发布。

## 8. 回放语料库与金样本

回放库至少包含：

- 正常开仓、保护、Add-1 / 2 / 3、动态去杠杆、止损和趋势退出。
- 盈利候选曾达标但执行时已不满足条件。
- 订单发送后无响应、延迟确认、拒绝、部分成交、撤单失败和成交 / 撤单乱序。
- 进程在发送前、发送后、部分成交后和保护前后崩溃。
- 交易所断线、私有流未知、公开行情异常、限速、规则 / 精度变化和预言机停更。
- Binance cross、Hyperliquid removable isolated 与 strict isolated 的差异。
- 保护缺失、止损穿透、流动性骤降、资金费异常和极端跳空。
- 权限撤销、违规自审、MFA 失败、Telegram 重放和 PWA 离线旧快照。
- Vault 贡献归零、转账在途、重复回调、错误地址被拒绝和 CTO 重启。
- 双 worker 脑裂、数据库 / Redis 丢失、审计存储故障和系统时钟偏移。

每个生产事故和真实执行偏差都要匿名化后加入回放库，形成永久回归用例。

## 9. 故障注入与演练

故障注入必须验证系统动作，而不只是监控是否报警：

| 故障 | 预期安全结果 |
| --- | --- |
| Risk Engine 不可用 | 新增风险关闭；保护、减仓和退出走预认证路径 |
| 订单请求超时 | 意图进入 Unknown，查询原订单，不重发 |
| 私有账户流中断 | 按 `DEC-OPS-005` 冻结范围；默认全局停止增险 |
| Freqtrade worker 宕机 | 受影响执行域冻结；按 `DEC-OPS-009` fenced 接管或人工处置 |
| Web / Telegram 均不可用 | 无新人工批准；既有 Add 按 `DEC-OPS-004`；退出继续 |
| 审计主存储不可用 | 按 `DEC-OPS-007` fail closed；不得无证据增险 |
| 数据库恢复 | 先对账，旧意图不重放，保护按真实仓位恢复 |
| 双主 | 只有持有有效 fencing token 的实例可发送，失败则 KILL_SWITCH |
| 凭据泄漏 | 撤销、冻结、对账、轮换和 break-glass 流程可完成 |
| Vault / RPC 异常 | Vault 贡献归零，停止划转，不向活动仓位补充 |

演练频率和恢复目标由 `DEC-OPS-001`、`DEC-OPS-003` 与 `DEC-OPS-011` 冻结。

## 10. 能力证据与真实写权限激活门

下列顺序是安全证据递增路径，不是产品功能或交易场所的开发分期。Binance 与 Hyperliquid、桌面与手机、交易与 Vault 能力都必须在工程完成门内实现；只有真实写权限按认证单位独立激活。

```text
文档与追踪冻结
  → 单元 / 属性 / 状态机 / 契约测试
  → 历史事件回放
  → 实时影子盘
  → OMS 仿真 / Sandbox
  → 单认证单位、低风险、自动加仓关闭的小额实盘证据
  → 单次 Add 独立认证
  → 场所 / 板块 / 风险档位分别扩容
```

### 10.1 共同硬门

- 零容忍门全部通过。
- P0 缺陷、未授权增险、重复订单、无保护真实仓位和不可关联审计订单均为零。
- 需求追踪矩阵完整，执行制品、配置和证据可复现。
- 回滚、对账、break-glass、凭据撤销和故障恢复演练通过。
- 候选 SLO 和恢复目标在研究证据冻结前只用于观察；冻结后的版本、范围和有效期才进入真实能力证书。
- Web/PWA 深浅主题、七导航域、三类验收尺寸、键盘、200% 缩放、无颜色依赖和主题切换状态保持全部通过。

### 10.2 影子盘门

- 使用实时数据运行完整提案、风险、授权预演、OMS 意图预演和审计，但无订单写权限。
- 与交易所真实可成交规则、成本、流动性和风险状态比较。
- 每个差异都有原因分类；Unknown 不能被当作成功或无信号。

### 10.3 仿真门

- 覆盖部分成交、滑点、撤单、结果未知、保护、重启、双主和场所断线。
- 订单与资金模拟器必须能够产生不利事件，不能只走 happy path。
- 模拟通过只证明机械逻辑，不证明真实成本或正期望。

### 10.4 小额实盘证据门

- 小额实盘只用于验证一个明确认证单位的真实语义，不能反向缩小 Binance 与 Hyperliquid 的完整工程交付范围。
- 每个认证样本固定交易所、执行域、账户、margin mode、低风险、少量标的和 `auto_add=false`；通过后也只授予该证书范围。
- 样本、时长、容量、成本和策略门引用《策略合同与数值化验收门》的当前批准版本；其中标记为研究候选的数字不能被本文升级为承诺。
- Binance、Hyperliquid Core 和每个 HIP-3 DEX 分别积累证据，不相互继承。
- Add-1、Add-2、Add-3 各自独立认证；未通过的层级保持关闭，不影响完整逻辑、界面和测试能力的工程完成要求。

## 11. 发布流程

### 11.1 发布单元

一次发布必须冻结：

- 代码 commit 与构建制品摘要。
- 数据、策略、参数、风险、权限和资金政策版本。
- API / Event schema、VenueAdapter、Freqtrade、CCXT、worker config 和账户身份。
- 数据库迁移、功能开关、容量、目标场所和回滚版本。
- 测试矩阵、缺陷、风险例外、演练和批准记录。

### 11.2 变更分类

- **C0 安全收紧 / 紧急停机**：可立即执行，仍需记录和事后复核。
- **C1 风险或执行语义**：完整回放、影子、仿真和对应场所重新认证。
- **C2 兼容实现**：契约、回归、灰度和回滚验证。
- **C3 展示 / 通知**：不得改变授权、风险或订单语义，仍需权限与回归测试。

发布审批人与职责分离由 `DEC-GOV-001` 冻结。

### 11.3 Go / No-Go

No-Go 条件包括：

- `RESEARCH_REQUIRED` 参数没有证据包，或 `OPEN` 外部事实没有真实来源，却被实现当作生产事实。
- 追踪链缺失、证据不可复现或制品版本不一致。
- P0 / P1 安全或资金缺陷未关闭。
- 真实账户、订单、保护、风险账本或审计无法对账。
- 回滚、kill switch、凭据撤销或保护 / 退出路径未演练。
- 依赖规则变化但执行证书未重放。
- 当前系统状态不是允许该类发布的状态。

### 11.4 发布与回滚

1. 发布前冻结变更和事实快照。
2. 先部署无写权限或影子实例，验证健康与契约。
3. 逐执行域灰度；任何不变量异常立即关闭新增风险。
4. 回滚只回退软件，不重放订单或复活授权。
5. 回滚后对账、确认保护和风险状态，再决定是否恢复。

自动部署与维护窗口必须遵循领域 RACI；风险放宽、资金权限、安全边界和真实交易发布由作者以外的两名有权主体复核，紧急安全收紧可先执行后复核。

## 12. 发布证据包

每次候选发布至少保存：

- 发布说明、版本清单和制品摘要。
- 需求追踪矩阵与全部门禁结果。
- 属性、状态机、契约、回放、故障注入和安全报告。
- 影子 / 仿真 / 小额实盘证书；适用时。
- 数据库迁移与回滚演练证据。
- Venue、账户、margin mode、保护和对账证据。
- 已知问题、剩余风险、补偿控制、所有者和到期日。
- Go / No-Go 会议结论、批准人和生产观察窗口结果。

证据保留期由 `DEC-GOV-002` 冻结。
