# 源码发布、配置、升级与恢复

> 状态日期：2026-08-10
> 安全默认：本地绑定、真实下单/资金/签名/广播全部关闭、缺失事实 fail closed

## 1. 一条命令启动

### 完整 Docker Compose 控制台

```bash
./scripts/run_compose.sh
```

该入口会：

1. 在 `.local/compose/runtime.env` 生成权限 `0600` 的 Session 签名密钥、凭据加密密钥和本地管理员密码；
2. 以 Compose 启动 PostgreSQL 16，独立执行 Alembic 升级和幂等本地初始化；
3. 以非 root、只读根文件系统、移除 Linux capabilities 的容器启动 API；
4. 只将 API 映射到 `127.0.0.1:8000`；可用 `TRADING_PUBLIC_PORT=PORT` 更换本地端口；
5. 硬编码关闭 runtime sync、通知 worker、Perptape WebSocket、Freqtrade worker、真实/测试网发单和资金提现运输开关。

管理员名为 `kelly_oooo`，密码文件为 `.local/passwords/kelly_oooo`。文件只用于本机验收，不复制到日志、截图或 issue。

需要发送团队通知时使用显式 profile：

```bash
./scripts/run_compose.sh --notifications
docker compose --env-file .local/compose/runtime.env --profile console --profile notifications ps
docker compose --env-file .local/compose/runtime.env logs notification-worker
```

该 profile 以只读根文件系统、零 Linux capability、`no-new-privileges`、健康检查和 `unless-stopped` 重启策略运行独立 worker。API 中的渠道测试只入队；worker 才能解密渠道凭据并外发。邮件还必须在 `TRADING_NOTIFICATION_EMAIL_SMTP_ALLOWED_HOSTS` 配置逗号分隔的精确公共 DNS 主机（例如在命令前设置该环境变量），空值会在建立 SMTP 连接前拒绝邮件发送。

需要逐 Team/Account 持续只读事实时使用独立 runtime profile：

```bash
./scripts/run_compose.sh --runtime
TRADING_PERPTAPE_WEBSOCKET_ENABLED=true ./scripts/run_compose.sh --runtime
./scripts/run_compose.sh --runtime --notifications
docker compose --env-file .local/compose/runtime.env --profile console --profile runtime ps
docker compose --env-file .local/compose/runtime.env logs runtime-worker
```

`--runtime` 只开启数据库绑定的只读同步进程；Perptape WebSocket 还要求第二个显式环境开关。每个 Team 流使用自己的加密 Key、PROPOSER service principal、停止事件和源/凭据版本；流失败后该 Team 进入有事实记录的 HTTPS 轮询回退，其他 Team 继续运行。worker 没有订单发送、资金、签名或广播适配器。`trading-sync-worker --healthcheck` 只验证进程安全配置和数据库，不联系交易所或 Perptape，也不把“进程健康”表述为“外部连接成功”。

### 本机 Python + Compose 依赖

```bash
./scripts/run_local.sh
```

该入口默认只使用 Compose 启动 PostgreSQL，并在本机通过 `uv` 运行 API；两个 Freqtrade worker 默认关闭。需要验证执行 worker 时显式运行 `TRADING_LOCAL_FREQTRADE_WORKERS_ENABLED=true ./scripts/run_local.sh`，此时只启动 dry-run worker，任一 worker 未就绪都会阻止 API 启动。入口强制使用 `127.0.0.1:5434/trading_local`，不会因 `.env.local` 中遗留的数据库 URL 升级其他库；密钥和 worker 密码持久化在 `.local/` 并保持 `0600`。

## 2. 配置真源与诊断

- `.env.example` 列出 `Settings` 的全部可配置变量；空值代表没有外部事实，不代表零、可用或已授权。
- `.env.local` 只用于本机秘密；生产应使用托管秘密管理器，不挂载可提交 env 文件。
- `TRADING_CONFIG_DIR` 只接受存在的绝对目录，且其中必须有 `.env.local` 或 `.env.production.local`。
- API、runtime worker 和 notification worker 启动时都调用同一 `Settings.validate_runtime_security()`，不依赖前端隐藏。

秘密不回显的诊断命令：

```bash
uv run trading-doctor
uv run trading-doctor --skip-database
uv run trading-doctor --compact
```

输出只包含环境、Schema revision、五个数据库 Gate、进程运输开关和能力状态；不输出数据库 URL、Token、API Key、私钥、加密密钥或其指纹。配置、Schema 或数据库未就绪时退出码为 `2`。

## 3. 默认安全配置

| 边界 | 默认 | 启用所需的独立事实 |
| --- | --- | --- |
| Mock 身份 | 关闭；production 硬拒绝 | 只限 local/test 显式开启 |
| 凭据写入 | 无密钥时拒绝 | 32-byte URL-safe base64 加密密钥 |
| Runtime sync / WebSocket | 关闭 | 独立读开关、账户映射、外部凭据和 worker |
| 通知 delivery | 关闭 | 加密密钥、Team 路由和显式 `--notifications` 独立 worker；邮件另需 SMTP 主机白名单 |
| Freqtrade LIVE 发单 | 关闭 | 精确 Team/Account/Venue 加密 Worker 绑定 + LIVE 模式探针 + 账户资格 + 进程开关 + `LIVE_ORDER_SEND` Gate + sender lease + 短期授权 + 新鲜风险事实 |
| 直连场所发单 | 退役默认 | 仅隔离兼容测试的 `DIRECT_LEGACY`，不是默认部署路径 |
| 资金、签名、广播 | 关闭/控制面内无签名器 | 独立 Gate、限额、地址、双人复核和人控钱包 |

Compose 的 `api / migrate / setup` 不加入 execution worker profile；不会因启动控制台一并打开发单。

`trading-doctor` 使用与本表相同的可机读定义，并补充当前部署开关；不用文档的“已实现”代替当前账户和外部连接验收。

数据库绑定步骤为：保存加密凭据 → 完成无副作用连接验证 → 在“团队设置 → 交易账户”显式启用连续只读同步 → 启动 `trading-sync-worker`。绑定创建独立 INTERNAL service principal，只授予该 Team/Account/Venue 的 OPERATOR 读取写事实范围；凭据轮换、连接失败、绑定停用、principal/membership/role 漂移或版本变化均 fail closed。`TRADING_RUNTIME_SYNC_ENABLED` 仍是进程总开关；账户绑定不会开启交易、资金、签名或广播。

Freqtrade 绑定步骤为：在同一账户卡片展开“账户专属执行 Worker” → 保存独立加密控制凭据、显式端点、`DRY_RUN` 或 `LIVE` 模式及可选 HIP-3 白名单 → 执行无下单探针 → 核对投影中的精确 Team/Account/Venue、模式与 `VERIFIED`。每次保存都会生成新的认证版本并把状态重置为 `NOT_VERIFIED`；移除、失败、版本漂移或账户范围不一致时，LIVE 端点在联系 Worker 前拒绝。Compose 的两个共享 dry-run Worker 只用于本地诊断，不是数据库绑定，也不会成为 LIVE 回退。

## 5. 数据库升级

1. 确认目标账户、环境、主机、数据库名称与当前 revision，停止新的外部副作用。
2. 生成并校验 custom-format 备份，把它复制到加密、版本化、不同故障域的存储。
3. 在同版本的可抛弃 `*_test` 数据库上恢复，验证 Schema、权限、提案/审核/订单/成交/资金/审计数量和 Gate。
4. 运行：

```bash
TRADING_DATABASE_URL="$TARGET_DATABASE_URL" uv run alembic current
TRADING_DATABASE_URL="$TARGET_DATABASE_URL" uv run alembic upgrade head
TRADING_DATABASE_URL="$TARGET_DATABASE_URL" uv run alembic current
TRADING_DATABASE_URL="$TARGET_DATABASE_URL" uv run alembic check
TRADING_DATABASE_URL="$TARGET_DATABASE_URL" uv run trading-doctor --compact
```

5. 只在 `/health/ready`、诊断、五个 Gate、实际页面和核心回归都通过后恢复读流量。升级不会自动开启任何 Gate。

Compose 使用一次性 `migrate` 服务；API 只在迁移和幂等初始化成功后启动。

## 6. 备份与恢复演练

```bash
TRADING_DATABASE_URL="$SOURCE_DATABASE_URL" \
  ./scripts/backup_postgres.sh /absolute/path/trading.dump

TRADING_DATABASE_URL="$DISPOSABLE_RESTORE_DATABASE_URL" \
  ./scripts/restore_test_postgres.sh /absolute/path/trading.dump
```

- 备份必须是绝对 `.dump` 路径；脚本使用 custom format、`--no-owner --no-acl`，并用 `pg_restore --list` 立即校验。
- 本地容器可设置 `TRADING_PG_CONTAINER=trading-postgres-local`。
- 恢复脚本硬拒绝名称不以 `*_test` 结尾的数据库，恢复后运行 `alembic check` 和数据库 readiness。
- 仓库内不保存生产库自动覆盖脚本。生产恢复需要独立变更审批、新目标库、网络隔离、加密备份解密、恢复后对账与人工逐级解锁。
- 恢复成功不等于可增险；先对账，再恢复保护/减仓，最后由有权人员显式审核能力 Gate。
