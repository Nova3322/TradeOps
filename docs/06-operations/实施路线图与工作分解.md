## 1. 交付原则

1. **完整目标一次定义和交付。** 不以试制子集、场所先后或“先做一部分”缩小功能目标；所有目标能力进入同一产品、架构、测试和运营完成定义。
2. **工程完工不等于现实权限全开。** 完整能力可以实现并保持默认关闭；只有按认证单位取得证据和批准的能力才可激活。
3. **六个工作流并行。** 工作流只是责任与交付物分组，不是六个新服务、六套数据或六条独立订单链。
4. **唯一事实和唯一订单出口不变。** Trading 风控中心先校验，OMS 形成订单意图，Freqtrade/VenueAdapter 执行；Web、PWA、Telegram、策略、脚本和资金工具均不得旁路。
5. **安全默认贯穿全程。** 未知、外部事实缺失、证据不足、凭据异常或证书失效时禁止新开仓和增险；保护、减仓、退出和对账按已批准路径继续。
6. **如无必要勿增实体。** 优先复用已经定义的文档、模块、领域对象和状态；派生展示、纯计算规则、工作流步骤或未来可能性不新建服务、实体或文档。
7. **不预建假设能力。** 不设计或预建独立自动代理、权限、接口、数据实体、页面或验收指标。
8. **证据环境不是产品分期。** 历史回放、实时影子、场所仿真/测试网和小额实盘只用于发现事实和形成认证证据，不代表不同产品版本。

- Web/PWA 主控制台与 Telegram 通知/轻操作入口，深色和浅色两种主题，视觉合同以 `docs/01-product/用户旅程与交互规格.md` 为唯一真源；
- SYSTEM 与 MANUAL 提案、人工初仓审批、风险定仓、原生保护、自动 Add、动态减仓、退出和完整记账；
- 低/中/高风险档位、最新组合 MTM、组合最坏损失、板块/场所/账户限额和未知状态收紧；
- OMS、Freqtrade、VenueAdapter、Margin Controller、逐场所事实对账和唯一订单发送者约束；
- 交易所资金、可选 Vault 风险贡献、人工划转、空仓自动利润归集、可选自动运营补充和失败恢复；

不在范围内：独立自动代理或代理审核、公开基金/份额/DAO、多租户商业化假设、未经独立变更批准的交易所或经纪商实现。保留 VenueAdapter 扩展合同即可，不为假想平台预建实现。

## 3. 六个并行工作流

**完成检查**

- UI 视觉仍由用户旅程文档管理，不新增视觉规范真源。
- 3 类外部事实的缺失只关闭受影响能力，不允许实现自行猜测。

### WS-2 领域与风险

**交付物**

- 现有 Proposal、Authorization、Campaign、OrderIntent、VenueOrder/Fill、RiskDecision/RiskLedger、CapitalTransfer 和 MarginNormalizationWorkflow 的生命周期、不变量和所有权；
- 1R、Trade Funding Envelope、Current Portfolio MTM Equity、组合 Heat、板块/场所/账户预算与最坏损失算法；
- 目标杠杆差额 Add、30/50/100 盈利里程碑、回调后重新合格、动态去杠杆、保护和退出规则；
- 21 项 `RESEARCH_REQUIRED` 的预登记方法、证据标准、冻结和失效规则。

**完成检查**

- 纯规则判断保持模块或函数，不升级为服务或持久化实体。
- 并发审批、风险预留、任意正成交消费 Add、Unknown 不释放和退出后释放都有确定语义。
- 加仓后最坏损失仍受最新账户价值和组合预算约束。

### WS-3 平台、合同与身份

**交付物**

- API、事件、幂等、顺序、审计、市场数据、Instrument Catalog 和财务对账合同；
- Perptape 候选、公开/私有事实、数据健康、时钟、版本与来源可追溯；
- 用户多标签、作用域、显式拒绝、MFA、会话撤权、PWA 设备与 Telegram 绑定；
- 持久事件、快照、对账和恢复所需的数据所有权，不复制场所或链上事实。

**完成检查**

- 一个问题只有一个事实源；缓存、页面和通知不成为权威数据。
- 授权撤销、旧会话、重复请求、乱序事件和数据陈旧均有确定失败语义。
- 系统可从场所事实重建订单/仓位/保护，从 Trading 耐久数据重建授权/风险/审计。

### WS-4 执行与场所

**交付物**

- OMS → Freqtrade worker → VenueAdapter 的唯一订单链和 fencing；
- Binance cross/isolated 与 Hyperliquid Core/HIP-3、isolated removable/strict isolated 的能力映射；
- 下单、部分成交、撤单、Unknown、原生保护、reduce-only、退出、重启和接管语义；
- 浮盈 Add、浮亏减仓和逐仓保证金规范化的完整目标行为。

**完成检查**

- 任何时刻每个执行域只有一个有效订单发送者；恢复只先对账，不能重放旧意图。
- 订单发送后失联、部分成交、双主、保护失败和场所中断均可安全处置。

### WS-5 资金与 Vault

**交付物**

- 交易所资金、Vault 资产、风险贡献开关、估值折扣、最低储备和运营资本目标；

- 合约/链/资产/地址资格、签名托管、白名单、额度、失败恢复和互斥记账；
- Vault 不救活动仓位、不把在途资金当可用保证金、不双计的硬约束。

**完成检查**

- `DEC-FUND-002` 的现实 Vault 外部事实未补齐前，只允许完成通用合同和安全默认，不得激活对应链上能力。
- 资金与交易权限、凭据、故障域和审计分离。
- 所有自动划转都能在安全前置条件失败时拒绝，失败后可恢复且不重复发送。

### WS-6 质量、安全与运营

**交付物**

- 单元/属性/状态机/契约/集成/端到端/故障注入/安全/对账测试与证据包；
- SLO、可观测性、告警、值守、runbook、备份、RTO/RPO、灾备、发布和回滚；
- 唯一订单出口、最小权限、秘密治理、Telegram/PWA 安全、旁路探测和 break-glass 演练；
- 按认证单位签发、暂停、降级、撤销和恢复能力的操作闭环。

**完成检查**

- 未授权订单、重复订单、无保护超窗、风险超限和账实无法解释为零容忍失败。
- 发布、回滚、恢复或证书变化不能复活授权、重放订单或放宽风险。
- 本地敏感值、生产秘密和各环境身份严格隔离。

## 4. 并行依赖

六个工作流同时启动，但以下合同是共同依赖，不构成功能分期：

```text
权威边界 + 术语 + 已确认决策
  ├─> 产品旅程 / 视觉 / 权限
  ├─> 领域状态 / 风险不变量
  ├─> API / Event / 数据所有权
  ├─> OMS / Venue / Margin / 保护
  ├─> Vault / CTO / 对账
  └─> 测试 / 安全 / SLO / 恢复

六流证据汇合
  → 设计完整门
  → 工程完工门
  → 按认证单位的能力激活门
```

硬依赖只有：风险批准先于任何增险意图；Instrument 资格先于路由；身份授权先于审批/操作；资金可用事实先于风险计入；场所事实对账先于恢复发送；安全与运营证据先于现实权限。其他工作应并行，不以等待另一工作流为由缩小目标。

## 5. 三道交付门

### 5.1 设计完整门

必须同时满足：

- 完整目标、非目标、用户旅程、权限、领域模型、风险、资金、场所执行、UI 视觉、API/Event、测试和运行合同已覆盖且互相一致；
- 40 项 `CONFIRMED` 选择已落入规范，21 项 `RESEARCH_REQUIRED` 已定义研究方法与证据门，3 类 `OPEN` 外部事实有明确提供者、影响和安全默认；
- 文档权威矩阵能回答每类问题的唯一真源，不存在重复状态机、重复实体或平行规格；
- 每项需求都有验收证据类型、失败语义、回滚/撤销边界和受影响认证单位；
- Binance 与 Hyperliquid 的变化事实被明确标为实现及激活前必须复核。

通过本门只说明“知道要完整做什么”，不授予任何生产权限。

### 5.2 工程完工门

必须同时满足：

- 完整目标的代码、配置、数据迁移、Web/PWA、Telegram、两场所执行、风险、Add/减仓/退出、Vault/CTO、审计、监控和运维资产均达到统一完成定义；
- 所有默认关闭的能力也已实现其启用、拒绝、撤销、降级、恢复和审计路径，不能用永久空实现冒充安全开关；
- 自动化测试、威胁评审、账实对账、故障恢复、回滚和数据重建均有可重复证据；
- 可部署产物不含密钥，客户端、日志、通知、错误追踪和测试快照不泄漏敏感值；
- 阻断级缺陷为零，未知状态不能静默转为通过。

通过本门说明“完整产品已经实现并可被认证”，不等于全部能力可使用真实资金。

### 5.3 能力激活门

认证单位至少包含：`venue/DEX + account/subaccount + margin mode + instrument scope + strategy/version + risk tier + Add count + capital-transfer capability`。每个单位必须：

- 具有有效策略、风险、执行、安全、资金（如适用）和运营证据；
- 通过该单位所需的历史回放、实时影子、场所仿真/测试网和受限小额实盘证据；
- 明确额度、有效期、owner、批准人、监控、撤销条件、退出和恢复路径；
- 不借用另一场所、账户、DEX、margin mode、档位、Add 次数或资金能力的证书；
- 外部事实变化、事故、偏差超限或证据过期时自动暂停/降级，重新认证后才能恢复。

小额实盘本身需要一张范围受限、额度受限、限时的能力证书；它是形成更广范围证据的环境，不是绕过激活门的例外。

- 正常、异常、并发、重试、超时、Unknown、撤销、降级和恢复行为完整；
- 接口、事件、数据所有权、幂等、顺序、审计和兼容性已冻结；
- 风险、安全、隐私、资金、场所变化和存量仓位影响已评审；
- 测试、监控、告警、runbook、回滚、灾备和证据链接齐全；
- 需求追踪矩阵闭环，不以“代码已写”或完成百分比替代证据；
- 未新增没有独立必要性的文档、服务、领域实体、角色、状态或配置层。
